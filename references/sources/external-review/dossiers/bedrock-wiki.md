# Bedrock Wiki: ecosystem classification and contribution attribution {#bedrock-wiki-ecosystem-classification-and-contribution-attribution}


Source snapshot: [server-software.md](https://github.com/Bedrock-OSS/bedrock-wiki/blob/wiki/docs/servers/server-software.md), dated 2026-10-20; SHA-256 `f01fbe0f62a322934bbf54f3bb72e526cdffd4d0f6d150328455d021f185ea08`, 3,543 bytes.

The page distinguishes independently implemented servers from software modifying the official BDS binary. It gives historical context for community implementations and notes loss of public symbols in Bedrock 1.21.10 as a constraint on BDS-based projects. That is community documentation, not an independently reproduced binary analysis.

The active/discontinued software tables are imported from public JSON datasets: the [active-software table](https://github.com/Bedrock-OSS/bedrock-wiki/blob/wiki/docs/public/assets/tables/servers/server-software/active_software.json) and [discontinued-software table](https://github.com/Bedrock-OSS/bedrock-wiki/blob/wiki/docs/public/assets/tables/servers/server-software/discontinued_software.json). They may change after the dated snapshot. Current inclusion rules require a publicly runnable artifact or build instructions, minimum project age, observable activity or recent protocol support, evidence of interest, and a distinct README/site; automated dependency commits alone do not count as activity. Archival or prolonged inactivity can move a project to the discontinued list. These are the community page's curation criteria, not universal software-selection thresholds.

The front matter credits wu-vincent among the page's contributors. [PR 1260](https://github.com/Bedrock-OSS/bedrock-wiki/pull/1260) is the specific authored change: it updates Endstone's description from API-only positioning to BDS-based server software with full vanilla features and a Paper-like plugin API. The table's current Endstone description matches that positioning. The merged PR has no technical review, and its body discloses Claude Code generation. This supports a documented positioning change, not independently proven full-vanilla compatibility.

Portable use: select server architecture with an explicit compatibility and maintenance model; distinguish reimplementation gaps from binary-version/symbol availability risk. Verify actual releases and supported protocols before relying on a dynamic comparison page. The source is navigation/context; neither its vendor claims nor the mentions list is a performance or originality evaluation.

The current tables put legacy `Nukkit/Nukkit` in the discontinued list while listing `CloudburstMC/Nukkit` and several separately named forks as active. Display names alone are unsafe identity keys: the two Chorus rows point to different Rust and Kotlin repositories, and the two Altay rows also point to different owners. Stable repository URLs and lineage are necessary to avoid attributing the maintenance status of one project to another. The table also includes a Java Edition cross-play category beyond the introductory two-way classification. These are observations about this snapshot, not claims that every entry meets the stated current inclusion rules. Outbound project/community links were navigation data, not independently reviewed projects or joined communities.
