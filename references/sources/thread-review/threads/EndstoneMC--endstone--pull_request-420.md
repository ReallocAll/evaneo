## Reconstructing native interfaces with incomplete evidence {#reconstructing-native-interfaces-with-incomplete-evidence}

The expanded porting guide separates full-header ports from binary-only investigation. It makes an important distinction between an address lookup succeeding and actually identifying the intended function. Its documented failures include selecting the wrong BatchedNetworkPeer overload, mistaking a large unrelated function for ItemInstance::fromTag, stale argument-register shuffles, an inlined helper that appeared missing, and PistonBlockActor virtual-slot drift. String terminators, exact overload shape, distinctive constants and caller-local landmarks are useful anchors; final candidate behavior must agree with the old named implementation. Function size, address neighborhoods, match count and the old RVA are only triage evidence. Every consumed missing symbol produces a consteval compile failure, while a wrong nonzero symbol can compile and fail later.

The recipe hierarchy is direct string, adjacent caller/callee, constant cluster, packet getName/vtable, whole class-vtable alignment and global initializer. Inlining can shorten a call chain and increase the target's size. It is not evidence that a function disappeared. For HashedString globals initialized at runtime, string registration references may never lead to the desired consumer; an immediate-encoded string, RTTI or a packet-vtable anchor can be stronger. The actual config comments give replayable per-function routes, including experience-orb breakpoints for drops, radius-four leaf flood-fill bounds, paired trade NBT keys for fromTag, and the scoreboard constructor's inlined storage reader.

Layout work uses independent constructor/destructor/copy/serialization accesses, platform-specific container and pointer ownership sizes, vtable sequences and whole-object allocation size. A declared prefix is not sizeof the native object. Equal total sizes can hide member shifts. An event variant has two independent contracts: alternative order/index and largest-alternative storage size. A shutdown-only alternative can remain broken despite successful startup. Empty placeholder types may retain an unused index without proving the native value's semantics; copying, owning or destroying such a placeholder would need separate evidence. Likewise, an unknown virtual's slot can be reserved only when it is never called through the invented signature. Windows and Linux layout numbers cannot be transferred mechanically.

There are useful limits to preserve. Statements that a unique/direct pattern has no misresolve risk are too strong and conflict with the same guide's later insistence on checking successful matches. A union of two version patterns proves only those sampled binaries, not the next version. Some config recipes still say to reuse a slot or that order barely drifts, despite the new whole-vtable warning. Fingerprinting pure/true/false stubs or equal outer anchors cannot prove unchanged interior slot identities. Destructor analysis cannot reveal all trivial members; optimization can suppress stores. Native-layout and ownership claims here are source-reported binary investigations, not reproduced disassembly. Legal/DMCA commentary in source documents is not an independently verified legal conclusion.

## Signature tooling and repeatability {#signature-tooling-and-repeatability}

The C++ TOML-to-header build target is removed. Python dump_symbols now writes committed, platform-specific C++ arrays directly, sorted by scope/name and sized by the actual nonzero entries. Both final arrays contain 64 entries. Zero results are omitted, preserving compile-time failure for consumed missing names. This removes a build-time generator and makes offsets reviewable, but requires intentionally regenerating the checked-in headers with every native update. The movement-correction and server-text helper entries disappear with their consumers; BlockType::spawnResources gains Actor context and SayCommand's optional argument changes from value to const reference, so the declarations and mangled keys both change.

The PDB path moves from an external Rust pdbtool process to Windows DbgHelp through ctypes. One enumeration groups undecorated names into address sets; only ambiguous pretty names attempt exact mangled lookup, then unresolved entries use the byte scanner. This avoids a separately installed tool and handles non-public symbols, but a single pretty-name address is weaker than verifying the full overload. SymEnumSymbols' return is ignored, so a partial enumeration is not explicitly rejected. The passed PDB filename is not opened directly: its parent becomes the search directory and the PE is loaded. DbgHelp EXACT_SYMBOLS helps its own matching, but this review did not inspect native PDB/PE identity or test mismatched inputs. The fallback prefers an adjacent executable, otherwise a configured-version download. No new scanner, overload, wrong-PDB, ambiguity or emitted-header fixtures accompany the change.

Pattern selection weighs stable call-site anchors against direct-prologue churn. RIP-relative metadata is inseparable from the pattern: an E8 displacement, indirect FF15 reference and direct prologue require different interpretation. First-match patterns may be tolerated only when the first resolved target is independently known; a later linker reordering can silently invalidate them. The source's temporary zero-entry compile trick explicitly must not be committed. These are research procedures in the patch, not actions executed here.

The new IDA acquisition scripts cache server downloads, extract only the named executable and save analysis databases. They offer operational guidance for multi-gigabyte databases, serialized workers, idle session loss and reversible dirty-file recovery. Their completion claims need care: make_idb logs a saved marker and exits successfully without checking save_database's return. fetch_bds checks a cached ZIP's expected digest but does not recheck the freshly downloaded bytes; an already extracted binary bypasses that download/hash path. Those are static control-flow observations, not evidence of a corrupted download. Direct writes and absent HTTP timeout/atomic replacement are further recovery limits.

## RakNet: replace the partial mirror while preserving a native ABI {#raknet-replace-the-partial-mirror-while-preserving-a-native-abi}

The patch removes the hand-written BitStream, timing, address, socket, message-ID and peer-interface subset and links a pinned RakNet 4.081 archive through Conan. Local portability patches fix POSIX includes and a malformed time header; optional plugins are disabled; IPv6 support is enabled because it changes SystemAddress layout. The Mojang flavor uses protocol 11, twenty internal IDs and MTU 1600. An explicit minecraft_version option distinguishes r26u2 from r26u3. The new r26u3 interface removes seven slots relative to r26u2, and adds a shadow-ban pointer before RakPeer mutexes to align the offline ping mutex. These are version-specific compatibility declarations, not a universal RakNet ABI.

GetOfflinePingResponse is no longer a native interface virtual. The ping hook stores a concrete RakPeer pointer and calls the library method against native peer storage, making exact member layout and mutex implementation part of the contract. Seven otherwise undefined Mojang virtual overrides are supplied as throwing link stubs; they must never be invoked. The recipe's test package deliberately skips build and execution for the Mojang flavor because these overrides are absent there. Its real vanilla smoke test starts a peer on an ephemeral port, checks a nonzero assigned GUID, shuts down and destroys it. Thus that test does not validate the native overlay, its stubs, IPv6 interoperability or offline ping.

The old custom BitStream had heap allocation without a destructor; replacing it changes ownership behavior and removes that local implementation risk, but the entire external archive is not represented in this PR diff. The ping callback still trusts several native invariants, and startup explicitly comments out the old SetLimitIPConnectionFrequency(true) call because the interface no longer exposes it. No replacement anti-flood policy is established by this patch. Globals still assume a single gameplay peer.

## Movement events move from post-simulation to packet admission {#movement-events-move-from-post-simulation-to-packet-admission}

The native ServerPlayerMovementCorrectionSystem hook, declaration, source-list entry and both symbol entries are deleted. Previously it called the native system first, chose a passenger vehicle or player replay context, then compared post-simulation position/rotation to previous values. Jump detection required wasOnGround and now airborne. The new path runs inside PlayerAuthInput packet handling: from is current server location and to is client-reported position/rotation adjusted by actor height. Jump means Jumping input, currently grounded and positive proposed Y delta. This is a semantic change from observed movement to requested movement, not just a relocated hook.

Both versions retain the Spigot-derived squared-position threshold 1/256 and squared-angle threshold 10. On cancelled jump the new path sets InternalTeleportFlag, teleports to from and rejects the packet. On cancelled move with any angular delta it similarly teleports; position-only cancellation sends a native CorrectPlayerMovePrediction packet with current position, zero position delta/vehicle rotation, no angular velocity, the client input tick, current on-ground state and Player rewind type. A plugin-edited destination teleports there and rejects input. The correction packet's local read/write methods throw; it relies on native allocation/serialization.

The exact-head enclosing handler was read to establish ordering: block-interaction callbacks and removal of cancelled block actions happen before the movement event. Rejecting the whole movement packet therefore does not undo already delivered plugin callbacks, and it also drops unrelated input contained in that packet. There is no vehicle/replay-context selection in this replacement branch, no finite-coordinate guard in the newly added code and no angle wrapping. These are boundaries to test, not proof that native admission permits malformed inputs. No new movement/correction/jump/vehicle tests accompany this port; the later #458 payload-alignment repair is relevant to its Linux field reads.

## ABI changes beyond movement {#abi-changes-beyond-movement}

BlockActor becomes a 32-byte position/type/dynamic-properties base. VanillaBlockActor adds separate main/render/tick interfaces and carries the old visual/name/tick data; beehive, campfire, furnace and piston derive from it. This is multiple inheritance, not simple padding. Windows Piston tick calls the original using IVanillaTickBlockActorComponent's member-function type so std::invoke adjusts this; Linux retains the derived type. Exact-head hook.h confirms that the original address still comes from the current hooked function's name. Linux detour discovery now rejects nonvirtual, virtual and covariant adjustor thunks to avoid registering compiler-generated wrappers as real detours. Generic member-function conversion changes from union/reinterpret aliasing to zero-fill plus memcpy, retaining an ABI-specific assumption that the function address occupies the leading pointer-sized representation and adjustment starts zero. It is not a portable arbitrary-member-pointer implementation.

Other changes are numerous and materially affect layout: Tag's print overloads swap virtual order; ActorDamageSource's death-message virtual moves to a trailing internal method while the public helper becomes nonvirtual and const-reference-based; GameMode adds useItemAsAttack; CommandOrigin requiresValidLevel; block-source/dimension/resource-pack interfaces add slots. BlockType moves material first, changes pre-flattening name to string, packs many booleans into bits, removes newBlockEntity and shrinks state records from 32 to 24 bytes. Drop APIs gain instigating Actor pointers; existing anonymous campfire/leaf/pop-resource paths pass nullptr. GameRule replaces its raw union with a variant, adds command-name/version/redirect data, grows to 280/240 bytes, and returns false for a non-bool value rather than reading the wrong union arm.

Player authentication gains identity/display fields; ServerNetworkHandler inserts ServerPlayerLoader and changes member order; ServerPlayer gains optional party data; GameSession loses one client handler; StrictEntityContext loses its registry pointer. NetworkSettingOptions shrinks 24→20 by narrowing throttle threshold, NetworkConnection gains a shared security controller, and NetworkSystem adds recording state. AssignedThread grows a child array/count. PubSub callback storage changes to move_only_function and its invoke slot now forwards arguments. The recursive SpinLock changes unchecked load/store acquisition to compare_exchange, preventing two ordinary contenders from simultaneously claiming an empty lock, and moves the recursion count to the modeled native offset. No contention/recursion/ABI tests are added.

Packet layouts gain serialization-mode tails, reordered soft-enum fields, an inventory-transaction variant and concrete transaction alternatives. Boss event enum fields narrow to bytes and two booleans disappear. DarkenSky/CreateFog flags remain in the public API but are no longer transmitted by BossBar::send. Hurt effects become booleans with optional aim direction/extra knockback, AttributeBuff grows 88→120, and KnockbackParameters gains fields. Actor Heal/Hurt variant order swaps; player cancellable-event variants insert tell/title alternatives, while ScriptingWorldInitialize becomes an empty placeholder. These changes illustrate why a matching sizeof alone cannot establish correct runtime semantics.

## Build, Docker, crash handling and incidental fixes {#build-docker-crash-handling-and-incidental-fixes}

A tracked Jinja Conan default profile replaces separate fixed platform profiles: dependencies use Release while the consumer uses RelWithDebInfo; Windows uses clang-cl except sentry-native's cl override, Linux clang/libc++. CMake presets follow that choice. Python building moves to conan-py-build, pins Python discovery to the backend interpreter's base prefix, and packages the endstone_wheel install component. The custom export_pkg command packages an existing build into output-folder/package rather than exporting a real cached binary; it depends on Conan private APIs, accepts test-folder without running a test stage, and its default absent output-folder reaches os.path.join(None, 'package'). The backend may always supply the folder, but the command's standalone optional-argument contract is not safe. Build policy never and this customized packaging route need to be understood together. Dependencies/backend versions remain partly unpinned.

CI avoids code builds for docs-only paths, shifts documentation publication to develop, and schedules nightly Docker publication only when commits fall in a preceding 24-hour window or manually dispatched. That window can miss a failed run rather than retrying until a successful build. The source Docker image keeps a Bullseye toolchain for manylinux_2_31 and Bookworm runtime, separates cached Conan dependencies, uses a repaired wheel and runs pytest in the build. The release Docker path installs a prebuilt wheel. Entrypoint/healthcheck scripts live outside /data so bind mounts cannot hide them; Compose switches persistence from ./bedrock_server to ./data, exposes IPv4/IPv6 UDP ports and gives 15 seconds to stop. Existing deployment data is not automatically migrated.

Root startup remaps service UID/GID then drops privileges with gosu; already non-root startup runs unchanged. Ownership repair selects only entries with the wrong user, so a correct UID/wrong GID is not repaired, and errors are ignored. Healthcheck sends an IPv4 localhost RakNet ping, but accepts any received packet whose first byte is pong; it does not validate sender, echoed timestamp, magic or payload. SERVER_PORT must match actual configuration, and this is liveness evidence rather than save/readiness proof. No Docker/healthcheck regression fixtures accompany it.

Crash helpers are now recopied if bytes differ; failed update logs a warning rather than preventing server startup. Fatal-app-exit reporting is no longer suppressed; Sentry logs and metrics are explicitly disabled, while crash reporting remains configured. The level's new-dimension callback no longer captures a constructor-local add_dimension lambda by reference: a member helper removes that concrete dangling closure. Command lowercase conversion now accepts unsigned char before std::tolower, avoiding negative-byte undefined behavior; it is not Unicode case folding. Permission registration now logs and skips an unexpectedly missing command instead of dereferencing it. The changelog connects this area to non-ASCII custom-command startup crashes, but no dedicated fixture proves the end-to-end fix.

## New stub renderer: capability and untested edges {#new-stub-renderer-capability-and-untested-edges}

The thousand-line griffe-backed renderer explicitly adapts nanobind's StubGen/pattern architecture to pybind11. It parses overload signatures from docstrings, raises collected unparseable-signature errors, preserves definition order, reconstructs setters/deleters, qualifies enum defaults, distinguishes same-package imports and nested types, and supports regex overrides, recursive submodules and marker files. Native submodule discovery mutates a shared-binary submodule's __file__ during inspection. Binding BlockType/BlockData/BlockState handles before attaching methods makes cross-references render with Python names.

This is a substantial standalone generator addition, not evidence that all generated stubs are now validated. At this head the development dependency still names endstone-stubgen; no CMake integration reference to the new script was found. There are no generator fixtures in this diff. Static edges include omitting Alias members, broadening an actually zero-parameter fallback function to *args/**kwargs, inserting a bare '*' before keyword-only parameters even after a variadic positional parameter, and escaping paired single quotes rather than triple double quotes in docstrings. Literal attribute values are protected from dotted-name simplification, but entire signature text including string defaults still passes through it. These need targeted emitted-stub parse/type-check tests before generalizing the renderer's correctness.

## Reusable decisions and verification boundary {#reusable-decisions-and-verification-boundary}

Treat the port as a set of separate contracts: function identity, calling convention, subobject adjustment, field offsets, variant tags/storage, serialization and observable event timing. A successful build checks only a subset. Keep exact platform/version evidence next to every opaque layout, fail loudly for missing symbols, test wrong nonzero resolutions, and exercise shutdown/reload as well as startup. Mature upstream libraries can replace incomplete local implementations, but their ABI adaptation layer needs its own tests; a skipped native-flavor test cannot borrow the vanilla library's result. The only new executable test source in this aggregate diff is the vanilla RakNet smoke package, which excludes the flavor Endstone consumes. All native ABI verification, runtime behavior and CI results remain source claims or proposed validation unless stated as direct static observations above.
