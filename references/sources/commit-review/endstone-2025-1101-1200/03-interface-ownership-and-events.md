# Interface ownership, bindings and event contracts {#interface-ownership-bindings-and-event-contracts}

## Typed bases instead of forwarding diamonds {#typed-bases-instead-of-forwarding-diamonds}
1129makes sender conversion methods explicit pure virtuals.1131–1134replace concrete/macro forwarding with ServerCommandSender<Interface>, moving common permission behavior into the header. Placement of the console conversion is tried in the public interface and then returned to the concrete adapter.1135extends the same approach to EndstoneActorBase<Interface,Handle> and EndstoneMobBase. Player, Mob and Item no longer derive the concrete EndstoneActor class; each specializes the public interface/native-handle pair.

The migration keeps weak-handle access and validity checks rather than reverting to raw native actor ownership. Eighty player functions are exactly equivalent under the recorded handle/base substitutions and whitespace normalization; two removed delegate methods were read. This proof avoids treating reordered code as eighty new implementations. All other1135files and1136fixes were read. The staged change briefly loses ActorPermissibleBase::get's body and leaves actor components typed to the obsolete concrete hierarchy;1136repairs them to shared public Actor ownership and fixes dependent-base calls.1137uses a nullable borrowed repository pointer, which changes the wrapper type without creating lifetime ownership.

1159changes scoreboard downcasts to static_cast and1160adds null-entry/invalid-ID checks. Null handling is useful, but it does not establish the dynamic type of a nonnull Actor pointer. The new sibling template specializations make a concrete EndstoneActor downcast unsafe in the general Mob/Item case. Formatter casts have a different basis because the formatter is constructed locally as that concrete type. These contexts must not be collapsed into a blanket preference for static_cast.

## Binding and event shape {#binding-and-event-shape}
1128uses std::ref for MapRenderer and PluginLoader trampoline arguments.1103defers newly created-map events until map origin data is ready and marshals loaded-map events to the main thread; captured references still require native map/server lifetime to outlast the task.1149exports MapCursor.1150filters same-slot held-item notifications on release; main already had equivalent behavior, and1152reconciles it after the typed-player merge.

1161removes PlayerEvent inheritance from PlayerDeathEvent, leaving one ActorDeathEvent/Event lineage and an explicit player accessor. Python binding/stub hierarchy and native dispatch follow.1162uses static_cast in typed event-registration lambdas so base adjustment is supported; matching registered event names to actual types remains the contract. The player-property prose incorrectly describes breaking a block, which is retained as a documentation limit rather than treated as behavior.

## Chat precedence and movement state {#chat-precedence-and-movement-state}
PrimeStrat's issue268requests Endstone chat logic before Script API cancellation. Vincent explicitly confirms the intended ordering and notes future script-message mutability as a concern.1195implements Endstone cancellation/edit first, native script callback second, script cancellation honored before sending customized formatting. The requester confirms the contract, not a runtime retest. At this source boundary, a hypothetical native script mutation would trigger the comparison branch that resends the earlier Endstone message; ordinary recipient changes are not copied back to native targets. This is a future-facing source limitation, not proof that the then-readonly Script API already failed.

1197–1198centralize mutable-attribute instance plus modification context in a pointer-like wrapper, preserving dirty notification when writing health/experience. Many methods remain declarations, and reinterpret_cast between separate same-layout structs does not itself create an object of the forwarder type.1199responds to kleines-L's report that walk_speed changes the exposed value but not movement: it updates both the ability/client state and minecraft:movement.1200immediately restores the getter to the configured ability value rather than native effective speed. No movement test or reporter retest is captured.
