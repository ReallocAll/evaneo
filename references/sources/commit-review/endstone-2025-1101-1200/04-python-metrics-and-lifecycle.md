# Python lifetime and the in-tree metrics transition {#python-lifetime-and-the-in-tree-metrics-transition}

## Interpreter ownership evolves, then teardown is avoided {#interpreter-ownership-evolves-then-teardown-is-avoided}
1127moves interpreter initialization from generic runtime/module startup to DedicatedServer::start. Initially a scoped interpreter surrounds original native execution, with scoped GIL release that reacquires on exit.1137removes the exception-to-RuntimeError catch; the exception and stdin cleanup obligations consequently change. Server-thread-stop listener teardown and the later locator reset are distinct points. At stable1200the scoped interpreter and old stdin restoration remain.

Main1187replaces scoped_interpreter with initialize_interpreter after a reported finalization crash. The observed mitigation prevents automatic finalization at the end of start; it is not evidence that Python object destruction became safe. The interpreter effectively becomes process-lived at main1194. Source search and endpoint reading found no integration calling the asyncio runner's shutdown. This distinction matters when reconstructing the history: a shutdown crash can be avoided by declining teardown, with different costs than repairing all ownership.

## Moving metrics in-tree {#moving-metrics-in-tree}
1143introduces chart adapters;1145removes the external bstats dependency;1146adds TOML configuration, plugin Metrics, MetricsBase, gzip/aiohttp transport and relative imports;1147exports chart classes;1148switches the core consumer. This sequence temporarily contains broken import/lifecycle combinations before follow-on commits complete it.1153renames eleven files with exact blob+mode equality and changes only imports plus runner shutdown handling in the residual.

Charts deliberately omit absent/empty data, with zero filtering varying by chart type. Configuration creates a persistent server UUID and defaults enabled. A missing UUID rewrites defaults, so it can also discard an existing opt-out; malformed UUID text raises instead. The config's anonymity/no-performance-penalty comments are author claims, not independently measured findings. Source inspection does not transmit metrics or authorize telemetry.

The background coroutine waits a randomized3–6minutes, submits once, then waits another0–30minutes before30-minute intervals. Plugin Metrics schedules its initial data collection through the main-thread scheduler, but periodic collection directly calls _submit_data from the asyncio loop. Core EndstoneMetrics does not override submit_task at all and declares service_enabled=True, so its initial collection also runs there. Both paths read server/player state; readiness after startup does not establish thread affinity.

1154stores the submission Future and exposes cancellation.1155moves core ownership into a native RAII wrapper constructed after level/scoreboard/commands become available, acquiring GIL for Python construction/destruction and calling shutdown.1173declares aiohttp;1174makes optional-metrics failures visible as warnings with the exception text. Cancelling the outer Future is not proof that pending network sends have drained, and those sends are not retained for cancellation. Python loop shutdown is a separate obligation.

1153avoids joining the current thread but shutdown first waits synchronously on a coroutine scheduled to that same loop, so a same-loop call can still deadlock before the join check. A timed-out join can also precede closing a running loop. These are static control-flow observations; no Python/native runtime was started.

## Transfer {#transfer}
Useful for optional-service readiness, interpreter/GIL boundaries, asynchronous telemetry ownership, exception-safe cleanup, and separating cancellation requests from completed cleanup. In-tree migration is an observed choice; absent discussion does not justify inventing a broader dislike of dependencies or a performance win. No test was added in the non-merge target changes and none was run here.
