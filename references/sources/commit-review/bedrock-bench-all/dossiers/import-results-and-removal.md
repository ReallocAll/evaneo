## Archived comparisons and their limits {#archived-comparisons-and-their-limits}

The LeviLamina interim table combines four arms: optimized and base LeviLamina, Endstone, and vanilla BDS. It explicitly records a contaminated base run with another Minecraft process consuming roughly 3.927 cores during storm. Versions differ: LeviLamina's BDS 1.26.51.1 versus 1.26.52.3 elsewhere. Reported steady TPS/CPU per tick are approximately optimized Levi 10.27/97.8 ms, base 10.61/93.4 ms, Endstone 20/42.9 ms, and BDS 9.4/103.3 ms. These are archived measurements with environment and workload differences, not a portable ranking. The smaller reference-check artifact repeats Endstone/vanilla measurements but gives vanilla two errors where the interim table gives zero; neither should silently overwrite the other.

Linux after-100 uses the dev4 CPython 3.14 build: 20 TPS, 43.25 CPU ms/tick, view latency median 132.518 seconds, p90 205.038 seconds, maximum 301.694 seconds. Head-100 uses dev8: 20 TPS, 44.75 ms/tick, median 132.384, p90 204.757, maximum 378.134. A stable median does not imply improved tail latency or prove identical work. The all.json seven-record collection retains vanilla/old/after and chaos reports, with differing action counts and instrumentation; it is not seven new independent trials just because stored together. Chaos-verify.out.json wraps the detailed verifier result.

The Linux dev6 chaos verifier is explicitly not clean: locator-pair divergences 24,301,071/101,039,052, including 24,290,451 send mismatches and 10,620 table mismatches. Its first table example has 504 versus 506 entries, while a first send example has ours=1 versus vanilla=0. Other displayed checks can remain zero, and equal-distance publisher reorder counts are distinct from missed sends. This intermediate negative result constrains any retrospective claim that every verification stage passed. Server exit zero does not override verifier failure.

## Windows experiments, failures, and incomplete samples {#windows-experiments-failures-and-incomplete-samples}

The logs preserve DLL/PDB prefixes and runtime banners, rather than complete build provenance. Labels such as net, net2, pool, wake, and final suggest experimental arms; they cannot independently identify a causal patch. Normal-looking roughly 20 TPS results coexist with very different chunk-view tails and CPU distributions. For example net and net2 have view p90 about 207.93 and 248.33 seconds. The pool hp16 combinations report median view times near 83 seconds, but varying p90/max values and settling times. Worker names/counts must be read from the logs rather than inferred from a label such as mt16. Main-thread CPU ms/s, total worker CPU, TPS and wall latency answer different questions.

The initial after-100 record has only 99 occupied cells for 100 players, maximum two per cell, and worst offset 2409.6 blocks. Its 20 TPS cannot be treated as a successfully enforced equal-spread comparison. The gen-vanilla-attr run has only a ten-second steady window/two samples and repeated reteleports, unlike a standard ninety-second measurement. The five-bot vanilla smoke has repeated foreign loadbot warnings and roughly 4.555 other CPU cores even at idle; its NetherNet connection errors coexist with five joined bots. Context determines what an error measures.

Three archived runs terminate before a usable steady measurement: gen-verify, pool-bl0, and wake01-100. Gen-verify reports server exit 4294967295, pool-bl0 exit 1, and wake01 exit 4294967295. All show zero steady samples yet the text wrapper ends `exit=0`. Gen-verify's 37,455,000 checked generation comparisons with zero mismatches therefore do not establish end-to-end stability. Thread-sampler NoSuchProcess and console-write errors follow process death. Wake01 reaches settling at 330 seconds, then dies before steady; its postdeath spread snapshot does not rescue the run. Retain these failures rather than selecting only successful arm summaries.

Integration output also changes across attempts. Initial intest-after records 15 passes and 143 errors across ban/block/bossbar/command/inventory/item-meta families and missing rejoin results, despite server exit zero. After2 records 158 passes but no final rejoin suite and a FAIL verdict; after3 with the same DLL hash records PASS with 208. Old/net/net2/wake0/final records show 208 passes. These are recorded harness verdicts with a potentially intermittent or fixture-related failure, not independently diagnosed code regressions or newly executed tests. Expected permission/syntax probes are separate from failed test assertions.

## Windows chaos verification is narrowly clean {#windows-chaos-verification-is-narrowly-clean}

The UTF-16 chaos-verify record reports 15 minutes of stress, no server crash, and clean displayed verification numerators across all 270 counter pairs. There are 90 monitor records spanning 10–900 seconds, with four one-second scheduling slips (41,261,591,831). Monitor TPS ranges 1.03–19.77, online bots 39–100, backlog 0–214, and final command feedback errors 1023. Recorded action families include weather, far teleport, spectator/survival, kills, randomtickspeed, reconnect churn and flash leave, block/summon operations, dimensions, stack/unstack, ticking areas, waypoint toggles, and cleanup. The summary counts 196 backlog-skipped actions. Thus a common nominal stress script does not establish equal applied work.

The chaos-window counter verdict has 237 source verify lines and a poststop summary 239, with correspondingly larger final counts. These scopes must not be conflated. Final checks include 25,123,227 Dimension player checks, 78,255,392 locator pairs, and 424,660,031 publisher missed-send checks, all zero divergences in the reported summary. Meanwhile the run warns about a foreign loadbot, reports 525 chaos error lines versus 1582 broader log errors, 185 rejoin failures, 37 rejoin-gave events and two never-respawned IDs. Thirteen closed-file event callback failures appear after an empty harness_errors array. A clean specialized verifier is evidence about those comparisons, not evidence that stress delivery, logging, or environment isolation was clean. The CPU/latency cost of instrumentation and foreign load is not separable from this archive alone.

## Removal and preservation {#removal-and-preservation}

Ordinal 026, `655e3e486185341520890621f65d9b69a9b6067d`, removes exactly 529 paths: all 503 legacy files and all 26 blog files. A prior static comparison reported that every removed legacy blob/mode matched ordinal 000 (and remained unchanged at 002), every removed blog blob/mode matched the reviewed ordinal 005, and every surviving path was unchanged at 026. A separate source-level check reported the 455-file source lifecycle and sole exact source survivor, LeviOptimize optall configuration. These comparisons are reported static inspection results, not independently reproduced here. This is deletion of already reviewed evidence, not 529 new semantic changes. Blog restoration at ordinal 027 is separately exact-blob verified. Do not infer a human motive beyond the actual commit statement; later canonical docs preserve a narrower selected result subset.

The import README positions the historical harness as the basis for a reproducible, fair refactor. Ignore rules omit binaries, installed servers, work/raw directories and environments. Those exclusions explain why this repository is insufficient to reconstruct every original run. Git commit history preserves declared authorship and AI coauthor trailers; submitted code, generated measurements, coauthored prose and explicit human decisions must remain distinguishable. Contemporary comparisons here do not revive the excluded decade-old Nukkit history.
