# Configuration, fixture and attribution evolution {#configuration-fixture-and-attribution-evolution}

## Evidence and limits {#evidence-and-limits}

This dossier summarizes configuration changes visible in the public commits. It does not cover the initial imports. No upstream harness, server, helper, build, test, or plotting command was executed. The [commit history](commit-by-commit.md) links each revision.

Public Git history credits wu-vincent as author. That attribution does not establish that every line originated with one person. Commit messages 008–025 explicitly credit Claude Opus 5.5 as coauthor. Four merges include Omniac/OmniacDev contributions: 176, 185, 187, and 208. Integration does not transfer authorship of those contributions.

## From parity categories to concrete configuration provenance {#from-parity-categories-to-concrete-configuration-provenance}

At 063 the project consolidates scattered configuration descriptions into one [config.file] shape. A common parser validates structure, file format and override category, retaining precise error locations and file order; each adapter still checks its own value shape, dotted key syntax and duplicate categories. This is an intermediate abstraction, not the final design.

Commits 084–089 introduce readable templates in each server's own syntax. The intent becomes visible adjacent to each setting rather than buried in Python or nested TOML records:

- PocketMine/Altay remove a 1024 MB hard limit and size async workers to allocated server CPUs. Comments explain that the limit stopped the synthetic 100-bot join. These are deliberate benchmark accommodations, so results are not simply stock-default server behavior.
- Allay's world template uses a platform thread rather than virtual thread so the tick workload has a measurable OS thread. It explicitly enables lighting because omitting the value disables it, and chooses its flat generator. This is both an instrumentation choice and a workload comparability boundary.
- Dragonfly keeps idle-world ticking enabled for the tick probe and changes logging from per-packet debug behavior. It sets survival explicitly because newly created worlds default to creative.
- Java-family templates disable adaptive level tick rate so the tick counter reflects actual slow-level work; allow hovering bots; increase per-address rate limits because all clients share loopback; suppress unrelated transports, updates and telemetry.
- BDS-family settings are byte-identical across hosted variants, with CSG off, RakNet and fixed gameplay values. Leaving max-threads absent preserves the shipped setting. Identical templates do not erase differences in hosted BDS builds.

Commit 090 introduces Jinja StrictUndefined rendering. Undefined variables fail rather than silently producing missing settings. Existing properties retain unrelated lines/comments and newline style. YAML merging deliberately handles only block mappings of scalar leaves, not the entire YAML language; JSON and TOML are parsed and deeply merged. Lists and empty mappings replace rather than append. Scalar-parent conflicts fail. New files retain rendered text after validation, while every written file and touched key records a hash and before/after values. Tests cover these contracts, not arbitrary YAML equivalence or server consumption. Writes occur one file at a time; there is no all-file atomic transaction. Path validation at this stage is lexical, not a symlink security boundary.

At 104 adapters directly name the template files, replacing the [config] filename map. This removes a configuration indirection but transfers target-path trust to adapter source. A common ConfigFile record holds template identity, file creation, hash and key changes. Readback compares parsed values, tolerating server reformatting/reordering, and detects missing files or changed keys. It cannot prove that the server used an unchanged value internally. Records lacking keys are deliberately skipped. BDS migration at105 removes categorized override machinery and records even values equal to defaults, giving a fuller audit trail. At116 this information plus launch argv/environment changes reaches run records and schemas. Later adapter migrations are individually tracked rather than assumed complete from the base abstraction.

## Workload definition and result presentation are versioned decisions {#workload-definition-and-result-presentation-are-versioned-decisions}

The fixed workload introduced at077 has its complete parameter hash, distinct smoke fixture and hash-changing test overrides. The initial defaults include 6000-tick autosave, a15-second probe gap bound, a1-second p99 probe-lag bound and180-second stop allowance. All differ from later values; copying final parameters into descriptions of earlier runs would be incorrect. Its from_record fallback treats absent workload metadata as the built-in workload, so this function alone cannot establish the historical workload of an old record missing that block.

At082 each server gains a default benchmark version and explicit inclusion policy. An excluded server requires a reason; an included server cannot carry one. Tests tie defaults to artifact pins. This records selection, not a performance ranking of missing implementations.

At106 report columns become fixed in code, reversing the configurable list introduced at079. The same summary metadata drives Markdown/CSV/plot labels. Skipped-server explanations survive report regeneration in session.json. Config name and bot count move to the report top; the hash stays in machine-readable summary but leaves the Markdown environment table. Rescue/nonvanilla override footnotes disappear with the old categories. The tradeoff is a simpler uniform results table with detailed differences available through config provenance and server documentation; a reader of only the headline table can miss material settings.

## Test data and credibility {#test-data-and-credibility}

Commits030,031 and065 replace authentic-looking URLs, hashes and published benchmark figures in synthetic fixtures with example.invalid, zero hashes and invented measurements. This prevents a passing report test from being mistaken for reproduction of published speedups. Assertions continue to test medians, ratios, ranges, status filtering, formatting and applicability. At064 construction-phase skips/strict-xfails and missing-module fallbacks are removed so missing implementations become ordinary failures. An optional never-populated snapshot test is removed rather than counted as coverage. These are useful distinctions between plumbing validation and empirical validation.

## Explicit reversals worth retaining {#explicit-reversals-worth-retaining}

ADR0005 at017 supersedes the legacy-faithful CSG-on headline. Its stated reason is unequal chunk work: comparing Endstone with CSG on against servers without it changes how much the server generates/sends. CSG-on survives only for reproducing the older Endstone figures; the new headline changes in place because no results had yet been published. Historical prose itself gives inconsistent full-view counts (317 and about450); the durable lesson is to define observable work rather than promote either count unquestioningly.

At159 full periodic autosave is disabled where a switch exists. The commit body says fresh100-player full saves stall PocketMine/Nukkit on the main thread for over a minute. BDS has no equivalent switch and keeps incremental saving. Earlier results are removed and rebuilt under changed settings. This is a disclosed fixture change, not an implementation speedup or proof of equivalent persistence cost.

At201 and203 postmeasurement stop failure changes from a failing run into an unclean_stop flag under analysis version3, including correction of historical stored exit-code reasons. A newly accepted result can therefore reflect classification/reanalysis rather than a newly measured improvement. The [results dossier](recorded-results-evolution.md) tracks that distinction.

## Workload moves from implementation default to auditable input {#workload-moves-from-implementation-default-to-auditable-input}

At `19e98c4e62ba2d1bce5b1433438d70000c972012` (120), run, run-one and smoke require a CONFIG. Named base files deep-merge tables; scalars and lists replace. The loader detects cycles, rejects unknown and missing keys and validates counts/choices. Base name and chain are recorded, while the resolved parameters, including repeat/order/cooldown/rerun policy, determine comparability hashes. The 25/50/100 reference configurations change only bot count. Missing workload records now fail instead of silently inheriting the contemporary benchmark defaults, a meaningful reproducibility improvement with a backwards-compatibility cost. The phase representation changes within the existing run/1 schema label. Synthetic fixtures are migrated; these are not measured runs.

Child run processes receive the configuration path and read it again. A mid-session edit could therefore affect later runs; resolved hashes should expose the difference when reports refuse mixed configurations. This is static reasoning, not a reproduced failure.
