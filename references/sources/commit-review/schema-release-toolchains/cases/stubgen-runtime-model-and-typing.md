# A runtime binding model needs explicit repair contracts {#s1-a-runtime-binding-model-needs-explicit-repair-contracts}

## Problem and source boundary {#problem-and-source-boundary}

A compiled pybind11 extension does not expose the same Python source AST as a pure Python module. Stub generation therefore has two different recovery problems: discover the runtime object graph, then infer an interface that a static checker can understand. `1e900f49e08a701a9e62f95a0b7cdfdfa4c1b0c8` implements this with Griffe extensions and Jinja templates. Read the initial full diff, especially the extension hooks and function/property/module templates; [the repository dossier](../stubgen-review.md) retains each intermediate revision.

This is public source-level evidence. Griffe, Jinja, Python, pybind11 conventions and the inspected extension are dependencies or upstream interfaces, not work that can be attributed to the generator author. Importing a requested module can execute initialization. The CLI's dry-run avoids output writing, but still loads the module; it is not an execution-safety boundary.

## Actual reconstruction mechanisms {#actual-reconstruction-mechanisms}

- Submodule repair recognizes a child whose qualified name belongs under the current module. A child sharing the parent's extension-library filename has `__file__` removed to force inspection rather than treating the shared library as already visited. That is an actual runtime mutation; no restoration is visible in the reviewed code.
- Property recovery creates function objects for native setters/deleters and calls the relevant extension hooks. The model gains writable/deletable labels. The template renders getter and setter, but the initial template does not render a deleter merely because the model has one. Model coverage and emitted syntax coverage are separate obligations.
- Native-enum recovery recognizes a qualified enum repr with a signed integer. An enum member is emitted as its numeric value in its enum, while an exported enum object is emitted as a qualified reference. A regex-level representation assumption is narrower than arbitrary Python repr parsing.
- Internals filtering removes pybind11 implementation attributes/base-class noise and default constructor docstrings, rather than asking the template to render everything and remove text afterward.
- Docstrings supply signatures. The parser constructs a `def` form and uses Python AST-only compilation plus Griffe safe expression/annotation builders. This does not execute the signature string. It does not remove the separate import-time execution already needed for inspection. Numbered overloads are parsed in sequence and tied to their following documentation. Failed signatures warn and fall back to unconstrained `*args, **kwargs` with no known return type, losing precision rather than proving a valid contract.
- Member ordering follows runtime dictionaries rather than alphabetical inspection order. Export and import repair occurs in the model, then templates consume that model. The later S2 case shows why confusing imports with members breaks this boundary.

## Alternatives and reversals {#alternatives-and-reversals}

`eb78bcc264e88529063e480c4d420ea86ba4b15b` replaces `griffe.load` with `importlib.import_module` plus explicit `ObjectNode`/`Inspector`. `c3ed361ad973d2cd4ccef96e991f6e39caec5285` reverses that choice to `griffe.load`, despite a TODO noting importlib's better module import logic. Neither change supplies a reproduction demonstrating why one route won. Preserve the explored alternative and reversal; do not invent a performance or correctness cause.

`ce96a6060f8f9e586fb7f3ed6dec9872f20120a6` changes filesystem layout from package `__init__.pyi` to dotted-path `.pyi` files. Later README trees remain stale. PEP 561 compatibility is therefore a claim requiring installed-package tests, not something established by a screenshot of the intended tree.

## A refactor with behavioral additions {#a-refactor-with-behavioral-additions}

The April split has an explicit Claude Opus 4.6 co-author trailer. AST proof establishes that the original eight classes are unchanged after omitting comments, locations and leading docstrings. It also identifies four genuinely new classes:

1. Equality/inequality signatures become `(self, other: object) -> bool`, with previous overload/docs removed. This encodes a conventional equality protocol; it is not proof every exotic native equality binding returns bool.
2. Callable annotations with a default represented as `None` gain `| None`, but the matcher is specifically an expression-subscript form beginning `collections.abc.Callable`. Alternate aliases or annotation representations can evade it.
3. Overload deduplication keys on annotation strings and return type. Distinct parameter names, defaults and positional/keyword kinds are ignored. Two overloads differing only in keyword names can be distinct call contracts yet be collapsed.
4. In-place operators reuse binary-operator operand types while retaining the in-place return type. It fixes a plausible pybind11 annotation deficiency, but assumes binary and in-place accepted operands coincide. It also handles existing overload sets differently from an un-overloaded in-place function.

The correct disposition is “behavior-preserving split of eight classes plus four new fixups, AI-coauthored,” not “pure refactor” or “solely authored mechanism.”

## What a future implementation should test {#what-a-future-implementation-should-test}

These are proposed tests, not results from this review:

- A tiny compiled fixture with shared-library submodules, exported enums, property setter/deleter, overloads and overload parse failure; ensure inspection does not silently omit objects and report the deliberate runtime mutation.
- Annotation/default representation cases (`None`, false-like defaults, Callable aliases), overloads with same types but different keyword names/kinds, and in-place operations accepting a narrower operand than the binary form.
- Generated syntax at positional-only and keyword-only boundaries, including all-positional-only signatures and variadic parameters. The initial template emits a positional-only slash on a kind transition; terminal positional-only cases need an explicit oracle.
- Installed-wheel template availability and checker behavior under the actual `.pyi` layout. Documentation examples and code should share an asserted output tree.

No native module, upstream test or formatter was run. AST equality establishes the stated code-structure relationship only; it does not prove Griffe-version compatibility or generated-stub soundness.
