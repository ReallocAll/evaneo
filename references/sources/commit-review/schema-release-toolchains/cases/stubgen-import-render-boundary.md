# Keep symbol ownership separate from import bookkeeping {#s2-keep-symbol-ownership-separate-from-import-bookkeeping}

## Failure chain {#failure-chain}

The initial import extension created a Griffe `Alias` member for both internal and external references. This made an external package appear in the member/module graph and could leak a spurious child-module import into output. A bare annotation naming a local class could also be treated as an external import: because the renderer suppresses imported members, the real class definition could disappear.

`4fd75f0ecdcb144c6dcaaa662bf5ca23edc622c0` supplies a detailed explanatory message, actual code change and model-level regression tests. Full diff, message.

## Revised invariants {#revised-invariants}

- An internal cross-module reference gets an import entry and an Alias so Griffe can resolve symbols within the inspected package.
- An external reference gets import bookkeeping only. Its package is not grafted into the module's semantic members.
- A bare name already owned by the current module remains local, without either import or Alias creation.
- Export names are deduplicated initially and again at render. The second pass matters because downstream callers can graft objects or append exports after loading.
- Internal `from` imports remain absolute. Relative shortening based on the current module's path can become incorrect when a caller remaps the inspected namespace into a differently nested output package.

This is a late-normalization design justified by explicit post-load mutation, not a blanket rule that every invariant should be deferred. Load-time normalization still helps callers consuming the model; render-time validation protects the output boundary.

## Tests and their exact reach {#tests-and-their-exact-reach}

The commit builds `Module`, `Class`, `Attribute` and `Function` graphs directly, avoiding compilation/import of a real pybind11 extension. Tests cover external imports, bare local references, internal aliases, descendant/sibling import spelling, and duplicate exports after caller mutation. This isolates the bug cheaply at the representation boundary.

The export-initial-population test reconstructs the set comprehension instead of invoking the actual extension hook. It demonstrates the chosen expression, but would not catch a future disconnected hook or a different extension implementation. A fixture is an oracle for model/render behavior, not proof that runtime inspection produces that graph. Pytest is declared in the dev extra, but reviewed CI runs lint and build, not pytest. No tests were executed here.

## Formatting follow-on {#formatting-follow-on}

`b19b059c5b9dfcee1052ff1a68030c86ea51de5a` moves import grouping into a render-time helper. It groups stdlib names via `sys.stdlib_module_names`, third-party names, then names under the package's first component; it sorts/deduplicates and combines `from` names. It also emits multiline double-quoted exports and inline ellipses for undocumented functions/properties. Full follow-on diff.

The accompanying tests assert exact strings and spacing. They do not invoke Ruff, so “Ruff-friendly” is the stated target, not independently checked idempotence. The running Python version affects the stdlib-name set. Custom import aliases and names differing from mapping keys deserve explicit tests; very long combined imports need a wrapping policy if exact formatter equivalence is desired.

## Portable application {#portable-application}

Use this case when a code generator mixes imported references with owned declarations, when output namespaces are remapped, or when clients mutate intermediate models. Establish separate invariants for graph ownership, import resolution, export naming and output formatting. Test a downstream mutation after load, not only the freshly constructed happy path.

Counterexample: a generator emitting a frozen immutable intermediate representation can validate once at the freeze boundary. Repeating normalization everywhere may obscure ownership bugs. Here the repeated export pass is warranted by the documented mutable public API.
