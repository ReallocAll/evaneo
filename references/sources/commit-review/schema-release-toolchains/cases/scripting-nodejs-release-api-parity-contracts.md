# Compatibility includes reflection, exceptional values and object identity {#n4-compatibility-includes-reflection-exceptional-values-and-object-identity}

## Available evidence {#available-evidence}

Three 0.2.0 changelog commits enumerate subtle binding-parity fixes:

- `7bf0ca7083c3ddd5aee46ce1c9cdd5e66e823b30`: argument kinds, async-generator rejection, stale error context and mutability of exported game objects.
- `12c45bf7a440bcae0f07420a047287d377ee7ac8`: error-message enumerability/serialization, integer-boundary formatting and exception type for expired native objects.
- `833eff174ecc51c3646cd17dd401d085b7338bdf`: enum reverse mapping, constructor misuse, negative zero, malformed Unicode, non-enumerable Record properties, user-created error stacks, weak-reference identity and closure diagnostics.

The [per-commit review](../scripting-nodejs-release-review.md) draws on the linked public commit messages and patches. A message says a harness settled conversion behavior, but the harness and native implementation are not in this repository. The evidence supports preserving a test inventory and a reported compatibility effort, not claiming those fixes passed here or inferring a particular internal algorithm.

## Observable contracts worth retaining {#observable-contracts-worth-retaining}

1. **Argument admissibility is not just broad JavaScript type.** NaN, functions and native game objects can cross different conversion branches. Async generators and synchronous generators can share familiar iterator shape but have incompatible scheduling contracts for runJob.
2. **Failure must not contaminate the next operation.** Stale argument/error context can make a later call's message name an unrelated earlier value. A regression case should fail one operation and then exercise another in the same execution context.
3. **Reflection is public behavior.** Whether an error's message appears in `Object.keys` or `JSON.stringify`, whether numeric enums map back to names and whether exported objects are frozen can change addon behavior even when ordinary getters return the same values.
4. **Boundary values expose hidden conversions.** Values just beyond signed 32-bit limits can be reformatted through a floating path. Negative zero needs an observable distinction such as reciprocal or Object.is, rather than ordinary equality. Lone surrogates and malformed UTF-8 require exact upstream-contract comparison, not an assumed universal replacement policy.
5. **Construction and lifetime are separate.** Calling a nonconstructor API function with `new` should follow the expected TypeError contract; constructing a native class whose backing object is gone has a distinct ReferenceError contract in these notes. A weak reference returning a new wrapper rather than the original object can violate identity even when properties look equal.
6. **Record enumeration and error construction have nonstandard edges.** The source explicitly says Record conversion includes non-enumerable properties and user-constructed API errors lack a stack according to the comparison. Do not replace those reported compatibility requirements with what ordinary JS conventions seem likely to be; inspect the authoritative versioned engine behavior when implementing.

## Applying the evidence without inventing validation {#applying-the-evidence-without-inventing-validation}

For a new binding layer, build a differential test matrix around value, reflection, exception, lifetime and sequence-of-operations behavior. Preserve test input, expected result, actual result and engine versions. An exact message mismatch may be a compatibility defect where clients depend on text; it may also be harmless for a broader API. Decide that contract explicitly rather than assuming identical strings always matter.

These are proposed directions derived from reported cases. Public fix claims and edge cases are retained; the native patch, harness and runtime remain unverified. API correctness cannot be inferred from a release version, issue closure or benchmark speedup. No upstream source or binary was executed, and unavailable private implementation details are not reconstructed.
