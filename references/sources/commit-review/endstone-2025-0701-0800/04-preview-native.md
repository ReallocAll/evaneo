# Native preview migration: authentication, packs, layouts and results {#native-preview-migration-authentication-packs-layouts-and-results}

## A coordinated but staged ABI transition {#a-coordinated-but-staged-abi-transition}

774–779 adapt1.21.90 preview authentication and native layouts. The sequence replaces certificate-backed GameServerToken storage, introduces legacy/raw token types and authentication/trusted-info records, updates primary/subclient request declarations, native user identity, async network state, resource packets and transfer fields.777 also changes actor virtual ordering, biome/tag storage, gameplay event variant alternatives, movement settings and resource repository methods. These are meaningful ABI edits, not boilerplate to infer away from their size. The full diffs were read; symbol-address bulk alone received numeric structural treatment.

Several revisions are incomplete between commits.776's XUID getter still refers to removed token storage until777.777 makes offhand retrieval virtual, then784 restores a nonvirtual component lookup and removes that virtual slot. Request data access780 initially checks only raw token presence;785 restores valid-legacy-token gating. Trusted-info XUID access ignores its old trust_self_signed parameter. This records source behavior, not authentication correctness: actual certificate/JWT verification and supported guest/self-signed flows were not executed or independently audited.

779 toggles the EntityRegistry preview-only field on;795 turns it off for stable release. Numeric audits preserve all old/new values, table keys, additions and version metadata for732/740/779/795/799. No binary disassembly proves their correctness.783's std::function→brstd::function_ref correction also changes the mangled symbol name at the same address, illustrating that matching an RVA is insufficient if argument representation differs.

## Resource packs: returned result versus installed state {#resource-packs-returned-result-versus-installed-state}

The native PackSource contract changes to options and a result containing shared packs plus report.777/780 add staged declarations and empty implementations.782 moves actual Endstone discovery/loading into _loadImpl and returns the result, while iteration now lives in the base class. However, returning packs does not populate the base's packs_ cache.786 explicitly copies the shared pack vector/report into that base state, aligning discovery results with forEachPack. This is the causal explanation behind the title saying zipped packs work again; the title is not an executed reproduction.

The shared-pointer vector copy preserves the same Pack objects rather than cloning them. Discovery remains once-only; errors and filesystem behavior are not exercised.788 adds a ResourcePacksInfo packet patch entry, but its body contains only a TODO to move content-key injection. Do not advertise completed key injection from that feature title. The ServerNetworkHandler content-key offset has an explicit unresolved source TODO in776.

## Result migration must be checked at the consumer {#result-migration-must-be-checked-at-the-consumer}

777 changes score modification from bool/int conventions to ScoreboardOperationResult and temporarily comments out bodies.780 repairs the internal pipeline: unknown identities and read-only criteria are explicit results, success updates references/notifications and returns the resulting score. Yet the public EndstoneScore::setValue check remains `result != Success`; ENDSTONE_CHECK rejects false, so success produces an error result at800. This is directly verified against the macro, not inferred from naming. Internal add/subtract also lack checked overflow and unknown operations fall through to Success despite enum alternatives. Native scoreboard execution was not performed.

The same preview patch introduces typed skin accessors, documented in dossier02. Its retained Geyser device-name source comment is attribution, not proof that all nearby code was copied or reviewed by that project.

## Verification cost and boundaries {#verification-cost-and-boundaries}

Fourteen preview ancestors are imported by789 with all67 changed first-parent entries equal to the preview parent. Canonical PR199 base/head IDs match the branch. Its empty primary body supplies no missing design rationale. Codecov's all-coverable-lines banner alongside0.00% project coverage and no inline reviews cannot support test-success or human-approval claims. Static assertions and parser checks validate representation internally only; compatibility with Bedrock remains an unexecuted boundary.
