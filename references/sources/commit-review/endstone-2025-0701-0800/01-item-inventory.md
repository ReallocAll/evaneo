# Item definitions, ownership, inventory and cancellation {#item-definitions-ownership-inventory-and-cancellation}

<a id="why-this-chain-matters"></a>
## Why this chain matters {#why-this-chain-matters}

This slice follows the completed 601–700 ItemType work into public construction, stack comparison, inventory algorithms and event timing. The source of the immutable-definition analogy is Vincent's PR189 body, explicitly comparing ItemType to Bukkit Material. It exposes definition-level durability and maximum count without requiring metadata. `ItemStack.type` changes from string to object; `.type.id` is the migration path. Merge702 is a verified import of ten completed earlier commits plus the newly read701, not a second implementation.

701 adds public constructors alongside checked factories. This is a real contract difference: factories reject unknown type IDs and amounts outside1–255, while direct string construction leaves unknown IDs as air/zero and accepts arbitrary amounts for valid types. The default reference initializer dereferences the registry's air definition. Native registry definitions are borrowed; adapter ownership does not imply definition ownership. At800 the translation-key result becomes an owning string generated from a native ItemDescriptor, appropriate because the generated value need not share the lifetime of a stored description string.

## Revisions that explain the final mechanism {#revisions-that-explain-the-final-mechanism}

The first drop event705 fires after an item actor exists. Cancellation tries restoring the hand, merging a single item or adding the stack elsewhere, then removes the actor. Ignoring fallback add outcome means the code does not establish conservation.708 tries a different compromise: zero pickup delay and throw time. That makes an existing item immediately eligible for pickup, not guaranteed returned to its owner.711 abandons compensating rollback and dispatches before `Player::drop`; cancellation returns false before the original call.710 complements this by recognizing a narrow two-source/one-action transaction, verifying both sides and executing the world/drop side before applying the inventory change. The explicit PocketMine-MP source comment credits the transaction-shape inspiration; that external implementation was not independently audited here.790 later suppresses the event for dead players to address an author-reported crash.

The useful principle is to locate the decision before the unwanted side effect and trace every enclosing caller. This implementation still does not visibly compare the world-side item with the inventory delta or perform balance verification in its replacement branch. Whether earlier native validation covers that invariant is outside the inspected native executable. This is a static audit limit, not a demonstrated exploit. Descriptor accessors introduced710 also return the opposite named descriptor, though this path uses ItemStack accessors.

Comparison704 distinguishes amount-sensitive equality from similarity. Native wrappers compare definition and NBT; pure stacks use factory metadata equality.718 repairs list-tag equality from owning-pointer identity to element content, a necessary distinction when cloned tags occupy different allocations.713 adds more native equality fields and normalizes damage/auxiliary data for transaction checks. Those comparisons should not be collapsed into one universal notion of identity.

## Partial mutation and ownership {#partial-mutation-and-ownership}

721/754 declare expanded inventory operations;756 implements queries and replacements;758 implements batch add/remove;760 repairs the remaining const variadic helper. `contains(stack, n)` counts exactly matching stacks, including each stack's amount. `containsAtLeast` sums similar-item quantities. String type queries validate registry lookup and return Result errors. `setContents` checks oversized input before touching slots and clears the remainder; it is not a transaction with rollback on later native failure.

Add/remove intentionally make partial progress and return maps keyed by argument index. Returned pointers reference the supplied mutable stacks. Partial addition changes the input amount; success does not consistently reduce it to zero. The algorithms repeatedly materialize wrapper lists and scan slots; no cost measurement exists. Removing explicit player `sendInventory` calls relies on the per-slot container mutation path rather than proving synchronization absent.

A crucial endpoint qualification: `getItem` and `getContents` allocate wrappers but borrow native slots. `EndstoneItemStack` copy construction copies `handle_`; `clone()` is therefore not a deep native snapshot. The add split path clones then mutates, so aliasing must be considered when passing native-backed inputs. `setAmount(0)` resets the wrapper rather than directly clearing its borrowed native slot. The public type string setter still updates only the base reference while native `getType` reads the native handle. None of these endpoint observations are current-version claims or executed reproductions.

## Tests and limits {#tests-and-limits}

No inventory/drop regression test is added by these target commits. That is a coverage fact, not a judgment that every interface needs more scaffolding. High-value future checks would focus on cancellation ordering, quantity conservation, borrowed clone behavior, partial leftovers and invalid quantities rather than testing trivial getters repeatedly. Native binaries, gameplay, Python extensions and upstream tests were not run. The adjacent command regression tests are discussed in dossier05.
