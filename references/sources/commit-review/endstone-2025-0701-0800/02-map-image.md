# Map and image staging across C++ and Python {#map-and-image-staging-across-c-and-python}

## Ownership and incomplete integration {#ownership-and-incomplete-integration}

723–729 build a native map view and renderer foundation: a saved-map reference, renderer list, dirty-state setters and fixed128×128 pixel copying. Renderers initially use unique ownership, then752 switches to shared_ptr with a matching pybind holder. This is a cross-language lifetime adjustment. MapView still borrows its native saved map; shared ownership of a renderer does not preserve that native map. Addition calls initialize before storing the renderer. Removal erases by identity, with canvas setup/cleanup still TODO. The slice does not complete a rendering pipeline or cursor implementation, and the release notes do not establish one.

The native renderer discriminator defaults false in MapRenderer and has no override in EndstoneMapRenderer at800. Thus the first native renderer is classified as virtual by the view's `!isEndstoneMapRenderer` test. Dimension absence is checked before unwrap, but the server's level pointer is assumed present. The buffer_span iterator introduced725 reverses equality and inequality; indexed pixel access does not use those iterators, so that source defect must not be presented as proof that this renderer's indexed loop fails.

752 corrects three visible Python/API mismatches: CLOSEST spelling, remove_renderer routing to removal rather than addition, and locked routing to lock accessors rather than unlimited tracking.753 explicitly initializes caster values and adds the Result include. These repairs explain why staged commits cannot each be treated as a working release.

## Buffer shape is an invariant across every boundary {#buffer-shape-is-an-invariant-across-every-boundary}

727 makes Color setters checked value-returning transformations;728 generalizes Image from RGBA to grayscale/RGB/RGBA. Python input accepts2D grayscale and3D arrays with3 or4 channels, forces a contiguous uint8 representation, then copies into C++. Output allocates a numpy array from width×height×depth and copies the stored bytes.

The endpoint source retains incompatible assumptions: public Image construction allocates four bytes per pixel for every type; pixel indexing strides by four; fromBuffer validates a depth-sized compact buffer. An RGB/grayscale image supplied by fromBuffer therefore does not share the stride used by getColor/setColor. A public-constructed RGB/grayscale image exported to Python has more stored bytes than the depth-sized destination. The memcpy uses stored size, without checking the allocated destination length. These are static size/stride contradictions; no native memory behavior was executed. Positive dimension validation was also removed during generalization. Color::BLACK passes alpha as the first constructor argument, yielding red255/alpha0 rather than opaque black.

Skin/cape processing belongs to the same contract.753 and777 still pass skin dimensions when constructing the cape image even though cape dimensions are read.778 introduces a second decoder that reserves string capacity but writes before resizing, ignores decode success and then resizes using the decoder's output count.784 repairs a separate call-site mistake that constructed a substring at the input's end; it does not fix the destination-storage issue. These different fixes should remain separate in retrieval.

## Test tradeoff {#test-tradeoff}

769 changes the invalid-shape fixture from three channels to two because RGB is now supported. This preserves a useful rejection test under the expanded contract; it is not evidence of weakening coverage. No image stride/round-trip or map renderer test is added here. A proportionate validation plan would prioritize small grayscale/RGB/RGBA round trips and dimension mismatches over reproducing the same trivial accessors. No such test was run in this review.
