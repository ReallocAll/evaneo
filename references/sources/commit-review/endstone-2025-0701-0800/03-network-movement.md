# Connection events, first-spawn timing and movement interception {#connection-events-first-spawn-timing-and-movement-interception}

## Connection identity precedes Player lifetime {#connection-identity-precedes-player-lifetime}

719 adds server port access by modeling Connector/RemoteConnector/RakNetConnector.738 is a proven branch backport with identical patch content except blob IDs and hunk coordinates;746 reverts it on v0.8. Main retains719 through750. The later release note therefore correctly lists ports despite the chronological revert.764 centralizes the unchecked RakNet cast in a server accessor,765 removes a second globally cached peer locator, and763/766 reuse address conversion. Unsupported transport kinds return an empty address; native connector/peer lifetimes remain external.

767 sends PacketSendEvent before login with a nullable Player, copied address and subclient ID. Existing outgoing native filters still run before the public event. Payload initially borrows the stream; mutation installs owned content and the send path re-encodes the original header. Python exposes copied bytes, but the stub's non-optional Player annotation is weaker than the documented nullable contract. Endpoint sendToMultiple dispatches separately through send for each recipient; it no longer has the earlier batch cancellation semantics from older slices.

770 moves receive interception lower, to NetworkConnection::receivePacket, allowing pre-login observation. It repeatedly reads native data, skips malformed headers/cancelled packets, and returns unchanged buffers to the original handler. Modified buffers are size-checked, parsed with the original packet ID/subclient and manually dispatched. This earlier boundary means the public raw event no longer necessarily follows native scripting rejection as it did in the previous scripting-event wrapper. Cancellation drains the next packet rather than returning a fabricated success; fairness and connection-close behavior are not measured. Endpoint parser extracts subclient bits12–13; this review does not assert protocol correctness beyond the inspected encoding/decoding code.

At770, SetLocalPlayerAsInit still triggers first spawn before public cancellation.771 fixes placement by wrapping the native packet dispatcher: original handling runs first, then EndstonePlayer::handlePacket calls doFirstSpawn. Cancelled receive packets no longer reach that dispatcher. The wrapper stores the first original dispatcher by reference in a static instance; packet creation assumes a nonnull packet before accessing its handler. This is improved ordering with explicit lifecycle assumptions, not a universal exactly-once proof.

## Reconstructing native behavior versus preserving it {#reconstructing-native-behavior-versus-preserving-it}

772 initially replaces the movement correction routine with a reconstructed implementation: accept nearby client positions, set depenetration overrides, consult replay policy, adjust prediction delta or send a correction, and reset flags. It models telemetry fields but does not reproduce telemetry handling.773 immediately changes course, calling the original native routine before deriving plugin movement/jump events. That reversal is stronger evidence than reading only the feature title: preserve the engine's algorithm when the plugin merely needs an observation/intervention point.

Events initially expose cancellation and mutable destinations while their action code is commented out.787 enables cancellation and changed movement destinations via teleport, adjusts coordinates from native actor height to public feet location, and corrects the Windows hook address.791 corrects Linux separately. The source explicitly warns that these teleports trigger PlayerTeleportEvent; a plugin may cancel that secondary event, and the result is ignored. Jump destination edits are not applied by the jump-specific path. Movement thresholds are credited to Spigot in a comment and compare the immediate prior position/rotation, without a visible accumulated-distance mechanism.

Both platform address corrections and the title claiming Windows success are retained as author reports. No Windows/Bedrock process, movement script or packet traffic was run. The historical endpoint is800; later sibling revisions must supply their own evidence rather than silently resolving these limits here.
