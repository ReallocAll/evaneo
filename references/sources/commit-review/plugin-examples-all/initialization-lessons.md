# Practical initialization lessons, with evidence boundaries {#practical-initialization-lessons-with-evidence-boundaries}

These are bounded ways to use the two starter histories. “Explicit” below means the source says why; “observed” describes the change; “inference” is a practical recommendation derived by this review. No lesson is a claim about every project or an instruction to copy the final template unchecked.

## Starting a small plugin: teach the smallest useful path {#starting-a-small-plugin-teach-the-smallest-useful-path}

**Use when:** creating a starter, tutorial, example or reproducible minimal issue project.

Both March 2026 resets explicitly simplify teaching scope: [C068](cpp/ledger.md#c068) removes Fibonacci complexity; [P043](python/ledger.md#p043) removes advanced scheduler/permission demos and a separate executor. [P047](python/ledger.md#p047) selectively restores broadcast and event priority. Start with lifecycle, one or two meaningful commands, sender capabilities, permission defaults and a listener; explain what and why. Add enough diversity to teach the relevant API edge. This does not prescribe a minimal architecture for a growing production system.

**Avoid:** turning Tim Peters' Zen text from an old demo into wu-vincent's own philosophy, or taking a removed demonstration as a rejection of the feature.

## Renaming a template: follow consumer identities {#renaming-a-template-follow-consumer-identities}

**Use when:** a fork builds but has the wrong plugin name, fails discovery, omits files or cannot release.

Observed C++ changes connect logical project name, loader/binary prefix, exported metadata, display prefix, generated version macro, artifact glob and release sed target ([C014/C027/C049–C053/C081](cpp/ledger.md#c049)). Python ties distribution name, import package directory, entry-point group/key/object, __init__ export, generated version path and permission prefixes ([P003/P011–P015/P045/P052](python/ledger.md#p045)). Relative imports reduce one rename burden but do not eliminate metadata/workflow edits.

**Inference:** maintain a rename checklist, inspect package contents/exported registration, and test discovery. Both release workflows also carry a repository guard. A README rename table can be useful and incomplete at the same time.

## Choosing a dependency revision: make API identity explicit {#choosing-a-dependency-revision-make-api-identity-explicit}

**Use when:** SDK upgrades, prerelease development, or a fresh clone behaves differently from an old build.

C++ main/version-looking refs change with development context; C076–C078 expose the SDK API setting. [C++ issue8](thread-context/analysis.md) explicitly calls v0.11 a branch. Do not infer immutability from the CMake argument named GIT_TAG. Python separates api_version from distribution version and its dev SDK graph ([P016/P027/P042](python/ledger.md#p042)).

**Inference:** record the resolved SDK commit and environment when diagnosing; confirm the actual public API and runtime compatibility rather than comparing a plugin release number to an SDK number. This evidence does not establish “always track latest” or “always freeze all refs.”

## Native setup: installed, selected and ABI-compatible are distinct {#native-setup-installed-selected-and-abi-compatible-are-distinct}

**Use when:** CMake says Clang is missing despite an installed Clang, Windows iterator-debug linker errors appear, or a Linux plugin fails to load.

[Issue2](thread-context/analysis.md) explicitly distinguishes installation from CMake selection. [Issue1](thread-context/analysis.md) links Debug build mode to this host's ABI mismatch. C009/C070/C082–C087 evolve explicit compiler selection; C046–C047 distribute symbols with narrowed artifacts. C072/C079 provide symptom-oriented glibc guidance.

**Inference:** check CMake cache/configuration, selected compiler, host-compatible build mode, dependency ABI and required symbol versions before changing plugin logic. Test build and release paths separately because they drifted. A distribution label alone is not an ABI proof, and no successful reproduction was performed here.

## Removing build boilerplate: verify the delegated contract {#removing-build-boilerplate-verify-the-delegated-contract}

**Use when:** replacing local CMake flags with an upstream helper.

C043 deleted setup after FetchContent_MakeAvailable; C045 restored compatibility flags; C049 applied target-private scope; C053 adopted endstone_add_plugin; C056 restored an explicit local include path. The source shows an iterative handoff of responsibility, including incomplete steps.

**Inference:** inventory which include paths, compiler options, link options, output names and install behavior the helper supplies at the chosen SDK revision. Reduce duplication only after checking those obligations. It is not enough that the template's CMake file becomes shorter.

## Public API and capability checks: check examples against current definitions {#public-api-and-capability-checks-check-examples-against-current-definitions}

**Use when:** adapting old examples or preparing agent-facing API guidance.

P022 explicitly avoids endstone._internal. [Python issue3](thread-context/analysis.md) recommends isinstance and acknowledges the old as_player example is outdated; P043 later adopts it. C073–C074 repair SocketAddress access and a value/reference mismatch, while AGENTS.md retains a stale toString snippet.

**Inference:** check public entry points, return-value/lifetime semantics and code samples together. A committed guide is evidence of intended usage, not a verified executable oracle. Repository AGENTS.md was read as source data only.

## Configuration and permissions: carry defaults through the real graph {#configuration-and-permissions-carry-defaults-through-the-real-graph}

**Use when:** building starter commands, editable config or operator-only functionality.

P047 explicitly uses config.get defaults to survive missing keys; this says nothing about malformed data or migration. C061 removes a privileged child granted by a public parent. Final examples separate public greeting from operator broadcast and validate missing broadcast arguments.

**Inference:** test effective permission inheritance and missing keys, then separately test invalid types, bad configuration, unknown commands and reload. Do not call a local default expression a full recovery design. The Python and C++ unknown-command returns differ, so matching examples still need binding-specific contract checks.

## Packaging and release: verify the thing users receive {#packaging-and-release-verify-the-thing-users-receive}

**Use when:** distributing a renamed template or adding third-party Python dependencies.

C081 explicitly centralizes version in CMake; P042 derives version from Git. Both manual release chains validate inputs and offer dry-run, but create external tag/release state before downstream builds. Python's dependency README overstates wheel bundling, and P051's typing_extensions minimum is below the documented introduction of override ([independent checks](external-checks.md)). A lock resolving a newer package does not prove the declared minimum is sound.

**Inference:** inspect wheel contents and Requires-Dist separately; test declared dependency floors; verify config resources, entry point, version and native artifact names; decide which validation must precede publication and how partial failures recover. These are static findings and recommendations, not completed installations or publication results.

## What this source family cannot establish {#what-this-source-family-cannot-establish}

It does not establish performance, concurrency safety, robust listener/task teardown, exhaustive testing, runtime ABI portability, atomic release recovery or a general persistence philosophy. It contains no dedicated test suite in the reviewed targets. CI build/install/lint presence is useful evidence of workflow intent but cannot be reported as passing tests. Collaborator, bot and explicit Claude coauthor credits remain attached to individual changes.
