# Bedrock protocol: compiler, wire evidence, backports and integration {#bedrock-protocol-compiler-wire-evidence-backports-and-integration}

## Scope and reading contract {#scope-and-reading-contract}

This report covers commits 118–170 and 351–433. The other commits in the 433-commit history have separate reviews. The aggregate index links those reviews without copying their dossiers. Parent edges, especially for merge 168 and release/fix ordering near 430–431, establish causal order; author timestamps do not.

The review covers the meaningful source changes in these ranges, including schema, compiler, runtime and tests. Large relocations, selector changes and constructor migrations are considered as coherent changes rather than independent style preferences. Generated or repeated regions are interpreted in the context of their surrounding source changes.

All conclusions here are static source review. Author-reported builds, timings, live connections, binary decompilation, external dump comparisons and generated-output counts were not reproduced. Related restricted headers are described only through public commit claims; no private header contents are republished. Historical guidance is specific to its context and may be contradicted by later commits. Declared Claude collaborators remain credited despite later repository guidance discouraging such trailers.

The linked dossiers retain commit-level detail, source limitations and relevant context.

## 1. A version number is not enough to identify a wire shape {#1-a-version-number-is-not-enough-to-identify-a-wire-shape}

The GameRule sequence is a useful architectural case because the first plausible abstraction fails on a second call site. Commit 121 splits a shared type at 2168: the integer changes from unsigned varint to fixed-width. Bool-only fixtures had concealed the difference. Commit 122 adds the integer 131070, exposing three versus four bytes, and also demonstrates that two overall packets can have equal length while unrelated insertions/removals compensate. Its golden update was manually inserted from reference-codec reasoning, not an untouched independent generation. Commit 123 immediately supplies the counterexample: packet 72 already uses fixed width while StartGame still writes the manual form. [121](dossiers/0121-45b90b8d2909.md) [122](dossiers/0122-afb3c72ef502.md) [123](dossiers/0123-c21461301ac5.md)

An era-pin API appears in 118 and is fully reverted in 120 without a stated reason. Do not invent a rejection rationale. The later solution is an independent `cereal` flavor axis, not a more elaborate protocol gate. Commit 127 keys declarations by name and flavor, propagates flavor through containers, rejects unsupported nesting/flavor combinations and orders cross-flavor dependencies. Commit 128 removes the temporary LegacyGameRule name; 129 applies the same design to packet 144's item-use transaction and fixes namespace lookup in the opposite dependency direction. Thus semantic type name, protocol snapshot and writer flavor are distinct coordinates. [118](dossiers/0118-a03af11ce887.md) [120](dossiers/0120-b51508d30762.md) [127](dossiers/0127-8216e3cc44fd.md) [128](dossiers/0128-66441d3576dc.md) [129](dossiers/0129-6a42aa2274c1.md)

The story does not stop at the first successful model. Backport 401 establishes that packet 72 itself used unsigned varints below 844; the earlier statement “fixed at every version” was only supported by tests spanning 975–2168. Commit 402 later removes a stale inline-coordinate workaround in SubChunkPacket by using the already-supported flavor axis: packet 174 keeps a manual varint triple even after packet 175's cereal SubChunkPos becomes fixed-width. A modern counterexample can be correct without justifying an unbounded historical claim. [401](dossiers/0401-7588f48890e5.md) [402](dossiers/0402-0e71af1c5f64.md)

## 2. Declared storage, semantic members and serialized events must be separated {#2-declared-storage-semantic-members-and-serialized-events-must-be-separated}

The PlayerAuthInput correction is the strongest local wrong-turn chain. Commit 124 correctly introduces symbolic enum-sentinel bitset sizes, but simultaneously concludes that cereal input data is a bitset because the in-memory header stores one. It manually patches a third-party golden to match. Commit 139 still defends that conclusion. Commit 142 reverses the model after binding evidence: the cereal path writes an always-true marker and a list, while the older path uses a bitset. It knowingly lands with failing fixtures; 143 adds per-declaration enum underlyings and derived-wire rebinding, and 151 repairs the goldens. Both the useful compiler feature and the wrong application must survive synthesis. [124](dossiers/0124-4bfdd4f4a417.md) [139](dossiers/0139-b35d7c429f87.md) [142](dossiers/0142-c8a51ea0efb7.md) [143](dossiers/0143-7a7f33af0709.md) [151](dossiers/0151-7c7023171096.md)

The header/binary relationship is also not one-to-one. BossEvent has two byte members packed into one unsigned-short write: replacing the public model with one uint16 preserves bytes but loses an independently meaningful field. Cylinder has the reverse pattern: one header Vec2 member was reportedly bound twice. A golden made by the codec whose model is disputed cannot independently settle either case. [135](dossiers/0135-af7ed61b36fc.md) [136](dossiers/0136-e22d45e1a2fa.md) [139](dossiers/0139-b35d7c429f87.md)

Commit 411 explicitly corrects an earlier bitset explanation. Commit 409 said an oversized ActorFlags count added a byte to every packet. The runtime serializer instead scans for the highest set bit and writes seven-bit continuation groups; an empty bitset is one zero byte. Narrowing declared width changes allowed input/output values and maximum continuation acceptance, not every body's length. The HEAD runtime source confirms this mechanism. The later 748 backport correctly repeats this distinction for input flags 58 versus 65. [409](dossiers/0409-04e877a5f306.md) [411](dossiers/0411-317ab1a98108.md) [416](dossiers/0416-0d346609a893.md)

## 3. Enum values, enum names, selectors and constant tags are four different things {#3-enum-values-enum-names-selectors-and-constant-tags-are-four-different-things}

Integer-coded enum changes can be silent semantic corruption with unchanged framing: an old sentinel value may become a named action, or a category bitmask changes while the packet still decodes. Commits 133 and 137 motivate symbolic semantic IDs instead of raw shift tables. Tests that exercise only zero do not distinguish unsigned from zigzag varints; 126 and 139 expose that limitation for transaction actions. [126](dossiers/0126-bdb8dcf348eb.md) [133](dossiers/0133-2cd05161b68e.md) [137](dossiers/0137-de3580cb39aa.md) [139](dossiers/0139-b35d7c429f87.md)

Name-coded enums introduce another axis. Commit 140 removes explicit Easing wire names and patches golden casing based on the generator's then-current spelling. The separate packet slice's 269 subsequently establishes lowercase enum names; 375 derives CamelCase public C++ identifiers and must restore explicit underscore-preserving wire names where joining would change bytes. Enum public identifiers and wire spellings cannot be treated as interchangeable cleanup targets. Commit 148's runtime hash-map lookup is a real optimization, whereas the separately reviewed 110 still routed through a linear `enum_index` despite a “no scan” comment. Constant-evaluation paths remain linear, and allocation inside noexcept runtime helpers is a source-level caveat. [140](dossiers/0140-185c58a8b9af.md) [148](dossiers/0148-ab8cbf3a8a63.md) [375](dossiers/0375-7d3f1e1f7396.md)

The TextPacket sequence records two distinct mistakes. Commit 389 omits twelve constants because it reads binding metadata as non-wire; 392 restores them. Commit 394 then changes lowercase strings to mixed-case labels after following the wrong bind path; 398 restores lowercase after distinguishing a descriptor's label from the enum-valued getter actually serialized. A case-insensitive reference reader alone does not prove the sender's casing. Final HEAD source contains lowercase constants only over [898, 924). No matching BDS traffic was reproduced by this review. [389](dossiers/0389-b30f2771bd7c.md) [391](dossiers/0391-9cae4a4e2694.md) [392](dossiers/0392-44387534a671.md) [393](dossiers/0393-7937532f53e2.md) [394](dossiers/0394-129a99ba4433.md) [398](dossiers/0398-a036d30ea204.md)

Producer correction 4069abe establishes a tagged variant's wire selector as the uvarint32 alternative index, not the enum tag. The consumer already used that selector convention, so the producer repair does not itself imply consumer byte changes. Inner tag members are separate serialized events. Commit 397 converts bindConst-valued fields to Literals so the model cannot encode contradictory payload/tag combinations. Fields described only by `constraints.enum_values` remain ordinary fields. A static count finds 43 converted fields, although the message says 42; all five modules and the full diff are preserved. [396](dossiers/0396-85249be34397.md) [397](dossiers/0397-ac42404d22fd.md)

A Literal initially froze its enum number at parse time. Commit 425 retains enum/member provenance and rebinds it at each snapshot, the same principle used earlier for array/bitset lengths. Without that change, inserting a new craft action in 426 would emit the new tag inside an old snapshot. The test pins both indices: old deprecated craft selector/tag 16/18, new 17/19. Commit 422 similarly adds a constant byte inside each sound alternative, behind the unchanged selector. A schema presentation change and a new serialized constant must be audited separately. [422](dossiers/0422-68281cef3220.md) [425](dossiers/0425-1871489109ac.md) [426](dossiers/0426-d1c1bda5fdb1.md)

## 4. Version propagation affects compiler identity and public APIs {#4-version-propagation-affects-compiler-identity-and-public-apis}

Version-dependent values need provenance until snapshot resolution. The progression is not a single finished feature: 124 supports nested enum widths, 357 adds module-scope widths, and 363 demonstrates that a versioned alias still freezes its width and must be replaced by an inline use. Commit 379 preserves repeated gated enum assignments, but not repeated annotated struct fields. Guidance in 387 explicitly warns that repeated struct annotations overwrite; a class redeclaration is required for a live field whose type changes. `field(type=X, until=N)` removes the field at N, it does not switch its width. [124](dossiers/0124-4bfdd4f4a417.md) [357](dossiers/0357-e2dc170fb520.md) [363](dossiers/0363-4031d6346ccd.md) [379](dossiers/0379-f45060011392.md) [387](dossiers/0387-c95cced508e2.md)

Nominal C++ identity can change when shape does not. Commit 161 handles nested identity under a versioned owner; 384 fixes the deeper-grandchild case by walking the ancestor path and avoids duplicating untouched siblings. These are serializer-specialization and namespace problems, not merely extra generated text. [161](dossiers/0161-5a997a99c50a.md) [384](dossiers/0384-753f0d08f1ba.md)

Module consolidation 365 is a particularly good preservation counterexample. Offline AST comparison confirms 611 class chains retain their bodies, gates and per-name order across 98 files. Comment-token multisets also match. Yet qualified dependencies, generated include closures and namespace aliases are observable interfaces. Commit 366 fixes four missed direct includes; 367 replaces incidental snapshot namespaces with selectors after the author's declaration-multiset check stripped away 46 lost aliases. “Same declarations” was a narrower property than “same consumer source compatibility.” [365](dossiers/0365-0616c0f7fe4b.md) [366](dossiers/0366-99254cf65553.md) [367](dossiers/0367-414abbc66610.md)

Lowering packet availability gates likewise deletes generated `X_<V>` forms when X becomes unversioned. The 171-gate sweep in 378 therefore needs the extensive test repair in 380. Later backports continually change what `base::X` denotes, making explicit era selectors safer for historical fixtures. A backport can break source compatibility without changing the intended bytes for an already-supported era. [378](dossiers/0378-f0ff697d1268.md) [380](dossiers/0380-e694c7a99de7.md) [383](dossiers/0383-adaf490f59ba.md) [418](dossiers/0418-1dc4408fd949.md)

Strong aliases show another deliberate split. Commit 351 makes inbound primitive construction explicit while retaining outbound numeric conversion. The 393-site test migration in 352 is one mechanical adaptation. Commit 432 adds BlockRuntimeId semantic typing without unifying its per-call-site fixed, signed-varint and unsigned-varint encodings, and places it in common to avoid an import cycle. Type-based traversal improves, but API compatibility still changes. [351](dossiers/0351-9c7ca2b14241.md) [352](dossiers/0352-1fbc57c745d7.md) [432](dossiers/0432-0b8a5bb995c0.md)

## 5. A dump is evidence produced by a versioned program {#5-a-dump-is-evidence-produced-by-a-versioned-program}

The backport process evolves from comparing packet files to comparing packet identities, transitive types, encodings and enum sets separately. Commit 369 records misses in unmodelled packets; 377 adds nearest-era comparisons, retro-fix classification and positive checks for manual/cereal writers. Commit 382 further distinguishes byte authority from member decomposition and admits that new dump files can reflect producer coverage rather than a cereal conversion. Its later sentence treating identical packet JSON as conclusive remains too broad relative to its own closure warning. [369](dossiers/0369-db670eb933c3.md) [377](dossiers/0377-143d1cf03006.md) [382](dossiers/0382-f9dbc39c0557.md)

At 898 the old dumper reported declared widths, omitted compression/endianness and rendered every enum field as a string. The author classifies 195 of 197 type differences as rendering noise. This review preserves that as a reported comparative result, not an independently measured dump delta. Producer fixes restore traits offset, enum names, constant values and selector metadata; a consumer must pin exact producer/version provenance rather than count changed JSON fields. [389](dossiers/0389-b30f2771bd7c.md) [390](dossiers/0390-2aae6c15b965.md) [397](dossiers/0397-ac42404d22fd.md) [398](dossiers/0398-a036d30ea204.md)

The producer/consumer companion review also establishes fixed byte arrays becoming length-prefixed blobs despite unchanged reflection. Consumer 160/162 models the nested heightmap's 256-to-272-byte change as 16 row prefixes, not a changed number of pixels. The producer's traversal/optional/map limitations remain relevant when treating absence or missing metadata as certainty. See the [producer synthesis](../protocol-dumper-all/ENGINEERING_SYNTHESIS.md); this is separately reviewed source evidence, not a claim that the consumer's external dump oracles were rerun here. [160](dossiers/0160-3d7f7226782f.md) [162](dossiers/0162-663b5689e48e.md)

## 6. Backport confidence must narrow as source coverage narrows {#6-backport-confidence-must-narrow-as-source-coverage-narrows}

Several explicit reversals prevent a simplistic hierarchy of “trusted” sources:

- 389 calls id330 a classless old slot; 395 restores DataStoreSync with a different two-case variant. An ID can change owner rather than first appear. [389](dossiers/0389-b30f2771bd7c.md) [395](dossiers/0395-3a894e71f854.md)
- 395 calls 819 an empty renumber; 403 finds a sound-event numeric change with a live int-coded effect. A serializer class with little code can still modify a type map. [395](dossiers/0395-3a894e71f854.md) [403](dossiers/0403-2a2d083b6f8b.md)
- 400 gates biome replacements at859; 410 moves the boundary back to800 after examining component history. [400](dossiers/0400-832183416f0b.md) [410](dossiers/0410-278e6cdc46bc.md)
- 134 treats a codec's VR memory category as wrong; 381 establishes it was real at944 and removed at975. A reference's correctness is dated. [134](dossiers/0134-f44b756c34b0.md) [381](dossiers/0381-d8775231d646.md)
- 214's earlier EditorNetwork dispute is narrowed by386: the old NBT reference is valid924; the strings after944 still have no independent golden. [386](dossiers/0386-35c7e06665ea.md)
- 416 is the oldest target with matching header coverage. 417 openly marks removals/encoding changes at729 as codec-only and leaves CurrentCmdVersion's old presence undecidable without a binary or capture. [416](dossiers/0416-0d346609a893.md) [417](dossiers/0417-582d55dbdbd0.md)

Even matching reference codecs are not automatically independent: they can share a stale field, a common incorrect changelog or copied implementation. Headers establish member existence and types, but hand-written serializers can change string-to-UUID, signedness or order without a header delta. Conversely, a renamed integer-coded enum may not change any bytes. Late reference fixes in a commit interval are not necessarily changes at its upper protocol boundary.

There is a substantial support-limit warning. Commit 395 explicitly leaves ten pre898 cerealization reconstructions open. Later work fixes Animate, but HEAD Text and CommandRequest/CommandOutput still expose modern ungated forms; their “modelled protocol729” presence is not evidence that every packet is wire-correct there. HEAD keeps no independently reproduced all-packet conformance proof. The exact captured definitions and declaration ranges are in the context ledger. This caveat is about observed coverage, not a claim to have demonstrated a live failure.

## 7. Tests should distinguish the mechanism and the oracle {#7-tests-should-distinguish-the-mechanism-and-the-oracle}

This history uses several valuable test forms: nonzero enum values for signedness, negative IDs, exact prefix bytes, absent/present variants, high-bit identifiers, snapshots on both sides of a gate, wrong-era reader rejection, and equal-length-but-different-order bodies. PlayFabID's move from skin to PlayerList entry in404 is a clear example: total length is unchanged, so the test checks ordering and rejection instead. [122](dossiers/0122-afb3c72ef502.md) [147](dossiers/0147-fd32682044a4.md) [404](dossiers/0404-44ca5929a3a4.md)

Those strengths do not eliminate provenance limits. Patched or manually adjusted reference bytes are consistently distinguished from independent generated fixtures in the dossiers. Above2168, many tests explicitly have no reference golden and assert structural deltas or self-roundtrips. That establishes internal implementation consistency, not live server conformance. For pre898 historical gaps, newer goldens cannot arbitrate the missing manual form.

The all-packet registry walk is another caution. Commit 167 fixes Clang expression-depth limits with an array expansion and loop; the separate packet slice's172 later deletes the invoking test, not only a count assertion. HEAD still contains the helpers but never calls `modelled` or `ids_agree`. Documentation that tells a maintainer to update registry counts therefore does not prove that regression check remains active. ## 9. Final-state alias correction: decode success was not write correctness {#9-final-state-alias-correction-decode-success-was-not-write-correctness}

Commit360 removes a hardcoded Latest command-version alias while adding named versions. Commit375 introduces symbolic sibling arithmetic but leaves that decode hole open. Commit428 finally adds `Latest = Count - 1` and unknown placeholders, with decode assertions. Because two enum names share a value, first-match reflection still writes the ordinary member name. Commit431 moves derived aliases first in reflection lookup tables and adds a packet byte-suffix assertion; this fixes a reported translated CommandRequest disconnect. Declaration order stays intact while reflection lookup priority changes. This is a wire-level behavior decision that a successful enum_cast test alone could not prove. ## Applicability and restraint {#applicability-and-restraint}

The supported engineering patterns are conditional: preserve semantic and wire axes, pin evidence to a producer and era, use fixtures that separate candidate encodings, and check public aliases/includes in addition to declaration bodies. The dossiers also retain reversals, acknowledged gaps, untested paths and author/report discrepancies. They do not imply every implementation is correct, that the target always follows these patterns, or that repeated generated/migrated lines are independent evidence of preference.

No frozen evaluation was altered and this expanded corpus has not inherited an old evaluation score. [CASES.md](CASES.md) supplies proposed retrieval prompts and expected source boundaries for the next integration stage; it is not a claim that a retrieval benchmark has already passed.
