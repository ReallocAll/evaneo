## Retrieval guide and causal engineering dossiers {#retrieval-guide-and-causal-engineering-dossiers}

### Choosing a Python/native dependency boundary {#choosing-a-python-native-dependency-boundary}

Start with 83554e7 (dossier 01), 862c91a (02), 57e3b8c (05), 0e1c526 (11), acabed55 (15), 9f7bb7c (63). The backend wraps wheel/editable hooks, leaving sdist/metadata/requirements delegated to scikit-build-core. Conan prepares native dependencies and a CMake toolchain before calling upstream packaging. Hatchling packages this backend itself; this distinction prevents confusing the tool's build system with its consumers' build system.

The explicit original constraint is preserving a project's CMakeUserPresets.json: copy only its recipe into a temporary directory. Toolchain output gets a separate temporary lifetime enclosing the upstream build. This avoids a project-local generated preset write but changes recipe-relative file availability and offers no demonstrated durable editable-rebuild toolchain. Those are static lifecycle tradeoffs, not stated author intentions. A persistent output-folder can preserve generated files, but there is no test proving every editable rebuild scenario.

Config starts as a dataclass converted through upstream SourceChain/TOMLSource; overrides reuse upstream platform/state handling. CLI config-settings remain forwarded downstream, but final Conan conversion does not include a config-settings source. Final `_build_wheel_impl` reads upstream settings from file and replaces config_settings['cmake.args'] with file-derived arguments plus toolchain/build-type/policy. Documentation's broad -C/full compatibility language must therefore not be converted into a proven behavior-preservation rule. See final context lines 223–289 in sources.

### CLI-to-API migration, host/build contexts, and reversals {#cli-to-api-migration-host-build-contexts-and-reversals}

Read collaborator [PR #5 integrated implementation](dossiers/context-f14d05ee5a77e0deb7f23e7376330a3bbcac6d65.md), target 3909029 (24), 99994f7 (25), collaborator [PR #6](dossiers/context-621737ea444a9b6acfd04ebfe892828c2e8154ab.md), c387a749 (32), 2c48ab3 (37), 19488f5 (38), 8b8bbfe (40).

mijoku replaces CLI arguments/stdout JSON with structured Conan API calls. This removes serialization coupling but assumes responsibility for the CLI's full orchestration: profile lookup, graph loading, analysis, installation, consumer generation, persistence. Two concrete losses expose the cost: detect() computes a profile without saving it, and both host/build profiles receive target overrides. Vincent's release adapts signatures and shares one profile object; 99994 persists the default profile. mijoku reports lost matches for prebuilt build tools and restores unmodified build settings in #6; Vincent acknowledges missing this in review.

The history does not end in a simple preference for distinct profiles. In September 2025 c387a749 deliberately reintroduces host overrides into build profile under a terse fix title with no stated scenario. Four days later explicit profile/options/settings/config host/build/all fields permit independent control. profile-all overrides the context-specific selector; shared lists append after context-specific lists; both contexts receive wheel build_type. An immediate correction changes erroneously appended settings-all into options-all. Preserve the reversal and distinct namespaces. Recommended transfer (our inference): test dependency graph/package identity separately for host and build, including common overrides, instead of testing only successful API invocation.

### Compatibility means import, parser representation, and interpreter support {#compatibility-means-import-parser-representation-and-interpreter-support}

Read c2627dc (10), b695536 (13), acabed55 (15), 3b768c5 (17), 93c36d1 (20), 7cfe619 (27), 29f7629 (29), 4aaf987 (51), [deivse's PR #10](dossiers/context-b5c178e28b3faa58986b387ed847595768c2d8e7.md), 4c43d3e (60), a1e7996 (62).

TOML parsing needs tomli before Python 3.11, separately from annotation evaluation compatibility. Future annotations fixed ordinary backend signature imports, but became a regression when added to schema dataclasses because upstream conversion sees strings. Removing postponement resolves that representation problem yet exposes interpreter minimum and PEP 604 runtime-union compatibility. The final local fix deliberately uses typing.Union[List[str], str] so older supported scikit-build-core converters work. martinezlc99 identifies UnionType and reports upstream #1214; mreininghaus confirms only explicit build settings trigger failure. Default-only smoke tests can miss this conversion path. The upstream PR itself was not independently reviewed here and is not claimed as verified implementation.

Upstream internals are another boundary: process_overides becomes process_overrides at scikit-build-core 0.11.4, addressed with a narrow import fallback (mreininghaus #8 reproducer). Conan 2.17 removes private save/runner helpers, replaced with stdlib file/subprocess work. Dependency floors evolve from scikit-build-core 0.9/Conan 2 to 0.10/2.11 and finally 0.11/2.20. Declared Python floors lag modern evaluated annotations until 3.10; metadata is not a compatibility test.

### Environment activation and operational error handling {#environment-activation-and-operational-error-handling}

Read 9a45f0f (21), f0075aa (23), 3909029 (24), 7cfe619 (27). Conan-generated environment is activated in a subprocess that prints JSON environment; the parent imports it into os.environ before invoking upstream build. Selecting quoted sys.executable fixes PATH/interpreter mismatch. Logging non-JSON lines preserves diagnostics; later subprocess code captures stderr and translates launch exceptions.

Limits remain: no parent environment restoration, no concurrency isolation, no explicit return-code check before accepting JSON, errors-ignore decoding, and stderr may be bypassed by early JSON success. These are static observations, not reported incidents. The mechanism is suitable as a case study for process/environment boundaries, not a production-ready universal recipe to copy without tests.

### Configuration multiplicity, lockfiles, and advertised capability {#configuration-multiplicity-lockfiles-and-advertised-capability}

Read deivse [issue #9 dossier](../../thread-review/threads/dossiers/wu-vincent__scikit-build-core-conan-9.md), 39aa2fa (48), 6cc6a01 (49), efce6a0 (54), 3fa92e8 (55), 855ac93 (58). Build policies become string-or-list, normalized once before Conan binary analysis. Empty inputs default to missing; list order survives. Other additions expose deployers, update, package identity, partial/clean/output lockfiles. Do not attribute all those features to the build-list request.

A subsequent save-call simplification first replaces cwd with None, then removes settings.lockfile_out entirely. Schema and README retain lockfile-out. Final code calls save_lockfile(lockfile, None), so a caller-provided output value is not forwarded at this boundary. This contradiction is stronger evidence than the feature-list claim of reproducibility, but does not prove complete failure of every lockfile path. Empty lockfile maps to None, and recipe lookup uses a copied temporary location; exact default discovery should be independently tested against chosen Conan version. Suggested validation: graph input lock identity, output file path, partial/clean behavior, and repeated build determinism as separate tests.

### Tests, CI, and releases: assertions versus outcomes {#tests-ci-and-releases-assertions-versus-outcomes}

Read 662fe5d (31), 6ee0517 (35), 911e428 (46), 5bc99b7 (57), 4c43d3e (60). Initial tests exercise editable redirect/inplace plus isolated/nonisolated pip flows. They inspect wheel members/metadata and import location and run the compiled square function in a virtualenv; wheelhouse staging controls pip dependency source after an initial network acquisition. Cygwin is explicitly nonstrict xfail. The introduced fixture library includes names whose package folders are not in that addition; don't treat fixture names as exercised cases. Conditional count assertion's inplace branch evaluates literal 2, so it does not assert the count in that branch.

CI only appears in Jan 2026, with three operating systems and initially Python 3.9/3.11/3.13, later 3.10/3.11/3.13. Cache keys include OS/interpreter/recipe hash; profile detection is forced. No run logs or status evidence here. Earliest publishing workflow builds on manual/release events but publishes only release events; later manual release workflow publishes to PyPI and then creates GitHub release from pyproject version. CI is not a dependency of that release workflow. The source demonstrates design, not gate success or delivered artifacts.
