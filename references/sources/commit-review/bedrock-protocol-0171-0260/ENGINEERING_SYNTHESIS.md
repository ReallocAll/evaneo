## Read a packet's representation, not its domain nouns {#read-a-packet-s-representation-not-its-domain-nouns}

The most reusable mechanism in this sweep is the separation between a domain type, its C++ representation and the encoding at a particular field use. These are three distinct decisions.

- ActorUniqueID ordinarily means signed zigzag64, ActorRuntimeID and PlayerInputTick unsigned varint64. The alias declarations were checked in surrounding source. RemoveActor178 makes-1 one byte and preserves a negative value beyond32 bits. TakeItemActor230 uses two unsigned runtime IDs. Camera252 instead uses two unique IDs. SetActorMotion241 independently tests both runtime ID and tick above2^32.
- ActorPickRequest183 uses fixed int64 rather than the usual unique-ID encoding. CreatePhoto209 keeps the alias for the public model but overrides the wire to fixed uint64; RequestPermissions215 overrides it to fixed int64. The tests preserve-1 as eight ff bytes. A semantic ID label alone cannot pick the serializer.
- Header enum underlying width is not necessarily wire width. PlayStatus176 explicitly chooses fixed big-endian int32. Difficulty195 chooses unsigned varint32. ObjectiveSortOrder203 and LessonAction218 are byte-backed enums whose fields explicitly choose signed varint32. Attribute modifier operation/operand240 choose fixed int32. SimpleEvent250 explicitly chooses fixed uint16; CommandBlockMode257 is declared uint16 but follows compressed enum encoding, so its value2 occupies one byte in the golden.
- Byte update flags can still be wire-varints: UpdateBlock231 has uint8 memory type with uvarint32 field override. Conversely CrafterSlot220 uses int32 memory slot with uint8 wire override. The tested200 boundary distinguishes these. Neither test establishes behavior outside the in-memory/wire representable intersection.

The historical DSL documentation was read through its relevant field/union declarations. It says non-byte enum underlying integers compress by default and an explicit primitive override changes that. Default list/map count is uvarint32; fixed arrays carry no count. These details matter more than noticing that many annotations are called `int32` or `uint16`.

For implementation or review, write a per-field expectation for domain identity, memory type, signedness, width, byte order, count/presence marker and version range. Then choose values that would differ under plausible wrong codecs. Do not automatically reuse a neighboring packet's field order: ActorPickRequest183 follows dump order ID,slots,with_data despite header declaration ordering; BlockPickRequest233 places with_data before slots.

## Optional, union, empty and constant are different wire operations {#optional-union-empty-and-constant-are-different-wire-operations}

Text212 writes two discriminators: the three-case payload variant's uvarint32 index and that case's byte TextPacketType. A chat prefix includes both index1 and type1. A dump's switch presentation was insufficient to reveal the outer index, and the message explicitly names gophertunnel as corroboration. The model initially allows a caller to construct a variant/type mismatch; no consistency constraint or malformed-case test is added here.

Ordinary `T | None` writes a presence byte. Interact236 and ActorEvent238 use that for Vec3. ChangeDimension247 tests that respawn and loading-screen presence are distinct bytes, and present loading ID is fixed uint32. Text212 distinguishes absent filtered text from present empty text. Animate244 similarly distinguishes absent swing source from present enum NONE. A named sentinel is not equivalent to absence.

Empty packets182,197,222,225,226,228 have no body marker. The fixture helper was read: decode requires successful parsing and complete consumption; decode_partial requires success with unread bytes. Thus partial-empty tests really assert data remains, but only226 explicitly compares unread length with the entire frame size. Empty strings/lists behave differently: they retain length/count prefixes. An empty named NBT compound246 occupies0a0000 rather than zero bytes or a bytes-list length envelope.

MapInfoRequest251's phrase “optionally supplying pixels” is semantic. The schema declares a non-optional list and encodes a four-byte uint32 count even when empty. ResourcePackStack191 uses default varint pack count but reuses Experiments with a fixed uint32 toggle count. AvailableCommands258 has eight top-level list counts and an all-empty eight-byte fixture; its leading string pools are three, despite the message's “four” wording.

## Treat reference codecs and generated goldens as fallible oracles {#treat-reference-codecs-and-generated-goldens-as-fallible-oracles}

There are several evidence levels in this slice, which should remain visible in later retrieval:

2. ServerPlayerPostMovePosition181 has no gophertunnel packet16. A custom shim drives its low-level Writer. That can independently encode primitive floats but does not independently discover the packet's field list.

4. EditorNetwork214 initially drives that writer over the chosen dump field list and labels it patched. The later924/944 split improves the historical explanation without producing an independent post944 packet oracle.
5. Animate244 and AvailableCommands258 initially alter lowercase producer names to DSL casing. Later269 reverses those case edits and changes descriptor wire_name to lowercase. Selected message/descriptor/test hunks were read here. These original goldens are superseded, not independent evidence for upper/mixed-case writes.

PlayStatus176 also separates names from numbers: it chooses header names over gophertunnel's disputed education-mismatch constants, but deliberately tests PLAYER_SPAWN3, where both agree. That fixture validates the four-byte big-endian code, not the disputed names.

A robust audit should ask what a fixture actually independently establishes. A full-length equality test can still agree with a hand-patched misconception. A self-round-trip proves mutual consistency, not compatibility with a third party. Finite-width and count boundaries help diagnose serializer defects but do not substitute for a captured packet when producer/schema evidence conflicts.

## Name-coded enums: separator, case, declaration and serialized value {#name-coded-enums-separator-case-declaration-and-serialized-value}

CommandPermissionLevel254 needs GameDirectors rather than GAME_DIRECTORS because case folding leaves underscores intact. Animate244 needs explicit UseItem/ThrowItem/DropItem spellings for the same reason. Later269 folds these names when serializing; the separator correction remains valid while the casing claim changes. AvailableCommands258's ADMIN fixture does not test the GameDirectors fix directly.

The upstream producer chain clarifies protocol behavior: protocol-dumper8fdd054 reads a const-selector's getter and resolves it through its enum table instead of using a member label such as “Action” or “Response Type.” It throws when a constant cannot be resolved. Its contemporary message favors declared CamelCase; the next producer2219d21 changes the table from mOriginalEnumName to mName after two reported ResourcePackClientResponse captures show lowercase bytes. Equal string lengths could not settle capitalization. Both producer commits declare Claude Opus5(1M context) coauthorship, which remains credited. Their unresolved898 interpretation remains visible alongside the core protocol393/394/398 correction chain; the producer's last local statement alone is not global final truth.

For code generation,255 exposes a separate locality issue: name-coded serializer discovery scans a module's own fields, while emission walks its own declared types. A consuming module can discover an imported enum but cannot emit its definition; the declaring module can own the enum without seeing the consuming use. Reading the relevant FileGenerator and EnumGenerator logic statically corroborates this blind spot. Moving CommandPermissionLevel into command.py solves this particular ownership pairing and improves conceptual placement. No general compiler fix or reproduced link result is claimed from that relocation.
