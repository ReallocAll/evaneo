## Initial architecture, maintenance and validation contract {#initial-architecture-maintenance-and-validation-contract}

The README and CHANGELOG present v0.1 as under construction. The design separates adapters (the only code that knows server names) from common phases, samplers, bot and metrics. Servers are black boxes, except minimal source-built tick/position helpers; private reverse-engineering material is forbidden as feature evidence. Public source pinned to version, official documentation, or a named observable counter supports each non-unknown feature cell. Unknown exercised features cannot enter published tables. Fidelity V0 means vanilla paths, V1 reimplementation, V2 gameplay changes; this is not the same as the per-feature vanilla/partial/altered/absent/unknown classification.

Contribution instructions demand raw-run before/after metrics for formula changes, separate refactors from behaviour changes, and named changelog entries. Metric formulas bump analysis version, additive schema changes minor version, destructive/redefining changes major plus retained schema/migration. Resolved scenario content is hashed; changing a published scenario changes the workload. Metric IDs carry units. Tests are synthetic unit/fake integration tests that neither launch real Minecraft nor download BDS; per-platform real smoke belongs on maintainer machines. Published claims require those distinctions to remain visible.

The illustrative Chorus adapter is explicitly fictitious, including console patterns and configuration. It demonstrates immutable verified installs copied into per-run writable roots, override/default accounting, fresh world checks, pure launch declarations, named version/readiness/spawn patterns, nullable unknown positions, chaos rendered-or-unsupported coverage, and runtime facts. It is not proof Chorus implemented those commands. A later-deleted example matrix merely paired bds@1.26.52.3 with fictional chorus@1.4.2, spread100, three rotated repeats, 60-second cooldown and one invalid retry.

Adapter prerequisites are protocol/offline login, a truly per-executed-tick counter, positions and in-world readiness. Connected is too early for placement. Local artifacts are labeled unpublished, versioned helper reflection is tied to pinned server code, helpers must not change simulation, and every modified default is categorized. The four categories distinguish harness necessities, parity alignment, rescue from a known default failure, and nonvanilla simulation changes. Rescue/nonvanilla require outcome/behaviour footnotes. Runtime environment, allocator, heap and undisablable telemetry/crash upload are facts, not silently removed confounders.

## Experimental contract and its limits {#experimental-contract-and-its-limits}

R1–R10 specify one scenario per table, one bot source/allowlisted identity variation, equal placement/priority/heap, one measured run and interference monitoring, fresh copies/worlds, override accounting, no measured-window interventions, valid tick counters, retained failures, and cost next to work/parity. The lifecycle records partial manifests each phase and never overwrites run directories. Windows suspended launch and Linux pre-exec affinity avoid some startup-sizing errors; however other pages explicitly say BDS pools ignore affinity/cpusets. Do not propagate the broad “all pools now match CPUs” promise as proven.

Initial phases: ready+10 seconds then 20 seconds idle; 300-ms staggered joins capped at 300 seconds; settle 300–900 seconds until 60-second in-view unique-chunk growth ≤0.1/bot/s; position/spread check; 15-second delay and 90-second steady; optional 900-second chaos. Bounded settle retries (three reteleports after 20 seconds) and nudges (two after 60 seconds, high y/low chunks) are recorded. A capped/relatively incomplete view can remain only a flag. Because load spans joins+settle, the “no interventions in measured windows” rule conflicts in wording with allowed settle interventions. Core implementation review must determine the gate's actual windows; the documents alone do not establish a code bug.

The relative completeness test (95% of bots reach half the median bot's view) can pass when every bot is equally stalled. The documents themselves warn low delivery rate is not completion, yet the relative test is not an absolute own-view target. Earlier 317 theoretical-disc versus ~450 observed historical full-view chunks describe different accounting/support boundaries and must not be conflated. Own-position and dimension-sensitive chunk accounting, deduplication, first-seen timestamps and settle-time snapshots were intended corrections, not guarantees that every old figure maps directly.

Tick probes every five seconds use priority console writes and receipt times. Declare monotonicity, require idle advance, gate >15-second gaps and >1-second steady p99 latency. One-hertz process/thread/machine data plus ten-hertz tick CPU and ten-second foreign attribution minimize observer cost. Newly born/exited thread accounting avoids lost deltas. Foreign load subtracts server/bot/harness trees; default gates are 0.25-core mean, 1.5-core ten-second peak and 0.25 on server CPUs, with 15-second idle check. Bot CPUs >85% busy invalidate delivery evidence. Physical versus vCPU placement is disclosed; guest gates cannot see cloud-host neighbours, and separate cores still share cache, memory and power.

Statistics retain medians/min/max/all values and k/n success, at least three successful repeats for publication (or all failed), rotated order and cooldown. Invalid gets one retry with original retained; server failure is an outcome, not silently retried. Complete separation at 3+3 has stated one-direction probability 1/20 under a no-difference model; it is not immunity from selection, multiple testing or workload bias. The initial percentile text calls rounded q(n−1) indexing “nearest rank”; retain the actual formula rather than assume the standard ceil(qn) definition. Status prioritizes invalid over server_failed; warning-only dropped bots and numerous nonfatal flags still require reader attention.

## Metric honesty and workload choice {#metric-honesty-and-workload-choice}

ADR 0001 places protocol-independent bot behaviour in a common core with thin current/1001 frontends because Go cannot link conflicting gophertunnel versions in one module. Identity, circle walking, accounting and event output are shared; fake XUID is an allowlisted exception; patch policy requires failing test, upstream link and drop condition. A double-build claim is documentation, not a result of this review. Missing exact old steady bot sources/hashes are disclosed rather than reconstructed by guessing.

ADR 0002 rejects a composite score because weights encode use case and skipped simulation can masquerade as superior engineering. Costs must sit beside observed work and feature evidence; no cross-fidelity ranking. “~” means not separated, not equal. A lobby and survival deployment need different features. Declared parity and passive counters alone do not prove complete behavioural equivalence.

ADR 0003 correctly separates tick CPU from wall MSPT: 1000×CPU delta / executed ticks, over one matching window. Blocked time is absent; a tick computing 30 ms and waiting 20 costs 50 wall ms. Go has no fixed tick OS thread. The documentation then calls 1000/TPS exact wall MSPT whenever TPS<19.5; this depends on back-to-back tick execution and excludes other timing causes. Low TPS alone is not a universal proof of CPU saturation. Use CPU utilization and interval semantics to qualify the claim. Historical “43 ms” is tick-thread CPU, not directly measured start/end wall time.

ADR 0004 initially preserves legacy CSG-on spread100, five-second probe, easy difficulty, rate-based settle, nudges and 90-second steady; alternatives (one-second probes, fixed330-second load, normal difficulty) were rejected to avoid mixing measurement repair with workload change. A separate spread100-equal was cross-server CSG-off. By deletion, ADR0005 has superseded it: every ranking scenario including Endstone is CSG-off; legacy reproduction moves to spread100-csg and matching claims/matrix. It explicitly changes spread100 in place despite the earlier new-name promise because no results had yet been published from it. This is an acknowledged design reversal, not mechanically identical renaming.

Circle bots send at 20 Hz, fixed own height, 0.2158 blocks/input and 0.01 radians/input, golden-angle start headings, deterministic identity, no encryption, cache misses, radius request16 clamped by servers. Grid is 11 columns,640-block spacing, origin1280. This is deliberately spread terrain pressure, not general real-player simulation or clustered packet broadcast. Entity/redstone-heavy workloads, capacity sweeps and active parity probes remain planned.

Chaos plans are generated before runs from seed/scenario/count and bot indices, use randomized intervals, record scheduled/sent/applied times, count unsupported/offline actions, and stop new actions at >60-second backlog rather than silently lighten the test. Only applied server rule confirmations partition TPS; mixed-boundary samples are excluded. Normal random tick speeds0/1/3 are separate from100/1000. The portable catalogue includes weather, while PocketMine's page says weather unsupported: “portable” must be checked against actual adapter capability, not trusted as a name. Chaos is robustness evidence and never a capacity ranking.

## Provenance repair: what the original figures can support {#provenance-repair-what-the-original-figures-can-support}

The provenance document maps reported rows to surviving summaries and scripts, while admitting original probe/thread/bot/server raw directories were not kept. Postprocessed figures cannot be independently recomputed from those absent inputs. The exact steady bot source and binary hash were also not kept. Windows Endstone0.11.14 steady used a pre-release DLL (hash prefix85262df56bbd64e4) inside0.11.13; chaos used an earlier DLL (ed43d5e170ccb982), with neither source commit recorded. Linux steady was0.11.14.dev10 (97d48a04d), chaos dev4, and0.11.13 used a cp314 wheel. Released-wheel reruns are related experiments, not exact binary reproductions.

Historical Windows steady TPS is the median of five-second samples (vanilla9.40), but CPU division used whole-window TPS9.237; Linux headline TPS used whole-window rates. View t90 came from60-second summaries and historical unique chunks, not fine-grained own-view records. “GB” divided MiB by1000, so4857.4 MiB is about4.74 GiB, not the labeled4.9GB convention. Lowest5-second Endstone16.53 and lowest15-second17.46 were separately quoted as16.5 and17.5. Linux15-second dip7.95 was reported8.0. These are distinct estimands, not inconsistent duplicates.

Windows chaos archive does not establish whether published rows used five- or ten-second series; original straddling samples were assigned by their ending regime. Windows chaos was ten minutes, Linux fifteen, and Linux bots jittered radius before chaos. Old0.11.13 CPU1.81 and private-memory row are not fully present in the archive; some process-core metrics counted only threads alive at both endpoints. DevTools ~701ms/s is a disclosed known cost, not subtracted. The contaminated Linux dev4 run17.16 remains archived alongside rerun19.30.

The published custom-server table did not use one common harness: different phases,600-second settle cap, five-minute chaos, bot builds, easy versus normal difficulty, PocketMine world-time probe, Nukkit pregeneration and PNX default heap. Endstone's publication row came from final-100, but comparison.md's reference came from chaos-after-win. Nukkit fresh-world watchdog failure was not archived; other result rows use pregeneration. Endstone's745m/833m shadow checks and208 in-server tests are from separate instrumented builds, outside this archive and not reproducible by this black-box harness. The documentation's assurance that corrections do not change direction is an author assertion; missing raw data prevents independently certifying every claimed magnitude here.

The initial publication policy requires clean recorded harness, released artifacts,≥3 successful repetitions or all failures, same machine/scenario/analysis, every invalid/failure retained, raw bundles with hashes, parity next to costs, and immutable corrections as new publications. The legacy archive explicitly does not meet that policy and must not be mixed into new tables. Later removal of these pages is not retrospective proof the original legacy data met it.

## Deleted server pages: version-specific mechanisms retained {#deleted-server-pages-version-specific-mechanisms-retained}

- **BDS:** official hashed zips, no worlds, immutable tree/fresh copies, original executable unchanged baseline; RakNet/offline/allow-list/LAN changes allow the harness rather than optimize gameplay. Windows path-length guard, Linux executable mode/library path, tick-thread lowest-ID MC_SERVER, unnamed position JSON mapped to grid cells, and transport-error allowlisting are measurement specifics. max-threads remains8, pool sizing may ignore affinity, locator work differs across OS, and CSG-off ranking prevents reduced terrain work. No runtime check was performed here.
- **Endstone:** CPython-specific wheel and hashed dependency venv; local unlocked wheels remain unpublished. version.txt prevents silent BDS redownload; before/after executable hash checks identity. Discover child by executable path, not process name (Linux Main rename), reapply Windows priority to child, report launcher aux CPU. Clear Python/preload environment. Linux glibc variant isolates allocator only where supported. Default IPv4 and NetworkStackLatency bucket20/drain5 differ from vanilla; probe_bots must remain0. Crash upload has no switch and is explicitly disclosed. 0.11.14 intended equivalent paths are V1; own equivalence tests are not independent feature evidence.
- **LeviLamina:** Windows-only26.51.6 hosts BDS1.26.51.1 with pinned PreLoader/PeEditor/CrashLogger/runtime data. PeEditor patches once while building immutable install, collisions between package paths fail; shared installs differ for base/variants. CrashLogger's debugger attachment remains default, separate-process CPU excluded while server-side effect remains. Fresh JSON prevents upgrade merges and shutdown saves contaminating repeats. Default LeviOptimize fixes map-tracking chunk leaks on disconnect; all switches alter moving block-entity contents, explosion exposure reuse within a tick and zero-vector pushes; maxPushTimes remains−1. Version-level parity still records V1 although variants are documented V2: explicit unresolved representational limitation. Same-build vanilla baseline is essential.
- **Dragonfly:** dfbench wraps a library, pinned module/go.sum/zip and deterministic build flags with source/toolchain keyed cache, rejects official replace/workspace substitution and marks devel local builds. Owner-world/player tasks serialize command access; spawned differs from connected; EOF stops server. GOMAXPROCS/GOGC/GOMEMLIMIT/GODEBUG are cleared, actual runtime facts recorded. A distant radius-zero idle loader advances empty-world tick counter without requested chunks (reported tests), which is a harness intervention that matters when no players remain. Flat terrain, no mobs/locator/player correction and no fixed OS tick thread forbid vanilla-equivalent throughput inference. The original summary's “data saving off by default” is superseded by this page's actual true defaults; measure pinned defaults rather than trust generic prose.
- **Nukkit:** pinned snapshot+Temurin21, reproducible locally built reflection helper tied to commit; JVM main-thread OS-ID queried before idle. Fake XUID prevents UUID collisions, allow-flight prevents hover kicks, per-IP120/10ms limit lifted, fixed heap, auto-tick-rate disabled. Default watchdog remains an outcome; no-watchdog rescue uses debug.level2 and therefore also changes logging. Default per-world handling is subtler than “one level”: Nether/End still load idle for chaos. Pregeneration explicitly populates, unloads/saves and reloads to verify99% coverage. Helper server tick differs from unusable own time-query output.
- **PocketMine:** protocol1001 frontend using shared core plus login backport; bundled PHP/ini/extension path and cleared PHPRC, first-created tick thread. Async-worker count aligned explicitly because auto ignores affinity. 1GiB hard-limit rescue is visible and stock variant preserves failure;200-packet RakLib-tick ban is lifted for loopback. Helper Server::getTick replaces world-time probe. Unsupported dimensions, mob/weather/block/ticking-area actions remain counted, not simulated equivalents. Custom terrain, no CSG/subchunk requests/observed corrections or locator keep reduced-fidelity caveats attached.
- **PNX:** pinned3.0.5 banner carries SNAPSHOT/git9813b75, fixed Temurin heap, world JSON seeds all dimensions and fresh check uses database absence. Fake XUID, per-IP limit raised but per-session limits remain. Bot-reported positions are fallback, not server-confirmed truth. No plugin pregeneration outside player views; ten-bot tour and received-disc coverage are weaker than Nukkit's storage reload verification. Cleanup selector could kill players, so unsupported. Source movement checks coexist with zero corrections in observed legacy runs; absence of packets is not proof of no code. Synchronous main-thread chunk loads in pregenerated legacy profile are reported, not measured here.
