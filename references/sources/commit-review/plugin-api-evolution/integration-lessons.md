# Scoped integration lessons {#scoped-integration-lessons}

These are retrieval aids backed by the detailed cases, not global personality rules. All evidence is static unless a separate author-reported claim is explicitly identified. “Try” items are proposed validation, not performed tests.

## Cross-language plugin API or service lookup {#cross-language-plugin-api-or-service-lookup}

Read PAPI01 + PAPI02. A shared C++ Service interface, Python override trampoline and distributed header can decouple clients from the provider language. The observed redesign replaces a temporary raw plugin downcast wrapper. Require correct arguments, initialization symbols, callback converters, null handling and provider-unload ownership. Counterexamples: unchecked service result and the retained nullable-pointer dereference. Do not retrieve only the architectural success while suppressing the boundary defects.

## Public API rename, type stub or command schema {#public-api-rename-type-stub-or-command-schema}

Read PAPI02. Treat header, trampoline, compiled module name, Python implementation, stubs, examples, command handlers and docs as a dependency graph. “Update stubs” also fixed the compiled module's init symbol and functional callback header. The command parser fix moves a greedy message to the end. Try all actual invocation paths; a search/rename and metadata declaration alone are inadequate.

## Packaging and Python compatibility {#packaging-and-python-compatibility}

Read PAPI03. Ship the C++ header with its provider when consumers need both; distinguish wheel build, wheel import, sdist build and interpreter syntax. Counterexample: Python>=3.9 metadata with match syntax and source exclusion of native binding files. Keep branch/tag identity visible. No generalized endorsement of one backend follows from a backend-change title.

## Plugin API upgrade diagnosis {#plugin-api-upgrade-diagnosis}

Read SIDEBAR01. A missing bound method is an API/version issue, not automatically a config issue. Match the exception path to an exact release diff and retain absence of reporter retest. Coordinate rounding, zero-padding and eager callbacks mean a compact lambda refactor may alter user-visible behavior. Preserve old config aliases when intentionally retaining compatibility.

## Async external integration and shutdown {#async-external-integration-and-shutdown}

Read DISCORD01. Keep server API work on the server scheduler and transport primitive event data across the process boundary. A graceful-close sentinel still needs bounded waiting, worker failure handling and a terminal-state policy. Target evolution improves ten-second sleep to a five-second join, but leaves cleanup and invalid-channel paths unresolved. Try failure/disconnect paths, not only successful chat.

## Third-party PR review and trust boundaries {#third-party-pr-review-and-trust-boundaries}

Read DISCORD01. An embed PR can add console execution privileges. The configured Discord console channel accepts any non-bot author's text as server commands. This is ArkanDash's contribution merged by Vincent, not evidence of Vincent’s security preference. Review permission/authority changes across every file regardless of PR title; thank-you/merge is not evidence of comprehensive audit.

## Native profiler architecture and lifecycle {#native-profiler-architecture-and-lifecycle}

Read SPARK01. Isolate handler capture, aggregation and export, but do not infer safety from separate threads or a lock-free queue. Try repeated start/stop, live info reads, delayed signals, plugin disable, two-queue ordering and handler restoration. Counterexamples: persistent state not cleared, map read racing writer, timeout without handler cancellation, and global SIGPROF ownership.

## Profiling data, protobuf and viewer adapters {#profiling-data-protobuf-and-viewer-adapters}

Read SPARK02. Module+RVA identity and deferred symbolization keep expensive names out of collection. A small write-only serializer can avoid a runtime dependency when schema is bounded, but requires decoder/viewer tests. Preserve authored credit for lucko/spark format. Current source substitutes average values into fields named median/rolling windows and adapts Java widgets for native data; those are approximations, not additional measurements.

## Export mode, retry and privacy {#export-mode-retry-and-privacy}

Read SPARK02. Explicitly verify whether a start-time save choice survives manual stop. Here manual stop can choose upload unless its own save flag is repeated, and the suggested post-failure retry command does not accept an already-stopped profile. Profiles include creator/plugin/world/host metadata. System curl avoids a linked TLS stack but introduces subprocess/platform/timeout obligations. No upload was executed.

## Dependency workaround and cross-platform claims {#dependency-workaround-and-cross-platform-claims}

Read SPARK03. Spark's comment cites a real reference-capture scheduler bug, but a same-day fix exists before spark's root and the captured v0.11 branch uses value capture. Revalidate historical rationale against exact resolved revision. Windows code is explicitly unexercised and statically incomplete; never promote “backend exists” to validated support. Keep ABI advice as author-stated constraints until tested.
