# Packaging, platform behavior, release configuration and documentation {#packaging-platform-behavior-release-configuration-and-documentation}

## Dependency and build evolution {#dependency-and-build-evolution}

The first package [002 · 3f7a9f8eb2f0](../commits/002-3f7a9f8eb2f0.md) uses hatchling, Python 3.8 or later and a separately declared asyncio runtime dependency. The timer-era implementation raises the floor to Python 3.10 at [030 · 3f6652361834](../commits/030-3f6652361834.md). The rewrite's packaging cleanup [049 · 1e58ae75549f](../commits/049-1e58ae75549f.md) removes the asyncio package dependency, retains Python 3.10, adds pytest/pytest-asyncio/Ruff development tooling and typed-package metadata. This is a concrete reduction in runtime dependency surface, not a general rule to avoid dependencies in all projects.

Test consolidation [055 · de96971f365a](../commits/055-de96971f365a.md) adds pytest-xdist. Coverage support [078 · 9e8efffa6660](../commits/078-9e8efffa6660.md) adds pytest-cov. Final hardening [096 · 1647e1fbd8c1](../commits/096-1647e1fbd8c1.md) adds strict mypy and bounded development dependency version ranges. Although the message says “pin,” ranges are not a lockfile or exact reproducible dependency resolution. Type casts on struct unpacking and Any kwargs in factories satisfy a specific static typing boundary; they do not validate protocol payload correctness or API keyword names at runtime.

## CI declarations versus observed executions {#ci-declarations-versus-observed-executions}

[077 · f5a80a0c57f3](../commits/077-f5a80a0c57f3.md) configures lint/format plus a matrix across Ubuntu, Windows, macOS and Python 3.10–3.13. A release-published event builds/publishes through PyPI trusted publishing with `id-token: write`. That is configuration of an external release capability, not evidence that a release was actually built, uploaded, installed or trusted-publisher permissions successfully granted.

[078 · 9e8efffa6660](../commits/078-9e8efffa6660.md) configures source coverage and a separate Codecov upload. Upload failure is non-blocking. [090 · fe1aa1f0993e](../commits/090-fe1aa1f0993e.md) adds branch coverage and repository/secret-reference configuration. A CI reference to a secret name is not an exposed credential and was not used here. [096 · 1647e1fbd8c1](../commits/096-1647e1fbd8c1.md) enforces a 90% coverage floor in the configured test command. Message-reported 98% coverage at [092 · 172c5b0a34c9](../commits/092-172c5b0a34c9.md)/[095 · b16084f41d35](../commits/095-b16084f41d35.md) remains unmeasured by this review; line and branch coverage should not be conflated.

## Platform workarounds and policy reversals {#platform-workarounds-and-policy-reversals}

[079 · c54c5d9bd5e2](../commits/079-c54c5d9bd5e2.md) removes macOS from the matrix because the message reports runner UDP problems. That gives a stated reason for narrowing CI, not evidence the library works or fails on every Mac. It also attempts Windows UDP-reset ioctl through the asyncio transport socket. [080 · 586499e6be2e](../commits/080-586499e6be2e.md) replaces that route with a raw socket created and bound before asyncio takes ownership, applying SIO_UDP_CONNRESET through ioctl or ctypes fallback. The replacement explains why socket wrapper capabilities matter at an FFI/platform boundary.

Tests later mock platform branches, but mocked control flow is not a real Windows execution. No Windows socket behavior, ctypes ABI or CI runner failure was independently reproduced. Platform behavior also drives the fail-fast-to-timeout reversal [067 · 1066db009a2f](../commits/067-1066db009a2f.md)→[093 · 05e52ac24fd0](../commits/093-05e52ac24fd0.md) and the manual ping timer [079 · c54c5d9bd5e2](../commits/079-c54c5d9bd5e2.md)→[080 · 586499e6be2e](../commits/080-586499e6be2e.md). Preserve those causal links instead of isolating each workaround as a universal design rule.

## Public contract and documentation drift {#public-contract-and-documentation-drift}

[066 · 70b168af6340](../commits/066-70b168af6340.md) adds CLAUDE.md with architecture/development instructions. It is evidence of repository-local agent coordination, not current agent guidance. [081 · 0eaae5130d76](../commits/081-0eaae5130d76.md) corrects clean-room descriptions to C++-reference language, adds MIT LICENSE, version/changelog/project links and broadly normalizes punctuation. The 2023 BSD license had been removed during [047 · 969d4d32bb56](../commits/047-969d4d32bb56.md). No licensing conclusion beyond that source chronology is inferred.

Documentation expands substantially at [086 · 38e3fe64f018](../commits/086-38e3fe64f018.md), including API catalog, exception/priority/address information, community templates and comparisons with other libraries. [089 · 65d56b479ee0](../commits/089-65d56b479ee0.md) deliberately condenses it into quick starts, ping and error handling. Competitor claims were not independently verified and should not be carried into neutral recommendations. Taken together, the two revisions show how the README shifted from a detailed API reference to a shorter getting-started guide.

Two final API mismatches are material:

- Several standalone examples still await send after it became synchronous in [083 · 994f00d73acc](../commits/083-994f00d73acc.md)–[084 · 79cb8cf9f66e](../commits/084-79cb8cf9f66e.md). Updating README examples at [085 · 1ad7cac9fb93](../commits/085-1ad7cac9fb93.md) did not cover them all.
- The condensed README's ping example uses `response.guid`, while PingResponse exposes `server_guid`. The final implementation and type record support the mismatch; no execution is needed to observe the incompatible names.

A further wire docstring still says IPv6 SystemAddress is 27 bytes while its code uses 29. The short-lived AUDIT_REPORT [073 · 1078d7dbe490](../commits/073-1078d7dbe490.md)–[077 · f5a80a0c57f3](../commits/077-f5a80a0c57f3.md) contains confidence claims and then stale GUID text despite a repair. Treat these as documentation-testing needs rather than copying the prose as authoritative API truth.

## Useful application {#useful-application}

Use this dossier when auditing a Python library release: distinguish configured checks from observed passes; review actual runtime dependencies separately from development ranges; test raw socket setup where wrappers hide platform calls; and search every example when changing a public signature. The strongest claims here concern source changes and explicit messages. Compatibility, published releases, measured speed, Windows success and legal provenance remain separate validation tasks.
