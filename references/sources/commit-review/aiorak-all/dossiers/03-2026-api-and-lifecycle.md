# The 2026 architecture, public API and lifecycle qualifications {#the-2026-architecture-public-api-and-lifecycle-qualifications}

## Tick-driven layers and the Event-to-handler pivot {#tick-driven-layers-and-the-event-to-handler-pivot}

The rewrite [048 · 21a9b41401a9](../commits/048-21a9b41401a9.md) separates BitStream, wire/framing, congestion, reliability, Connection, UDP transport and client/server surfaces. Reliability and connection progress are driven by explicit periodic `update(now)` work instead of one event-loop timer per reliable message. Client/server update tasks run approximately every 10 ms. This makes state transitions and timing inputs more inspectable, but it does not automatically guarantee cleanup, fairness, bounded work or deterministic execution.

The first API exposes Events and initially owns retransmissions by datagram. Initial tests [051 · d3edff38b025](../commits/051-d3edff38b025.md) and examples [050 · a20c8f160f82](../commits/050-a20c8f160f82.md) reflect that contract. [052 · d099a6ecd1d2](../commits/052-d099a6ecd1d2.md) repairs offline discovery: ping parsing validates magic/duplicate completion, the server can answer without allocating a Connection, and UDPSocket distinguishes connected transport addressing.

[053 · 02518a3c358b](../commits/053-02518a3c358b.md) then replaces central Event consumption with per-peer handler coroutines and byte-oriented Connection queues/async iteration. Client and server reuse the Connection surface. The server maintains separate maps for pending protocol connections, established peers and handler tasks. These sets have different lifetimes; treating them as one count is unsafe. A normal handler return does not necessarily close a peer. Handler exceptions are initially swallowed, then made visible through logging in [064 · 2961f488270f](../commits/064-2961f488270f.md).

[054 · 8d5e18e56b16](../commits/054-8d5e18e56b16.md) keeps reliability updates active while DISCONNECTING and drains pending work for up to one second before cancelling the update task and closing the socket. It also prevents new peers during shutdown. The explicit budget bounds shutdown latency, so the correct API description is best-effort drain rather than an absolute delivery promise. Tests exercise successful graceful-close scenarios, not every cancellation or remote-failure permutation.

## API honesty and migration cost {#api-honesty-and-migration-cost}

[083 · 994f00d73acc](../commits/083-994f00d73acc.md) changes Connection.send from async to synchronous because it only enqueues and contains no await. This rationale is explicit. [084 · 79cb8cf9f66e](../commits/084-79cb8cf9f66e.md) does the same for Client.send and removes direct recv methods in favor of async iteration. The resulting contract separates enqueue from delivery: a successful synchronous call means the local layer accepted a payload, not that a peer acknowledged it.

This is intentionally source-incompatible. Tests and README snippets migrate at [084 · 79cb8cf9f66e](../commits/084-79cb8cf9f66e.md)–[085 · 1ad7cac9fb93](../commits/085-1ad7cac9fb93.md), but several standalone examples at the final target still `await` synchronous send: echo client/server, chat client/server and the multi-client sample. Static source comparison establishes a mismatch; no example was executed. [061 · 7f2b5b0218f4](../commits/061-7f2b5b0218f4.md) had already repaired a missing required handler in the ping example after the earlier API migration. Together these are counterexamples to assuming that a repository-wide API change was complete merely because a quick start changed.

[086 · 38e3fe64f018](../commits/086-38e3fe64f018.md) threads priority into public sends and distinguishes local address from remote-prefixed connection properties; adds repr, GUID and connection-list access; and prepares community/release documentation. [082 · fc2270f8da2c](../commits/082-fc2270f8da2c.md) adds a server GUID property. [091 · 4aaf4559c901](../commits/091-4aaf4559c901.md) removes connection_count in favor of `len(server.connections)`. [087 · 3c33478ed5e5](../commits/087-3c33478ed5e5.md) removes Optional guards from Server because the factory returns only started objects. [076 · 03a7726369f3](../commits/076-03a7726369f3.md) had made a similar successful-factory invariant explicit for Client. Those invariants simplify the steady-state surface, but do not by themselves cover failure during creation or direct construction.

## Errors are a policy, not a single direction {#errors-are-a-policy-not-a-single-direction}

[067 · 1066db009a2f](../commits/067-1066db009a2f.md) adds fail-fast transport errors: ICMP/OSError can wake a pending handshake with an error instead of forcing it to wait. [093 · 05e52ac24fd0](../commits/093-05e52ac24fd0.md) explicitly reverses that behavior to debug-log-and-ignore for consistent timeout behavior across platforms. Preserve both the former latency benefit and the later consistency choice. This is not evidence of a broad preference to swallow exceptions.

[086 · 38e3fe64f018](../commits/086-38e3fe64f018.md) introduces public exception classes, and [088 · 9c132d11bf6e](../commits/088-9c132d11bf6e.md) connects timeout, rejection and closed-connection exceptions to actual call sites. Dual inheritance retains compatibility with standard-library catch categories. However, ProtocolError is exported while many parsers still raise plain ValueError. “Catch the library base error” therefore cannot be expanded into “all malformed protocol input is wrapped in that type.”

Ping timeout handling evolves from wait_for to explicit timer cancellation in [079 · c54c5d9bd5e2](../commits/079-c54c5d9bd5e2.md)–[080 · 586499e6be2e](../commits/080-586499e6be2e.md), and [096 · 1647e1fbd8c1](../commits/096-1647e1fbd8c1.md) places transport closure in a finally immediately after endpoint construction. The final ping code catches CancelledError and translates it to a library timeout regardless of whether the cancellation came from its timer or the caller. This is a static cancellation-semantics qualification. Distinguishing user cancellation from timeout would require a distinct signal or ownership test; no such change is claimed here.

## Final-source ownership counterexamples {#final-source-ownership-counterexamples}

These findings use the final target `1647e1fbd8c1df12a183e63f8dd20e1a27f8116e` and the local guarded context files. They are source-level observations and hypotheses about composed behavior, not reproduced runtime failures.

1. **Failed connect lacks symmetric cleanup.** `_client.py:76–126` creates the transport and starts its update task before awaiting connection completion. Timeout is translated and connection errors are raised, but no finally closes the partially constructed client. A factory invariant that successful return means initialized does not clean up a failed factory attempt.
2. **Remote close can bypass disposal.** `_client.py:266–287` feeds the end sentinel and sets `_closed=True` when it processes DISCONNECT. `close()` at lines 128–159 returns immediately if `_closed` is already true, before task cancellation and socket closure. The update loop at 297–331 may exit or remain pending based on reliability state, but does not itself finally close the transport. Logical closure and resource disposal share one flag without an independently established disposal path.
3. **Server event removal can pre-empt ACK drain.** Connection's disconnect-notification branch at `_connection.py:745–751` enters DISCONNECTING, sets its ACK-drain flag and immediately emits DISCONNECT. The server's event processor at `_server.py:560–585` removes that connection from `_connections`; later periodic updates visit only that map. The intended delayed-ACK state added in [073 · 1078d7dbe490](../commits/073-1078d7dbe490.md) therefore needs integration-level scrutiny. This is a composed-state concern, not proof of a specific observed packet loss.
4. **Handler-task bookkeeping is not task cancellation.** The same server removal path pops `_handler_tasks` without awaiting/cancelling that task there. A queued sentinel ordinarily lets an iterating handler finish, but a handler doing unrelated work may outlive the map entry. Normal handler return also does not establish peer closure.
5. **One sentinel is not a permanent closed iterator state.** Connection uses an asyncio queue and a single end sentinel. A consumer that calls into iteration again after consuming that sentinel lacks a separately demonstrated immediate-closed check. This is outside the common `async for` usage but matters if promising robust re-iteration.
6. **Timeout properties need owner consistency.** Later public timeout changes update connection state, while the reliability layer's timeout is captured at construction. A mutable property is not evidence that all dependent timers/readers observe the new value.

## How to use this evidence {#how-to-use-this-evidence}

Retrieve this dossier for async ownership, factory lifecycle, enqueue APIs, handler/server lifetimes or migration audits. Preserve the distinction between an implemented intention and its cross-layer realization. A useful future test plan would cover cancellation while connecting, remote disconnect followed by close, outstanding ACKs while removing peers, long-lived handlers, repeated iterator access and example compatibility. Those are proposed verification targets; none of those tests were run.
