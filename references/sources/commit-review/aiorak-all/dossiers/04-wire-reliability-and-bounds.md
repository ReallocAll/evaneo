# Wire fidelity, reliability redesign and resource limits {#wire-fidelity-reliability-redesign-and-resource-limits}

## Paired tests were insufficient for wire compatibility {#paired-tests-were-insufficient-for-wire-compatibility}

The rewrite and initial roundtrip tests [048 · 21a9b41401a9](../commits/048-21a9b41401a9.md), [051 · d3edff38b025](../commits/051-d3edff38b025.md) use matching Python encoders/decoders. Such tests prove local agreement and exercise code, but both sides can share the same mistaken byte order. [058 · 25456e7f42be](../commits/058-25456e7f42be.md) is the concrete counterexample: 16-, 32- and 64-bit integer encoding changes to big-endian while 24-bit sequence values remain little-endian. It also corrects reply-2's one-bit security flag, reliable-ordered disconnect, timestamp echo and ordering/sequencing counter reset. Earlier blanket compatibility statements are authored claims, not established facts.

[059 · 3a757cef955a](../commits/059-3a757cef955a.md) extracts shared ordering-counter advancement to prevent single/split paths from drifting; that rationale is explicit. [060 · 157807b72657](../commits/060-157807b72657.md) centralizes reliable/sequenced/ordered classification on Reliability enum properties. These refactors reduce duplicated protocol-state decisions; they do not create new delivery guarantees on their own.

[065 · 17ec20091aeb](../commits/065-17ec20091aeb.md) makes version, MTU bounds and discovery candidates configurable, with the rewrite defaulting to RakNet 6 and MTU 1492/400. [071 · 2134ab6df587](../commits/071-2134ab6df587.md) adds resolved peer addresses for hostnames, a 29-byte IPv6 SystemAddress implementation, configurable internal-address count, real local interface/port reporting and rejection IDs. One docstring still describes 27 bytes. IPv6 family encoding uses the platform AF_INET6 value while reading skips that field; external interoperability has not been verified here. Security negotiation remains unsupported.

## Successive hardening passes expose the difference between local and total bounds {#successive-hardening-passes-expose-the-difference-between-local-and-total-bounds}

[064 · 2961f488270f](../commits/064-2961f488270f.md) introduces a fixed datagram receive window, split eviction, channel/MTU/ACK-range validation and logs. [070 · bff4439e9b3c](../commits/070-bff4439e9b3c.md) switches split age to last update, evicts periodically, caps fragment counts, uses modular ACK/NAK range lengths and reduces MTU after repeated probes. At this stage each ACK/NAK range is capped separately, so many ranges can still produce more total work. [096 · 1647e1fbd8c1](../commits/096-1647e1fbd8c1.md) finally limits aggregate ACK/NAK work per packet.

[070 · bff4439e9b3c](../commits/070-bff4439e9b3c.md) also adds compressed integer helpers with roundtrip tests. [073 · 1078d7dbe490](../commits/073-1078d7dbe490.md) explicitly removes them as incorrectly encoded and unused. Passing a paired roundtrip did not establish the external format. This is an unusually direct reversal useful for codec audit: independent byte vectors and provenance-specific reference behavior are stronger than self-consistency alone.

## From datagram retries to message ownership {#from-datagram-retries-to-message-ownership}

[072 · 862190c1e17d](../commits/072-862190c1e17d.md) replaces datagram-owned resends with a per-reliable-message resend buffer and a datagram-to-message history. An ACK resolves the messages carried in an acknowledged datagram, while message identity survives repacking/retransmission. It adds separate datagram and reliable-message deduplication, upgrades split unreliable payloads to reliable transport, assigns reliable numbers late during packing, applies modular counters, fragments ACK/NAK packets under MTU and uses exponential retry timing.

This is a substantive ownership redesign, not merely optimization. Datagram identity is a transmission attempt; reliable-message identity is the logical unit being delivered. Retransmission scheduling precedes new traffic, and resends can bypass congestion restrictions that would otherwise deadlock recovery. The code's `has_pending` includes datagram history, even for unreliable traffic; “pending” is thus not identical to “unacknowledged reliable application message.” Tests cover selected deduplication, wrap, upgrade and ACK/NAK cases, but were not executed by this review.

[073 · 1078d7dbe490](../commits/073-1078d7dbe490.md) adds weighted priority scheduling and interleaves sequenced messages within ordered slots. It retains NAK history, fixes the handshake deadline to initial start instead of activity-refresh, adds half-timeout reliable keepalive and adjusts frame/socket handling. The audit report claims all identified issues are fixed. That phrase is bounded by what its author identified, and subsequent changes demonstrate it is not proof of protocol completeness.

Two final static ordering details deserve caution: the heap compares ordinary numeric ordering values even though protocol counters wrap, and the ordered sentinel subkey is 1,048,575 while sequence values are 24-bit. Comments assume sequenced subkeys remain below that sentinel, but the reviewed counter range does not establish it. These are unvalidated edge-case concerns, not runtime failures established here.

## Handshake admission and server allocation {#handshake-admission-and-server-allocation}

[074 · ec4115547871](../commits/074-ec4115547871.md) adds GUID-to-address tracking and rejects reuse of a live GUID from another address. The message describes a four-way identity matrix, but the new condition is narrower. Its shortened audit report even retains a now-stale missing-GUID assertion, and [077 · f5a80a0c57f3](../commits/077-f5a80a0c57f3.md) deletes the report entirely. Documentation confidence must be compared to actual conditions.

[075 · 50aec9bb9035](../commits/075-50aec9bb9035.md) makes OCR1 stateless and allocates a pending connection only on validated OCR2. It also adds broadcast/exclusion, peer-disconnect and timeout/MTU access, and an optional 100 ms non-loopback per-IP limit. This reduces one allocation surface. However, capacity checks count established peers, not all pending connections; the IP-time map has no normal expiry demonstrated before server close. “Stateless first handshake” therefore does not imply bounded total handshake state.

## Final bounds: what they actually do {#final-bounds-what-they-actually-do}

[096 · 1647e1fbd8c1](../commits/096-1647e1fbd8c1.md) adds named limits to ReliabilityLayer: 512 split trackers, 8,192 ordered-heap entries per channel, 16,384 receive-queue entries, 4,096 resend-buffer entries and 4,096 datagram-history entries. It validates split indices/contiguity, fixes split-ID wraparound and caps total ACK/NAK processing. None of the test files changes in that commit. These are real code changes, but the broad “bound all data structures” and production-hardening phrasing needs the following qualifications:

- At resend capacity, the send loop still encodes and returns a new reliable frame for transmission; it merely skips adding that new frame to the resend buffer. The constant's description of blocking new sends is not implemented. This changes reliability under saturation rather than supplying backpressure.
- When receive/ordering limits are reached, payloads can be dropped after datagram receipt/ACK/dedup bookkeeping has advanced. A reliable classification does not itself guarantee recovery of a payload discarded at a later local queue boundary.
- The bounded ReliabilityLayer receive queue is drained into a separate unbounded `asyncio.Queue()` in Connection. A slow application consumer can therefore grow memory outside the new bound.
- The outgoing send queue remains unbounded. Reliable-message receive-window advancement can allocate a large hole window up to its one-million threshold. Pending handshake maps and per-IP state are outside this new list of limits.
- Tracker/history eviction trades memory for recovery information. Dropping the oldest tracker/history is not equivalent to refusing fresh work before acceptance.
- The removed unreliable-timeout path was explicitly dead. One retained test manually sets a stale creation attribute and asserts the queue empties; ordinary sending can also empty that queue, so the assertion alone no longer demonstrates age-based culling. A second mixed-entry test invokes update but has no outcome assertion at all.

These observations distinguish resource-accounting boundaries, not an exploit demonstration. No packets were sent and no resource-pressure experiment was performed. A future validation should test each limit at capacity and one beyond, trace whether acceptance/ACK precedes rejection, observe application-queue growth, and define whether saturation blocks, fails a call, drops an unreliable item or closes the connection. Those alternatives have different API and delivery costs.

## Portable reasoning {#portable-reasoning}

Use this history for distinguishing wire-format correctness from local roundtrip success; logical messages from transmission attempts; local queue caps from end-to-end memory bounds; and audit claims from executable conditions. Preserve C++ RakNet attribution and declared Claude coauthorship. Do not turn claimed reference fidelity into independently established compatibility or describe every policy as a personal preference of the GitHub author.
