# The 2025 client: handshake, retries and cleanup {#the-2025-client-handshake-retries-and-cleanup}

## Primitive and framing assumptions {#primitive-and-framing-assumptions}

[006 · c548de6e4706](../commits/006-c548de6e4706.md) builds a byte buffer with read cursor, copy-on-write handling of memoryview input and integer/address helpers. A generic read returns a slice rather than demanding exactly the requested length, so safe decoding depends on integer decoders or caller-level validation. [007 · 2bd2c02f26c1](../commits/007-2bd2c02f26c1.md) sets the era's protocol version 11, MTU defaults around 1400/minimum 576, channel/address constants and message IDs. These are historical values; the 2026 default envelope differs.

The DatagramProtocol-based connection in [008 · dd7423f0c869](../commits/008-dd7423f0c869.md) owns its event loop and transport and routes callbacks. [009 · 0904bd2a5bb6](../commits/009-0904bd2a5bb6.md)–[014 · 7f992686e507](../commits/014-7f992686e507.md) implement offline probes and the open-connection handshake progressively. [012 · 531475ba4fad](../commits/012-531475ba4fad.md) checks per-message minimum lengths and magic before routing, but does not make every dispatch path hostile-input-safe. The protocol-incompatibility test [013 · 89db6e3ec40f](../commits/013-89db6e3ec40f.md) assumes an external configured server, so it is less isolated than later loopback fixtures. No endpoint was contacted.

[014 · 7f992686e507](../commits/014-7f992686e507.md) creates separate open/connect futures. Per-attempt waits shield a shared future so timing out one probe does not cancel the eventual handshake result. That is a concrete ownership choice: the caller owns an attempt timeout; the connection owns the shared completion. Duplicate reply handling is separately guarded at [018 · 9f3c352b5e15](../commits/018-9f3c352b5e15.md). The pattern is useful for retrying a single logical operation, but only when final cancellation and transport cleanup are also defined.

## Reliability was assembled, not born complete {#reliability-was-assembled-not-born-complete}

[015 · c82333cf6637](../commits/015-c82333cf6637.md) supplies frame/flag structures with send/split placeholders. [016 · 5282ff4856a8](../commits/016-5282ff4856a8.md), despite a formatting title, wires reliability into connection handling and changes behavior. [017 · 03430fe163ec](../commits/017-03430fe163ec.md) adds congestion-window and RTT/RTO bookkeeping. [019 · 6de02c3ac35d](../commits/019-6de02c3ac35d.md) packs new outgoing messages under congestion budget. [020 · bf68eb53c227](../commits/020-bf68eb53c227.md) adds reliable-message IDs, datagram history and headers, followed immediately by the split width correction [021 · 2a7ef10a2274](../commits/021-2a7ef10a2274.md). ACK generation [023 · a1151f51b605](../commits/023-a1151f51b605.md) and NAK construction [024 · eaf454e86e94](../commits/024-eaf454e86e94.md) are separate milestones from retransmission completion. ACK emission still has resend cancellation marked as TODO at that point.

[021 · 2a7ef10a2274](../commits/021-2a7ef10a2274.md) separates datagram headers from frame parsing. [022 · 1a295bd1428a](../commits/022-1a295bd1428a.md) routes protocol-control versus application payloads by message IDs and message form. [025 · d6d264196250](../commits/025-d6d264196250.md) completes a further connected handshake step using local/internal addresses and timestamps, while repairing the preceding ACK/NAK dispatch error. These changes are causally interleaved; a synthetic account that describes finished independent layers at every step would be misleading.

Connected ping/pong [026 · 432591291a99](../commits/026-432591291a99.md), [028 · 74bded43c1f2](../commits/028-74bded43c1f2.md) establishes RTT plumbing and a five-sample latency history. The send facade first appears on Client [027 · 722c56e1a024](../commits/027-722c56e1a024.md) and then moves to the shared connection [028 · 74bded43c1f2](../commits/028-74bded43c1f2.md). [029 · ef6a55e780c6](../commits/029-ef6a55e780c6.md) removes an unused detect-lost path without a broad explanatory rationale; the 2026 code later restores a handler. That deletion is unsuitable as a general rule against liveness messages.

## Retry ownership and liveness {#retry-ownership-and-liveness}

[030 · 3f6652361834](../commits/030-3f6652361834.md) moves transport responsibility into ReliabilityLayer and introduces reliable-message retry scheduling, pending-byte/history bookkeeping and resend-before-new-send ordering. It also raises the Python floor to 3.10. The design here is timer-driven. It must not be silently conflated with the 2026 layer's explicit `update(now)` tick.

[031 · 5b3fc0ba7d5f](../commits/031-5b3fc0ba7d5f.md) and [032 · 0496e43c8e45](../commits/032-0496e43c8e45.md) adjust keepalive behavior around outstanding reliable work. [033 · 9e05e123632e](../commits/033-9e05e123632e.md) handles invalid-password connection outcomes and timeout flow. [034 · 9f32c1ae1b29](../commits/034-9f32c1ae1b29.md) introduces a state machine and explicit disconnect/timeout transitions, but immediate enum/import/value mistakes require [035 · 936e5e1cf09b](../commits/035-936e5e1cf09b.md). The latter is evidence of repair to a transitional state, not a second independent design insight.

The key ownership improvement is [036 · 2d2d6952e8c1](../commits/036-2d2d6952e8c1.md): a map from reliable-message number to TimerHandle lets ACK processing find and cancel the actual outstanding timer. This is more specific than “manage timers carefully.” A queued resend, a scheduled retry callback and an already-acknowledged message are different states. Removing only a buffer entry does not necessarily cancel a callback that will reinsert or resend it.

[037 · 4bfd2b90f059](../commits/037-4bfd2b90f059.md) waits for pending ACK/reliable work before completing disconnect, with a timeout fallback. That is best-effort orderly teardown, not proof that every payload reaches the peer. If the other side disappears, bounded shutdown deliberately chooses eventual cleanup over indefinite delivery waiting. No comprehensive cancellation test was added with this exact ownership change.

## Receive, close and future races {#receive-close-and-future-races}

[038 · 69c84a027d77](../commits/038-69c84a027d77.md) introduces protocol exceptions with familiar standard-library connection/timeout ancestry. [039 · 5313db986108](../commits/039-5313db986108.md) races an application queue-get task against a shielded close future. If close wins, it cancels the queue task. That repairs one explicit race: a receive must terminate when the connection closes instead of waiting forever for another application packet. The shown change does not put child-task cleanup under a finally for every caller-cancellation path, so it should not be copied as a complete structured-concurrency pattern.

The async context manager [040 · a663e0c2bdf9](../commits/040-a663e0c2bdf9.md) helps normal use close the connection and transport. Presence of `async with` is not sufficient evidence that every independently owned TimerHandle is cancelled; inspect those owners and terminal paths. [041 · 5ff07cd708d1](../commits/041-5ff07cd708d1.md) introduces offline ping with a future and a finally-based socket close. [046 · 8c680b21421c](../commits/046-8c680b21421c.md) adds `done()` before `set_result()`, explicitly because duplicate responses can otherwise complete a future twice and raise InvalidStateError. Timeout, peer duplication and caller cancellation all compete to finish futures; idempotent completion is a narrow reusable lesson supported by the actual diff.

## Applicability and limits {#applicability-and-limits}

This phase is good evidence for iterative timer ownership, protocol-state repair, and differences between operation completion and resource disposal. It is weak evidence for server correctness, proxy forwarding, split reliability or proven interoperability: server [042 · 3587a7a3a59b](../commits/042-3587a7a3a59b.md) and proxy [045 · f486416fc6f2](../commits/045-f486416fc6f2.md) are unfinished, and the entire implementation is removed at [047 · 969d4d32bb56](../commits/047-969d4d32bb56.md). Tests were read as source and never run. Examples [010 · 569569007ef2](../commits/010-569569007ef2.md), [043 · 5a7500538207](../commits/043-5a7500538207.md), [044 · 137c3f6f1d55](../commits/044-137c3f6f1d55.md) establish intended access and naming, not measured behavior.

When applying the lesson elsewhere, enumerate the owner of each future, retry handle, queue-get task and transport. Write terminal transitions for success, timeout, duplicate packet, peer close and caller cancellation separately. That recommendation is a synthesis of the observed repairs and omissions, not an authored design manifesto.
