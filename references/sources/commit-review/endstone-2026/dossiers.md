### Packet data model and authentication boundary {#packet-data-model-and-authentication-boundary}

The v0.10 integration updates Bedrock 1.21.130 ABI and surrounding implementation, not merely symbol offsets. Available commands become a payload member plus serialization mode, and permission filtering is moved to `packet.payload.commands`/`constraints`. Text packets separate payload from packet and model bodies as `variant<MessageOnly, AuthorAndMessage, MessageAndParams>`. Factories select the right body: raw/tip, author+chat, or translated/popup+parameters. The writer now emits localization, variant index, variant-specific strings/type/body, sender IDs, and an explicit optional-filtered-message presence bit. It retains a TODO questioning the transmitted type-name strings; the source is evidence of uncertainty, not a validated wire-format specification. `_read` remains unimplemented. No packet round-trip or client interoperability test is added by this comparison.

Authentication moves out of the packet factory's LoginPacket dispatcher into `_validateLoginPacket`. The useful ordering is explicit: IP-ban check; absent connection request rejection; call original validation; stop if optional auth result is absent; only then derive authenticated identity and enforce name/UUID/XUID bans. The former dispatcher invoked original handling and then accessed request-owned authentication data. The new hook consumes the original's explicit success result before identity-dependent work. This is the observable trust boundary; it does not prove all upstream validation is sound. ConnectionRequest/SubClientConnectionRequest ABI removes stored verification/authentication fields and their getters now directly use raw token data, making correct call ordering and object validity prerequisites.

The certificate-chain size gate changes from three to ten. `Certificate::validate` adds a null-this rejection via `std::launder(this)` before forwarding. Linux adds `-fno-delete-null-pointer-checks` to the runtime target, an important compiler-assumption dependency. This is a defensive hook at a native boundary, not a portable guarantee that calling C++ methods on null objects becomes generally valid. No malicious packet execution or reproduction was performed.

### Data layout, proxy references, and lifecycle {#data-layout-proxy-references-and-lifecycle}

`BaseAttributeMap` changes from unordered_map to a Bedrock-compatible flat-map representation with separate key/value vectors. The adapter introduces zipped proxy iterators returning pairs of references; name lookup changes from reference to pointer, and loops use `auto [id, instance]`. Because the pair elements themselves are references, the returned `&instance` refers to stored data rather than a copied AttributeInstance. ID lookup uses `(*it).second`; find performs lower_bound and comparator-equivalence checking, assuming sorted keys and aligned value positions. Empty mapped storage supports the set specialization. This is a narrow ABI adapter, not demonstrated full STL-container conformance; no iterator law or container test appears in the port.

Skin types become SerializedSkinRef while preserving a 16-byte shared-owner representation. Block size assertions change (Windows/Linux 304/312), direct-data fields disappear, and virtual slots/signatures change across Item, Actor, Mob, ILevel, BlockType, network callbacks and shutdown. Attribute-map size assertion is removed instead of replaced. These details must be checked against the target binary; header compilation alone cannot validate slot ordering. A subsequent ILevel slot carries a TODO to check its name, explicitly preserving reverse-engineering uncertainty.

Minecraft shutdown now calls a stored move-only callback instead of an IMinecraftApp pointer; reload dispatches through ServerInstance. Resource-pack creation checks for the repository and points its exception at the missing hook. Devtools launch on a detached thread behind a build flag; lifecycle joining is not introduced. `b187b75e` supplies DedicatedServer through `entt::locator<DedicatedServer*>` after the old embedded app reference disappears. It emplaces the pointer specialization, but cleanup resets `locator<DedicatedServer>`, a distinct type. That source mismatch is recorded without claiming a reproduced shutdown failure.

Hook declaration, platform address and version metadata move separately: changeDimension is disabled, the next symbol table gives Linux an address but Windows zero, then a later commit supplies the Windows address and restores ENDSTONE_HOOK. A stale enable-hook TODO remains. The protocol changes 859→898; runtime/stub Minecraft versions are aligned to 1.21.132. Numeric offsets are retained as provenance, not reusable constants for other versions. Log suppression expands from database info to system/content info, trading diagnostic volume against losing low-priority context.

Sources: [4f8d3b85 / PR324](https://github.com/EndstoneMC/endstone/commit/4f8d3b85cf7a94df21acf3addc34123dfde16af2), [72ce6920](https://github.com/EndstoneMC/endstone/commit/72ce69200c50deacc486f418f318335a96c2c946), [889e7929](https://github.com/EndstoneMC/endstone/commit/889e7929595ad5eca180fc62d73ce4f5bd2f1525), [db179649](https://github.com/EndstoneMC/endstone/commit/db1796490452f734bd1cb1e676845bf2c85b9b08). The squash explicitly credits killcerr; that source attribution is retained.

The hook shape is `if (canSpread && !isInstaticking) { callEvent(source,target); if (cancelled) return; } original(...)`. Source and destination wrappers are owned by the cancellable event. To avoid emitting a cancellable event for impossible native operations, the implementation reconstructs liquid eligibility: below min height/no block fails; existing same material or lava fails; then the destination/source directional blocking rules are tested. Importantly, when no event is emitted, the original routine still runs; the helper gates interception rather than replacing the entire simulation.

The initial squash gets several details wrong, and the evolution is necessary knowledge:

1. `_canSpreadTo` initially returns `_isLiquidBlocking`, so event eligibility is inverted. `72ce6920` adds the negation.
2. The lava branch initially asks whether the liquid source blocks lava; the same follow-up changes it to the destination block.
3. Defaulted Material equality becomes type equality, then `889e7929` changes it again to address identity. Distinct objects with the same type cease being equal; this assumes canonical material objects. `isType(Lava)` deliberately remains a type test.
4. The destination directional check initially passes `flow_from_pos`; `db179649` supplies destination `pos`. The source is separately tested using the opposite face and source position.

These are behavior-preservation fixes hidden among refactor titles. Counterexamples worth testing are unobstructed water, blocked destinations, lava into a different material, directional/waterlogged shapes, minimum height, unloaded positions, instatick calls, same-type distinct material objects and cancelled vs allowed propagation. The patches add no such tests. Native vtable fixes nearby are prerequisites for calling block-type queries reliably.

BlockGrowEvent and BlockFormEvent public headers are added, but this diff wires only liquid BlockFromToEvent. Header documentation mentions dragon eggs and other formation cases without adding their dispatch. Python bindings also do not appear here. A class declaration or umbrella include is not evidence an event can fire in every documented scenario.

## Async runner: useful behavior checks versus timing/lifecycle guarantees {#async-runtime}

Sources: [6bc11c12](https://github.com/EndstoneMC/endstone/commit/6bc11c12029780ec241d2cc1180633ca30d78a60), [dcb9d994](https://github.com/EndstoneMC/endstone/commit/dcb9d99467fd8839c3d2086b4029a2bd1c57d552). The complete existing `endstone/asyncio/__init__.py` was also read at the latter revision.

The runner is a lazily created daemon-thread loop, protected by global and per-runner reentrant locks, with `run_coroutine_threadsafe` producing concurrent futures. Tests verify a shared running loop, worker-thread identity distinct from the calling thread, actual side effects/results, nested awaits, exception propagation, rejection of non-coroutines and multi-thread submissions. Five-second future waits and ten-second thread joins are finite, but joined-thread liveness is not directly asserted and there is no cleanup/shutdown exercise. Tests first initialize the singleton before the multi-thread cases, so they do not force simultaneous first creation.

The implementation sets its startup event immediately before `run_forever`. Waiting for that event does not itself guarantee `is_running()` is already true; the immediate running-state assertion has a small readiness race. The shutdown method cancels tasks, gathers them, shuts down async generators/executor, stops and joins the loop; no new test checks these paths, self-thread shutdown, cancellation-resistant tasks or closed-runner reuse. Its cleanup future wait has no timeout even when thread join accepts one. These are observed untested boundaries, not reproduced failures.

The initial concurrency test submits sleeps of0.2,0.1,0.05 seconds and expects completion order3,2,1. The next commit adds a monotonic total below0.3 seconds: meaningful against a serial0.35-second implementation, but sensitive to scheduling/load with only about0.1-second margin. It is a coarse concurrency regression test, not a benchmark. README's scheduler-integration claim exceeds the added tests: they never call the Endstone scheduler.

Thread-local storage avoids cross-thread sharing, but not recursion: a nested explosion overwrites then clears the outer position; exceptions bypass reset entirely. A saved prior value with scope restoration would address those boundaries, but is not present here. The Python getter returns pointers into owned block wrappers; setter clears the owned vector before cloning the supplied pointers. Passing the getter's own blocks back can therefore invalidate inputs before cloning. This risk follows from code order and is not a reproduced runtime result. Per-block wrapper allocation and cloning are proportional to affected blocks. No tests establish cancellation, nested explosions, source position, edited lists, self-assignment or Python lifetimes.

## Scheduler clock and locks {#scheduler-clock-and-locks}

Sources191:62f8d63c/#351 and192:43fe66de/#317. Full diffs/messages and surrounding scheduler/async/test code read.

The cancellation bug is a concrete lock graph: cancelTask/cancelTasks held tasks_mtx, called async doCancel, and an idle task called removeTask which reacquired tasks_mtx. A worker held its own mutex while removing itself, giving the complementary scheduler/task ABBA order. The fix snapshots shared_ptr targets under scheduler lock, erases synchronous targets there, then cancels after unlocking. Async run/doCancel computes finished/idle under task mutex and calls scheduler removal only after releasing it. Querying workers similarly occurs after releasing scheduler lock. Last-worker cleanup now includes cancelled repeating tasks. The shared ownership keeps selected task objects alive across the lock boundary, at the cost of a temporary vector and a snapshot rather than atomic batch cancellation.

The new tests construct an enabled mock plugin/scheduler, schedule idle async tasks without ever driving a heartbeat, cancel individually or in bulk, and assert they are no longer queued. Merely reaching the assertions is significant against the old recursive mutex deadlock/exception. The tests have no active worker, barrier or concurrency schedule, so they do not exercise the ABBA interleaving, cancellation during callback execution, plugin unloading or last-worker cleanup.192 unexpectedly deletes the single-task regression while preserving the bulk test; no removal rationale is provided.

The delay bug comes from mixing a session-local initial0 with a world's persisted large tick.192 anchors the first incoming tick and uses `incoming - base + 1`. A delay5 task then fires on the fifth heartbeat even if the world's first tick is5,000,000. The new assertion sequence proves both non-early execution and the exact boundary; an immediate boolean-only final assertion would have missed the original defect. The correction assumes a monotonic incoming counter; reset/wrap and scheduler recreation are not covered.

These changes do not certify the entire scheduler. The surrounding async isRunning branch still returns workers.empty(), which is inverted relative to its name. The enclosing heartbeat submits a closure capturing a queue element by reference, then erases that queue; a deferred worker can outlive the referenced shared_ptr element. These are unchanged context limitations, separate from the verified lock/clock fixes. No tests ran in this review.

## Formatting and compile cost {#formatting-and-compile-cost}

The change series separates dependency removal, compile-time work, editor integration and later portability fallout.

### Public and internal formatting migration {#public-and-internal-formatting-migration}

201 changes public `fmt::format_string`, formatters, preconditions, logger/send/broadcast overloads and Python string representations to the C++ standard facilities. It removes fmt from the CMake interface and Conan transitive requirements. This preserves a header-only public API but changes the compilation contract for every plugin: docs raise LLVM to 18, and plugin-defined fmt formatters are no longer the customization the public logger consults. Internal fmt remains temporarily via spdlog, then 202 selects spdlog's standard-format option and removes the remaining dependency. Dependency updates are broader than this migration: ImGui/gtest in 201, then Boost, EnTT, expected-lite, GLM, GSL, Sentry and spdlog in 202. Neither patch adds new regression assertions, so these are not experimentally established drop-in replacements.

Two replacement helpers illustrate the cost and limits. `quoted(string_view)` allocates a string and escapes quote, backslash, newline, tab and carriage return. Its comment claims debug-format equivalence, but other control characters pass through unchanged; the claim is broader than the implementation. `join` borrows iterators and a separator view, allocating no own buffer. Its formatter uses `{}` for each element and does not apply inherited parsed string presentation state. Therefore it is appropriate for the immediate empty-spec call sites in this patch, not a general substitute for every fmt join specifier or a safely stored view of temporary data. The NBT byte-array formatter still dereferences `begin()` unconditionally; this is a retained pre-existing empty-array boundary, not created by replacing the format library.

Internal adaptations are semantic details worth retaining: filesystem paths become `.string()`, thread IDs go through an output stream, and an optional caught exception is logged via `what()` instead of formatting the optional wrapper. Chat uses `vformat` with named local name/content variables, keeping argument references alive during the call and preserving the surrounding invalid-format catch. Rotated filenames switch from a two-argument fmt chrono pattern to `%Y-%m-%d-{}.log.gz`: first substitute the index, then format a `date::local_days` built from local calendar fields. This supports the project's date-only pattern but is a different grammar and loses sub-day fields if an external custom pattern expected them. Crash/rotation diagnostics now emit literal ANSI color sequences through `cout`; they are no longer mediated by fmt's color helper.

## Post-port correctness and tests {#post-port-correctness-and-tests}

These revisions expose gaps that a successful symbol scan and nominal version update did not catch.

**Map data and decorations (211).** The earlier packet patch returned when either pixels or decorations were absent. A custom pixel-only map therefore never invoked its renderer. The new skip condition requires *both* to be empty. Rendering happens for texture-only and decoration-only updates; bounds checks and pixel copying apply only to a nonempty texture update. The remaining implementation clears old decorations and emits visible renderer cursors, preserving direction, caption and a fixed white color. It still skips entirely empty creation packets. A newly observable ordering is that plugin rendering now runs before an invalid pixel rectangle is rejected; bounds rejection also leaves original decorations untouched. Width/height coordinates are bounded, but the vector length is still trusted rather than checked against width×height. No new map regression test is present.

**Crash-handler packaging, also in 211.** The title only mentions maps, but the same patch fixes another lifecycle issue. Bootstrap copying of `crashpad_handler`/Windows support files into the server directory and Linux chmod are removed. Native startup instead computes the handler alongside the loaded runtime library and passes that explicit path to Sentry. The source explains that moving the executable had broken its relative search for vendored libc++. The mechanism is relocation-aware dependency lookup, not merely copying a newer binary. No wheel-install/handler-start assertion is added, and executable permissions must now be supplied correctly by packaging.

**Enum drift (212).** Inserting PLAYER_WAYPOINTS at 17 shifts all later game-rule indices. SHOW_DEATH_MESSAGES moves 27→28; the old numeric slot now denotes immediate respawn. Thus a compile-successful native accessor can read a perfectly valid but wrong boolean and silently suppress chat. Packet ID, Molang and block-actor enums are also refreshed. These numbers are semantically meaningful ABI constants, not noise. 218 changes target BDS to 26.33 with protocol1001 and unchanged offsets; a fresh successful signature resolution is author-reported and does not by itself validate all enum meanings or game behavior.

**Console input (214).** Replxx's LF/Ctrl-J mapping becomes `commit_line`, allowing web-panel input to submit instead of accumulating multiline text. Linux also gains the interactive default, with `--no-interactive` documented for incompatible process managers. Non-TTY fallback is asserted in the commit message but not exercised here. No PTY, panel, CR/LF, or piped-input regression test accompanies the change.

**Parallel test isolation (220).** Full fixture context shows why the changes are meaningful. Ban tests save/read actual JSON, assert optional UUID/XUID omission versus presence, distinguish forever expiration, compare creation timestamps normalized from +02:00 to UTC, and check absent-file behavior. A shared filename lets separately discovered CTest cases overwrite or remove another case's evidence. Deriving `test_banned_players_<test-name>.json` isolates these cases while retaining the existing assertions; teardown removes each case's own path. It does not isolate two concurrent runs of the same test in one directory and does not sanitize arbitrary parameterized names.

The plugin loader constructor uses the common `plugins/.local` path and removes matching old library files before loading. Three tests verify missing-file failure, actual fixture-library load and directory metadata, plus platform filename filters. The patch discovers this group separately and assigns a CTest RESOURCE_LOCK, preserving parallelism for the remainder instead of serializing everything. The lock protects CTest scheduling inside that invocation; it neither proves the production loader thread-safe nor coordinates independent test processes started outside CTest. No 28-way run was performed in this research.

## Scheduler lifetime followthrough {#scheduler-lifetime-followthrough}

222 (`83f23187`) closes the earlier heartbeat use-after-free risk by submitting `[task]`, retaining the shared task, instead of `[&task]`, a reference into a queue entry erased after dispatch. This repair adds no test itself. The intervening collaborator commit `812032ee27a638023fe6e13b25796712c5f33774` (#436), authored by ReallocAll with Vincent co-author trailer, supplies related async-task and executor changes. The later lifecycle state must preserve ReallocAll's contribution rather than attribute all inherited changes to target commit230.

The collaborator patch fixes async `isRunning` from empty→nonempty worker list; publishes the current tick at heartbeat *start*, so a callback scheduling delay2 sees the current tick rather than the previous one; initializes owner-less task pointers to null; registers a task in the map before publishing it into the concurrent pending queue. Cancellation is an atomic release-store; worker admission checks it while holding the worker mutex, so cancellation can distinguish an admitted worker from an idle task. Scheduler-map and worker mutexes are never held together. The main thread removes cancelled pending/scheduled entries after consuming an acquire flag, promptly releasing callbacks instead of waiting until their scheduled tick. Repeating tasks cancelled during execution are not rescheduled. Internal tasks remain distinct from plugin-owned tasks.

The assertions are meaningful and broader than successful submission: a dropped external task handle must still execute asynchronously; a callback-created delay2 runs on the third heartbeat, not the second; a weak sentinel stays alive immediately after cancellation but expires on the next heartbeat while an uncancelled peer remains and runs; owner-less internal tasks survive plugin bulk cancellation. Promise barriers hold async work in flight while checking `isRunning`, then verify it clears. Timeout paths release barriers and reset the scheduler before stack captures disappear. Executor(0) must complete a future with1, verifying the minimum-worker clamp. These tests use mock server/plugin, real worker threads and explicit heartbeat calls, without a live BDS. No tests ran here, and cancellation timing, concurrent publication and actual reload unloading are not exhaustively tested.

Reload disables plugins, polls active workers up to50×50ms, logs plugin/author names for survivors, removes cancelled scheduler-queue entries, then clears and reloads plugins. This is a bounded grace period, **not a proof that executing plugin code has stopped before unload**. Executor-owned queued closures are separate from the two scheduler queues and are not drained by this reload method; cancelled tasks can still retain callback objects there. Executor destruction does join workers and drain its queue, but that is a different lifecycle. Non-`std::exception` exits skip worker cleanup; the enclosing packaged_task captures the exception in a future that the heartbeat discards. The commit narrative's “let it propagate” does not mean it reaches a caller or preserves worker bookkeeping. Enqueue's boolean result is also ignored. These source-level limits should remain alongside the happy-path assertions.

## ACKNAK guard reversal {#acknak-guard-reversal}

Sources230,233–236 demonstrate why security changes must be followed through later revisions.230 initially reparses ACK/NAK datagrams before native handling, assuming the BDS sliding-window header, and rejects an individual acknowledgement span larger than the resend buffer. Malformed parser reads return “not oversized” and pass through rather than constituting complete input validation.234 adds a total inclusive-span bound and rejects the24-bit maximum to prevent wrap/splitting bypasses. Its comment that inverted ranges always underflow beyond the bound is imprecise: min=max+1 contributes zero modulo unsigned arithmetic. Native range validation is a separate protection. No packets were generated or sent, and no regression packet fixtures were added.

235 then retracts the server security release note and removes the hook parser: its message reports that shipped BDS already limits range count, total acknowledgements and maximum wrap on both ACK/NAK. The owned vanilla/Mojang RakNet recipes receive the actual patch instead: no more than0x400 ranges, cumulative0x4000 acknowledgements, explicit min<=max checks and a NAK maximum-value rejection matching the existing ACK protection. The check sits before each costly range walk; prior accepted ranges may have been processed before a later range rejects the datagram, so it is not an all-or-nothing transaction. Work/memory during range-list deserialization precedes these checks. BDS's existing binary protection is a source-reported reason, not independently reverse-engineered or executed in this review.

The remaining incoming hook only supplies ServerListPingEvent. This bounds historical claims: do not cite230's abandoned release note as evidence that current BDS was vulnerable or that the final hook still blocks ACK/NAK.233 separately makes the Mojang vtable overlay optional by default; explicit version selection remains necessary when consuming native BDS objects, while the plain recipe removes that option. ## Compression peer splicing and buffer lifetime {#compression-peer-splicing-and-buffer-lifetime}

401 ports the develop compression work into release history, using libdeflate1.25 and Snappy1.2.1 through Conan/CMake. The replacement derives from the modeled native CompressedNetworkPeer so native code can still write compression flags/settings through the connection's typed weak pointer. On a successful original incoming-connection call it chooses connections_.back(), explicitly avoiding an ID lookup that could find a closing connection with the same identifier. It locates the old compression peer in the chain, constructs a replacement with copied settings/flags/max size, reconnects the chain and updates the weak pointer. Unexpected chain shape logs and leaves native behavior. This assumes the native callback appended the intended connection and no intervening callback changed the list. The Windows byte signature is lengthened because the old prologue matched an unrelated function; message provides the rationale, not a binary validation run by this review.

Codec state is allocated lazily per connection and freed with typed deleters. Level6 compresses, level0 writes a stored raw-deflate stream; wire format remains raw deflate rather than a zlib wrapper. Compression threshold0 suppresses ordinary compression. Hybrid mode adds one byte indicating algorithm or0xff for raw, and if a compressed body does not shrink it sends raw instead, matching the stated newer BDS rule. Allocation/compression failure silently drops outgoing data. Receive rejects empty compressed input, header/negotiated-algorithm mismatch and unsupported algorithms.
