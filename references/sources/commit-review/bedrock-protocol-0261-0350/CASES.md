# Packet evolution: mechanisms, counterexamples and use boundaries {#packet-evolution-mechanisms-counterexamples-and-use-boundaries}

This analysis covers 90 GitHub-attributed commits in EndstoneMC/bedrock-protocol, indices 261–350, authored 25–26 August 2026. It is a historical slice, not the current API reference. The bundled [DOSSIERS.md](DOSSIERS.md) retains each reviewed SHA. Public provenance links accompany these explanations.

## 1. A binding's spelling is not necessarily its transmitted name {#1-a-binding-s-spelling-is-not-necessarily-its-transmitted-name}

**Chain:** [265](DOSSIERS.md#commit-265), [267](DOSSIERS.md#commit-267), [269](DOSSIERS.md#commit-269), [270](DOSSIERS.md#commit-270), [342](DOSSIERS.md#commit-342).

The initial CommandRequest and CommandOutput implementations pair PEP-8 enum identifiers with BDS spellings such as `AutomationPlayer` and `DataSet`. That is necessary to preserve separators: `AUTOMATION_PLAYER` cannot become `automationplayer` through lowercasing alone. However, their original tests also change independently generated lowercase bytes to the binding's mixed-case spelling, supported by the then-stated belief that the receiver lowercases before lookup. This is an example of a plausible interpretation corrupting an otherwise useful external fixture.

Commit 269 explicitly reverses the interpretation. Its reported binary trace distinguishes the bound original `mNameExt` from lowercased `mName`; the latter is passed to serialization and used for lookup IDs. The source changes are unambiguous: `EnumValue.wire_name` lowercases the explicit spelling or identifier; every reflected name table, including numeric enums, is lowercase. The C++ API therefore changes too: `enum_name` is lowercase and `enum_cast` automatically folds input. The explicit case-insensitive predicate and arbitrary-comparator overloads disappear, along with the second lowercase index. The runtime path borrows a string view when input is already lowercase and constructs a temporary lowered string otherwise; constant evaluation uses a folded linear comparison. These are static code observations, not measured allocation or speed results.

The implementation is deliberately more permissive on read than the reported BDS lookup: it accepts mixed-case binding spellings. The CommandOutput alternate fixture is accordingly renamed from “BDS casing” to “binding casing,” and its bytes are changed in the reverse direction to preserve that permissive-read test. Do not teach that BDS itself accepts every mixed-case input.

Static verification inspected 26 `const std::string = bytes(...)` arrays in the affected C++ files: 17 change only uppercase ASCII to lowercase, one changes lowercase to uppercase for the alternate read fixture, and eight are unchanged. All lengths remain equal; 106 byte positions change. This count is distinct from the message's historical report that 26 goldens had previously been recased. The complete per-array differences and hashes are in structural-verification.json. No reference codec, compiler or BDS binary was executed here.

**Use:** when a decoder agrees with local round-trip tests but disagrees with peers, trace the actual serialized member and transformation. Keep original reference bytes intact until a discrepancy has an identified mechanism. Record changed interpretation as a reversal, not a timeless trait. Later enum/TextPacket history belongs to the core review; this slice alone does not settle every later literal-binding issue.

## 2. A shared in-memory type can have different wire encodings at different call sites {#2-a-shared-in-memory-type-can-have-different-wire-encodings-at-different-call-sites}

**Examples:** [275](DOSSIERS.md#commit-275), [280](DOSSIERS.md#commit-280), [289](DOSSIERS.md#commit-289), [321](DOSSIERS.md#commit-321), [336](DOSSIERS.md#commit-336), [337](DOSSIERS.md#commit-337), [348](DOSSIERS.md#commit-348), [349–350](DOSSIERS.md#commit-349).

The DSL keeps the annotation's in-memory type while allowing `field(type=...)` to change the wire primitive. In the examined context, integer enums default to their underlying width compressed as a varint above one byte; ordinary fixed integer fields do not. The same apparent integer width consequently does not establish the same serialization.

UpdateBlockSynced writes byte-sized flags through uvarint32 and a signed ActorUniqueID alias through uvarint64. Its MessageId override is uvarint64, while UpdateSubChunkBlocks uses the same enum's default uvarint32. The fixture values NONE/DESTROY cannot distinguish those two widths, so the difference is a schema observation, not a demonstrated boundary test. Lectern page counters retain int32 storage but write uint8. RequestAbility overrides signed-byte AbilitiesIndex to signed varint32. NpcDialogue writes its actor ID as eight fixed unsigned bytes. CameraInstruction uses the same EasingType as a byte for SetInstruction but as a name-coded string for FOV and spline keyframes.

NetworkSettings illustrates why messages alone are insufficient: its message says the algorithm's enum would otherwise be a byte, while the actual enum is uint16. With the documented default-compression rule, its field override is needed to pin fixed uint16 rather than uvarint32. Similarly, AnimateEntity's initial message says the header's enum and dump's int32 compress to the same varint; the patch and both goldens instead use fixed int32. Commit 350 reports inspection of the BDS binding and resolves the uncertainty without changing the already-correct wire representation.

**Use:** separate domain identity, native memory representation and serialized representation. Test values crossing the relevant boundary: -1 distinguishes zigzag from a signed byte; 127/128 distinguishes byte/count prefixes; 2^32 distinguishes narrowed IDs; negative fixed-width values distinguish compression. Do not unify aliases merely because their small positive examples match.

## 3. Presence is a representation choice, not a semantic guess {#3-presence-is-a-representation-choice-not-a-semantic-guess}

**Chain/examples:** [271](DOSSIERS.md#commit-271), [281](DOSSIERS.md#commit-281), [286–287](DOSSIERS.md#commit-286), [321](DOSSIERS.md#commit-321), [323](DOSSIERS.md#commit-323), [328](DOSSIERS.md#commit-328), [334](DOSSIERS.md#commit-334), [343](DOSSIERS.md#commit-343), [345](DOSSIERS.md#commit-345).

EducationSettings preserves an outer optional AgentCapabilities struct whose own bool is optional. The populated golden is patched to add a marker omitted by gophertunnel; a separate test gives the outer struct present with its bool absent, proving the model has three distinguishable states instead of a flattened optional bool. Its deprecated field is a constant false byte and changing that byte to true is an explicit rejection test.

StructureTemplateDataResponse supplies a different failure mode: the reported native member is `shared_ptr<CompoundTag>`, while the dumper only recognizes `optional`. The dump therefore misses a real presence marker. The DSL models the tag as optional and has populated, absent and present-empty compound fixtures. This is a concrete counterexample to treating an omitted “optional” annotation as evidence of mandatory wire presence.

CameraInstruction's nine members are independent optionals, not a one-of union. Its empty body is nine marker bytes, and a present false boolean is not absence. CameraSpline's optional easing names differ from CameraInstruction's embedded spline keyframes; similarly named types should not be merged without comparing wire layout. Clientbound close-screen has an optional form ID, while serverbound screen-closed has a mandatory one. The latter's external golden is explicitly patched and remains marked for BDS confirmation.

Several summaries overstate semantic exclusivity. ModalFormResponse says exactly one of JSON and cancel reason is present, but its own test sets both present-empty JSON and cancel reason. DebugRenderer says marker data rides only on add, but its tests deliberately encode CLEAR with marker data present. The serialization evidence supports independent presence markers, not those summary claims.

**Use:** distinguish absent, present empty, present false, tagged empty case and predicate-gated omission. A field's business meaning cannot replace reading the serializer. The tests demonstrate representation; they do not establish which combinations the real client accepts as meaningful.

## 4. Tagged variants, repeated bindings and unconditional value slots {#4-tagged-variants-repeated-bindings-and-unconditional-value-slots}

**Examples:** [263](DOSSIERS.md#commit-263), [266](DOSSIERS.md#commit-266), [325](DOSSIERS.md#commit-325), [336](DOSSIERS.md#commit-336), [338–340](DOSSIERS.md#commit-338).

LegacyTelemetry separates its event type from a 22-case variant index. Several event types share the payload-free last case; matching the event type directly to the payload index would be wrong. BookEdit keeps ReplacePage and AddPage as different cases even though their payload bytes are identical after the case index. SyncWorldClocks uses a four-case union and tests each case, while only the empty SyncState list is exercised.

PlayerVideoCapture is the strongest warning against simplifying an odd shape. Its schema declares two independent Start|Stop variant fields. A TODO reports that the same native member was bound twice, so the wire carries two indices. Tests exercise Start/Stop, Stop/Stop and Stop/Start rather than silently collapsing the model to one action. That interpretation is still awaiting BDS confirmation, so it is retained as a provisional binding reconstruction rather than an independently verified fact.

Conversely, RequestAbility and ChangeMobProperty always write all value slots even though a separate type determines which is used. Replacing these with a compact variant would change the wire. LabTable reset, TextureShift SET_ENABLED and NPC dialogue close similarly retain fields whose operation might not use them.

**Use:** recognize when repetition or apparently unused fields are protocol obligations. Tagged unions, independent optionals and unconditional fields solve different representation problems. Avoid “cleanups” based only on semantic intent.

## 5. Test provenance and incomplete oracles {#5-test-provenance-and-incomplete-oracles}

**Read helper context:** tests/fixture.hpp, lines 16–63 at commit 350.

`encode` serializes a body. `decode` requires success and zero unread bytes. `decode_partial` explicitly requires success with bytes left over; it is a desynchronization demonstration, not ordinary acceptance. `rejects` requires deserialization failure, not merely trailing bytes. Telemetry's stale fixed-int16 POI item ID partially decodes as 22 rather than 300, making a wrong interpretation visible. Truncated BookEdit, chunk lists, UUIDs, armor pairs and optional IDs probe incomplete frames.

The repeated test pattern is substantive but not 86 independent engineering preferences: a new packet model receives an external-origin golden, explicit packet-id/snapshot assertions and one or more boundary or empty-state cases. References are usually gophertunnel; the casing correction also edits CloudburstMC-derived fixtures. Test provenance comments are claims about where the bytes were generated. This review inspected those bytes and tests but did not regenerate them or run any codec.

Important unresolved/adapted fixtures are called out individually:

- Telemetry POI cauldron item ID (263): fixed int16 versus varint32, awaiting BDS confirmation.
- EducationSettings (286): added outer optional marker, with author-reported writer evidence.
- CameraInstruction spline (321): three reference optional markers removed, awaiting confirmation.
- CameraSpline (323): spline-type marker removed and easing markers added, awaiting confirmation.
- DebugRenderer (334): primitive reference writer follows the proposed dump layout rather than its own packet serializer; all three fixtures patched.
- VideoCapture (338): old action reindexed and second variant index added, awaiting confirmation.
- Party destination cookie (342): reference enum strings lowercased using the preceding casing analysis.
- ScreenClosed (343): optional form-ID marker removed, awaiting confirmation.

A patched external fixture checks the chosen model's implementation, but is weaker as an independent oracle for the chosen model itself. Header/dump agreement is useful evidence, not a substitute for missing BDS confirmation. The per-SHA dossiers preserve that distinction.

Commit 270 is a documentation refinement after the casing reversal. It removes derivable narrative and statements of agreement, retaining source/packet identity and exceptions such as altered goldens. All seven files are identical after comment/blank removal. That supports a local rule about durable fixture comments, not a universal preference for less documentation.

## 6. Reuse and dependency structure without a wire change {#6-reuse-and-dependency-structure-without-a-wire-change}

**Examples:** [268](DOSSIERS.md#commit-268), [300](DOSSIERS.md#commit-300), [308](DOSSIERS.md#commit-308), [310–312](DOSSIERS.md#commit-310), [346](DOSSIERS.md#commit-346), [350](DOSSIERS.md#commit-350).

Wrappers and nesting often mirror the documented native declaration: AutomationClientConnect retains WebSocketPacketData, FeatureRegistry retains its nested entry type, and AdventureSettings remains a struct. Other packets deliberately reuse existing types, including FullContainerName, Scheme, EduSharedUriResource, ClientStoreEntryPointConfiguration and SerializedAbilitiesData. The latter's commit message incorrectly names StartGame as the prior user; the inspected call sites are AddPlayer's two era declarations. This does not invalidate reuse, but the caller attribution must be corrected.

MolangVersion's original location followed its first use in item_stack. Commit 350 moves it to dependency-light molang because importing item_stack from actor would return through inventory to actor. Static verification proves the moved 16-member class is text- and AST-identical and the item-stack fixed-int16 call site is unchanged. The actor field remains plain fixed int32. No compiler output was generated to prove byte-for-byte output identity; the narrower verified result is a source-level move preserving the declaration and call-site override.

**Use:** keep domain types reusable without importing their first consumer. Preserve a caller's encoding override when moving the declaration. Do not equate a shared name with a single wire layout or claim a refactor's runtime equivalence from declaration equality alone.

## 7. Versioning and attribution boundaries {#7-versioning-and-attribution-boundaries}

The 86 packet-addition commits in this slice initially mark their modeled shapes `since=2168` and assert availability at 2168 but not 1001. That is evidence of model coverage at that point in the project, not proof that the packet was first introduced in the game at 2168. Later backports and renames are reviewed elsewhere. Chronological indices are author-time ordering; actual parent relationships are preserved because several adjacent commits appear in reversed dependency order.
