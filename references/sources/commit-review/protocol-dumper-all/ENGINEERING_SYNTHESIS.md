# Protocol-dumper: evidence, reversals, and usable engineering lessons {#protocol-dumper-evidence-reversals-and-usable-engineering-lessons}

## Scope and reading contract {#scope-and-reading-contract}

This dossier covers exactly 117 GitHub-attributed wu-vincent commits in EndstoneMC/protocol-dumper, from 2026-04-11 through 2026-10-13. The assignment is one linear causal chain from root 709fd86175fb to 074925d133f4. No merge or missing intermediate parent is hidden. Every message and every meaningful added/deleted patch line was examined; repeated unchanged context was reconstructed from the preceding reviewed state, and ten final files (1,819 lines) were independently read in full. The guarded extractor withheld three credential-like patch lines and one repeated final-workflow line. Their contents were not reconstructed. The extraction hashes and guarded files are not bundled, so the withholding cannot be independently audited from this Skill alone.

The bundled per-SHA dossiers contain the concrete change, reason/uncertainty, causal neighbors and public commit links. Those links lead to the original patches and messages; the guarded extraction files are not bundled. This synthesis is a cross-commit interpretation, not a replacement for those records. No upstream program, build, test, injection, remote workflow or publication was run. Claims that a binary was disassembled, a dump succeeded, output matched another implementation or N files changed belong to the commit author unless expressly called a static observation here. The selected repository contains producer source and configuration, not the published generated schema trees. Reported output totals cannot be independently recounted from this assignment.

GitHub links are provenance; all core analysis is local. A reference such as commit 089 resolves to its [numbered dossier](dossiers/089-11a6c467d63a.md) and linked full public source SHA. This bounded selection is not all Internet evidence, all branches, or proof of a timeless personal preference. Contemporary messages mention other codecs including Nukkit; no excluded 2015–2017 Nukkit chain was reopened or used for completion credit.

## 1. Find the real serialization boundary before choosing a representation {#1-find-the-real-serialization-boundary-before-choosing-a-representation}

The root was a Windows-injected cereal reflection dumper emitting protobuf definitions. Fixed RVAs were unset, so the initial source cannot establish a working extraction. Early documentation explains that Mojang's cereal is its own EnTT-backed library, not the similarly named public library. The first major representational correction is 017 (8a4240c6381d): protobuf declarations imply protobuf wire rules that do not describe Bedrock's fixed widths, endian choices, compressed integers and enums-as-strings. JSON becomes an intermediate schema for downstream code generation. This is an explicit reason, stronger evidence than simply observing a file extension change.

The first implementation also read members through a name-sorted map. The correction orders by serialization ordinal, since alphabetic names would silently reorder bytes. Later direct EnTT traversal replaces the intermediate SchemaDescription and relies on reflection enumeration rather than the old map. Preserve both the ordering problem and the later architectural change; do not recommend the obsolete ordinal API unconditionally.

Commit 024 (c4638f4f46f4) separates validation-required metadata from binary optionality. The earlier generator treated strings/vectors as optional because cereal's required flag was unset; the fix examines std::optional instead. Commit 025 fills missing object schema names from declared reflection types only where the schema omitted a name. The useful general distinction is between declaration identity, validation metadata and wire representation. None is a substitute for the others.

The same distinction recurs at greater depth:

- 087 (7402cc268c7d): a serialize-as type can have a getter for the binary write representation, a matching default setter and a text-only alternate setter. Choosing the overload-chain head emitted a color as a string instead of four int32s. The fix prioritizes the getter and default setter while walking overloads. The implementation still falls back to any setter if neither preferred form exists, so it does not prove all alternate-reader ambiguity is eliminated.
- 088 (7fa43d6b5058): a conditional member can expose a closure signature in data.type(), with its true payload reachable through DynamicSetterArgCtor. A type-looking reflection result is not necessarily a payload type. Version 1.26.50.25 later removes this thunk entirely, requiring the gated reversal in 098.
- 106 (a02bd7bbcd19): fixed byte arrays changed from fixed-count element serialization to blob serialization with a uvarint32 length. Reflected names/types/descriptors reportedly did not change. The producer therefore adds an explicit version gate rather than claiming reflection is sufficient. A nested 16-by-16 byte heightmap keeps a fixed outer dimension and gains a prefix per row: 256 to 272 bytes in the author's account.

These are useful producer/consumer boundary cases: a complete reflection walk is not a wire correctness proof. Use serializer behavior and version-specific observations to validate interpretation, and retain uncertainty when only registration metadata is visible.

## 2. Recursive models must preserve scope and dimensions {#2-recursive-models-must-preserve-scope-and-dimensions}

The model changes repeatedly: polymorphic nodes with toJson (023), value-returning structs and variants (032), virtual writer scopes (038–039), then a substantial direct-EnTT/ADL JSON rewrite (040 onward). Commit 040 deletes Visitor files still referenced by the project. Several following commits leave field resolution commented, empty, or stubbed before filling it. These are intermediate snapshots, not a sequence of independently verified working releases. They cannot support an inference that every commit builds, or that the author has one fixed preference for polymorphism versus variants.

The final model uses TypeRef for names/types/enums/alias references, recursive TypeSpec for arrays/maps/variants/enums, and distinct field variants carrying common metadata. Field-level optional/pointer wrappers are peeled before container dispatch. Container introspection constructs a reflected instance; missing default construction or missing element/key information throws. Nested optional remains explicitly unsupported. The size heuristic identifies nonempty default construction as fixed extent and zero as dynamic; a zero-sized fixed array is an untested edge case, not a claimed supported feature.

Commits 049/051 enable nested arrays, maps and variants, but variant alternatives initially bypass traits-aware resolution. Commit 094 fixes this by sending member, element, key, value and alternative positions through buildTypeSpec. An enum overlay belongs beside the wire type rather than replacing it. A variant case can itself be a container or variant, rather than only a name.

That refactor immediately creates a regression: generic object splicing flattens an inner array's {type, repeat}, after which the parent overwrites repeat. Commit 095 (b80de45fd42d) narrows splicing to enums only. The concrete counterexamples are ItemEnchants' outer fixed three with variable inner arrays and SubChunk's 16-by-16 maps. Modifier names matching at two levels is not permission to merge their scopes. This is a strong behavior-preservation lesson because the same simplifying abstraction both solves nested enum labels and destroys nested dimensions.

Repeat's external schema changes from a scalar to count/prefix object (051), then back to scalar (107). The latter explicitly acknowledges a breaking consumer change; it reports 175 wrappers transformed and no other output changes. That report is preserved but not reproduced here. It is not evidence that wrappers are always bad. The relevant constraints are information redundancy, nesting readability, existing consumer contracts and a bounded delta check.

Final source limitations observed in context: MapSpec/MapField have key/value but no explicit length-prefix member, unlike ArraySpec; description is serializable but buildField does not fill FieldBase::description; floating types fall through type naming rather than the integer trait helper. These observations bound what the final code encodes, without claiming a demonstrated runtime failure or inventing protocol rules to fill the gap.

## 3. Variants and constants: semantic correction can overturn a plausible schema {#3-variants-and-constants-semantic-correction-can-overturn-a-plausible-schema}

Commits 027 and 055 model a tagged variant using its tag descriptor, name, enum and wire type. The early message explicitly leaves mapping enum values to alternatives unresolved. Commit 112 (4069abe8c2e3) overturns the whole selector interpretation: according to its binary trace, tagged-variant logic validates an alternative's tag member but has no writer; it then invokes the plain variant save path. The actual wire selector is the alternative index encoded as uvarint32. The tag member is serialized inside the selected alternative. PlayerList demonstrates why a tag-value lookup is wrong: AddEntry is alternative index 1 while its Action constraint is enum value 0. Merely choosing the correct integer width would not fix that semantic mismatch.

Const selectors similarly evolve. Commit 111 recognizes fixed members on compound factories rather than treating every bindConst as an enum declaration. Its initial string value uses the member label, which happens to work for TextPacket's old literal names. Commit 113 corrects this for Action/Response Type/Type labels by reading the constant getter and finding the corresponding enum value. It throws when it cannot resolve that constant rather than guessing.

Commit 114 then corrects the enum name source itself: mOriginalEnumName is declared spelling, while the serialized member name is mName. Two captured ResourcePack response byte strings are the stated evidence; length checks alone cannot distinguish capitalization because lengths match. The message candidly leaves the lowercase mechanism and older mixed-case TextPacket handling unresolved. No subsequent reviewed commit resolves that question. Keep it open; do not convert the last code change into universal verified correctness, nor preserve 113's CamelCase conclusion after its next revision contradicts it.

## 4. ABI drift: exact boundaries, discriminating symptoms, and deliberate opacity {#4-abi-drift-exact-boundaries-discriminating-symptoms-and-deliberate-opacity}

EnTT is not only a header library dependency here. BDS compiled its own version, registers nodes and returns reflection objects through thunks. The dumper interprets memory and calls vtables across that boundary. A new local header cannot repair metadata already stamped by BDS.

Commit 089 (11a6c467d63a) makes that concrete: meta_type::is_signed reflects std::is_signed on the enum itself, which is false regardless of its underlying sign. Enumerator values cannot identify a signed type that has no negative enumerators. The chosen probe binds an all-ones object and reads it through BDS's per-type conversion helper; negative means signed. The commit reports 71 unambiguous enum comparisons, zero disagreements, and 30 corrected fields. That is a reported experiment, not a reviewer run. Commit 092 separately prioritizes one-byte width over Compression because the byte writer has no varint path. It distinguishes unsigned values under 128 accidentally sharing bytes from an actually correct type model, and explicitly leaves two-byte compression uncertain.

Descriptor layouts evolve at precise boundaries:

- 084: old ConstraintDescription omits a trailing optional; retaining it reportedly crashes destruction. Packet getter/setter equality is also relaxed for old reflection behavior.
- 085 and 090: 1.26.30.28 adds EnumMapping and mScope. Reading the properties map at the wrong offset causes nonsensical bucket state; reading deprecation from a disengaged optional payload causes nondeterministic flags across otherwise identical dumps.
- 098: 1.26.50.25 removes DynamicSetterArgCtor, independently rebinds thirteen fields, removes the keyed trait enumerator and shifts higher bits. The bool write branch disappears rather than moving to another bit. Updating only a field offset or only an enum constant would be insufficient.
- 108: update 6 adds two opaque pointer slots in two descriptors and a 40-byte return-structure prefix. The message distinguishes map-read drift from return-by-value sret writing beyond an undersized buffer. Null opaque slots are modeled only for size, not assigned invented semantics.
- 110: a flat_set is not always layout-equivalent to its vector. Before no_unique_address, empty mapped-container and comparator objects cost padded space at separate nesting levels. The old mirror reportedly reads every serialization trait from a string buffer, yielding plausible but wrong zero traits while the dump completes.
- 117 (074925d133f4): 1.26.70 changes meta_type's node/context order through a meta_object base. Locally computed return metadata and a BDS arg thunk return the same logical payload with halves transposed. The symptom is every packet failing lookup while many enums/types still dump. This local-versus-cross-boundary comparison isolates a return-object ABI issue rather than assuming all node layouts broke.

The messages describe hexdumps, destructor offsets, initializer stores, poisoned return buffers, upstream change identification and successful before/after dumps. They offer unusually detailed diagnosis, but this review has not downloaded those binaries or executed those experiments. The portable lesson is how to choose discriminating observations and preserve exact hypotheses, not a guarantee that all reported offsets apply to another platform/build.

Version gates become legible via ENCODE (091) and semantically channel-aware (115): stable build 1.26.50.5 includes changes introduced in preview .25, so numeric build comparison alone is wrong. Stable saturates the gate build byte to 255. Commit 116 then rejects mislabelled channel pins using a version-shape convention because a mistaken channel compiles wrong layouts. That convention and one-byte-per-component packing are assumptions that must be revisited for future release schemes.

## 5. Lifecycle, hooks, and conservative support floors {#5-lifecycle-hooks-and-conservative-support-floors}

Early Windows lifecycle choices reverse. Commit 002 moves work off DllMain to avoid loader lock. Commit 018 switches back to synchronous attach plus auto-unload after a reported FreeLibraryAndExitThread/CRT atexit deadlock. These are contextual attempts and should not become a general recommendation to run heavy work under DllMain. Commit 062 switches to Linux constructor loading; 064 immediately fixes premature reflection access by hooking bindPackets, calling the original first, then dumping the context argument. Deleting the whole ServiceLocator/ServerInstance/NetworkSystem layout chain in 065 shrinks the ABI surface.

Signature maintenance also has explicit corrections. An anchor string and nearby call are a starting point, not identity proof. Commits 099–101 require a unique section hit plus target prologue/body and closure checks through packet binder strings. A pattern can be unique but resolve the wrong function. A .24-specific signature is retracted when the supported latest .29 differs. The message's claim that no version gate can serve both is best read as a support-policy decision, since build-component gates exist elsewhere.

The final source rejects builds below 1.21.130 at compile time, retaining candidate older signatures and ABI blockers as disabled groundwork. It distinguishes versions lacking a cereal graph from those whose hook resolves but whose EnTT/container layout still fails. Stable backports can also need distinct signatures (105). This is a useful limit: scan success is a necessary condition, not an extraction success claim.

Final error behavior is narrower than some commit reports imply. Missing descriptors, unsupported reflection, invalid packet payloads and unsupported nested optional throw; there is no per-type recovery in final Visitor. The hook catches the dump exception and logs it, letting the host continue. original_bindPackets is outside that catch. Hook allocation/prepare/install failures are checked but cleanup is not present. File errors warn, counts increment before successful output, and dump complete is still printed when writes failed. Filename sanitation can collide, output is not atomically replaced, and no stale-file cleanup occurs in dump itself. These are static risks to verify before relying on complete artifacts, not reproduced failures.

## 6. Dependency/build/CI choices are part of the behavior {#6-dependency-build-ci-choices-are-part-of-the-behavior}

Commit 004 pins archive hashes; later 072 intentionally removes BDS hashes to follow latest, including the explicit-version path. Funchook uses Git so its distorm submodule exists and avoids a capstone/CMake policy conflict. Dependency settings move into self-contained folders. Linux libhat lacks a required section API; 070 adds --no-undefined to catch it at link time and supplies a libelf shim. The shim reads /proc/self/exe and mostly closes resources, but its inner gelf_getshdr failure throws without cleanup. This is a source observation, not a validated leak.

Post-build behavior is consequential: CMake downloads BDS, copies the shared library, modifies DT_NEEDED/rpath with patchelf, and preserves version-specific server directories. It is not a pure compilation command. This review did not run it. The remove-before-add step expresses idempotence; the versioned imported reviewed changes command paths so Ninja should reapply the step when switching versions. A separate imported path target and fetch target keep those responsibilities distinct.

CI migrates from Windows artifact builds to a scheduled Linux live-dump smoke workflow. It waits up to 30 seconds for a log sentinel, checks process death, uploads schemas and always attempts logs, then publishes to protocol-docs update branches. It does not assert schema equivalence, wire decoding, ABI layout, file counts or absence of write warnings. No unit/fixture/test files were found in this repository's reviewed changes or final tree. The workflow is inspected code, not observed green runs.

Publication evolves to both channels with stable precedence and no older same-channel rewind; force deliberately overrides the guard. Version metadata is briefly duplicated in version.json then consolidated in README. The latter avoids duplicate state but depends on prose formatting. Channel/version-scoped concurrency does not serialize all writers to the same update branch; concurrent pushes may conflict and no retry is visible. Fresh CI workspaces reduce some stale-output risk, but the completion marker is still not proof of every output file. The credentials expression is guarded and was not inspected.

Documentation choices also reverse: detailed internals and exploratory design become a concise README; non-obvious CMake reasons are added inline, later descriptor evidence is removed from comments because the commit carries it. Preserve history as a deliberate evidence location, without inferring a universal rule to either comment everything or remove rationale.
