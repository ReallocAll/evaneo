# Plugin contracts, bootstrap repair and release communication {#plugin-contracts-bootstrap-repair-and-release-communication}

## Identity policy moves across layers {#identity-policy-moves-across-layers}

Python metadata defaults evolve through three different names: package metadata in [1483](https://github.com/EndstoneMC/endstone/commit/f5f2204222899aa5d7a0d7fdcd9b291cbc716513), a prefixed distribution name in [1484](https://github.com/EndstoneMC/endstone/commit/1968a0cfbda55fd943a217aaa945d4896f8ad63c), and finally the bare entry point in [1513](https://github.com/EndstoneMC/endstone/commit/2b477a3ee021a597efd3f53fd18a1b7d1f5fd6f7). The middle choice becomes incompatible when [1511](https://github.com/EndstoneMC/endstone/commit/cf651cd192aaeb8bc5df0ee8e7ebc0006c29c72f) restricts plugin names to lowercase letters, digits and underscores and forbids an endstone prefix. This is a concrete cross-layer inconsistency and repair. A summary that only says “consistent naming conventions” would erase the reason the later repair matters.

[1508](https://github.com/EndstoneMC/endstone/commit/c1750010cb353cb785975a31414bfd16490fdaeb) moves initialization from both language loaders to the manager after validation. It assigns loader, server, logger and data folder centrally. [1512](https://github.com/EndstoneMC/endstone/commit/7d471b7625f1e1e0bb16c4713946b153fc1ece7e) derives a display prefix from underscore-separated words while leaving canonical identity unchanged. [1513](https://github.com/EndstoneMC/endstone/commit/2b477a3ee021a597efd3f53fd18a1b7d1f5fd6f7) enforces the distribution/entry-point relationship and gives two specific user actions in error output. This is good evidence for centralizing common policy and making validation actionable. It is not a full implementation of packaging-name normalization, nor proof that direct loader users retain their old initialization behavior.

Metadata fallback reduces duplicated descriptions, authors and websites, but class-level override remains. The loader takes only the class's own dictionary rather than an arbitrary inherited metadata merge. The new error containment in [1514](https://github.com/EndstoneMC/endstone/commit/8f97fa3c860119efdc2a95be8bc97d6b4330059d) surrounds metadata lookup and entry-point import, not all description parsing or construction. Full endpoint context confirms that malformed permissions or a bad plugin constructor can still escape. Preserve the guarded stage rather than repeat the title as a universal continue-on-error guarantee.

## Build and bootstrap constraints {#build-and-bootstrap-constraints}

The Windows loader work [1444](https://github.com/EndstoneMC/endstone/commit/8b9c6eb5d923aafda06f1b2b11a6ec113796e5bb)–[1447](https://github.com/EndstoneMC/endstone/commit/625d3759351d5dde325fdd70ebde703cc7d6e226) inserts a small DLL that loads the sibling runtime, moves its CMake target under the existing Windows install guard, changes error reporting to a message box, and preflights image loading with DONT_RESOLVE_DLL_REFERENCES. The architecture and earlier failure reporting are observed; a specific unstated loader-lock diagnosis is not. Fixed buffers, ANSI path handling and missing handle cleanup remain limits, not reasons to claim an executed failure.

[1481](https://github.com/EndstoneMC/endstone/commit/e6dfd43b4517b1c1b8f09c3d86d0bc7700b98d4a) sets embedded sys.executable from the interpreter prefix. The issue-linked [1522](https://github.com/EndstoneMC/endstone/commit/1828ad8a3dc2e8655ec3ab1b64ee4ae1dbea20af) switches both it and plugin installation's executable finder to sys.base_prefix, and includes the attempted path in errors. The release notes identify virtual environments as the case. This is a useful diagnostic refinement: conventional path derivation and embedding environment selection must agree. The issue thread itself was not read, so its discussion or reporter contribution must be resolved through the separate thread corpus rather than invented here.

[1509](https://github.com/EndstoneMC/endstone/commit/ec181dddadf42e34be1a709310004ea63de7f040) rejects Debug via CMAKE_BUILD_TYPE. [1510](https://github.com/EndstoneMC/endstone/commit/1dee2f556426a4835d6a1ec1ba9e45bb9f453d83) gives consumers endstone_add_plugin, packaging the shared target, prefix, includes, headers and Clang runtime flags. [1519](https://github.com/EndstoneMC/endstone/commit/9ae1b2093ade22d6f8f37e6627a64e1663732484) migrates tutorials away from duplicating those flags. This is an observed move from repeated consumer recipes to a build helper, with explicit constraints on the supported toolchain path. It does not test multi-config generators or prove every ABI flag is correct; source-level native compatibility remains a boundary requiring separate validation.

## Documentation is substantive but distinct from tests {#documentation-is-substantive-but-distinct-from-tests}

The command tutorial [1521](https://github.com/EndstoneMC/endstone/commit/350eaae1770263c5fc9de3be46962518f698d813) explains operator-by-default security, explicit permission defaults and usage grammar, then gives both Python and C++ examples. The listener tutorial [1523](https://github.com/EndstoneMC/endstone/commit/c63477dd37e9d0ff6378812dcc2d7bb8e5e7a205) explains discovery/registration rather than merely listing APIs. The scheduler tutorial [1524](https://github.com/EndstoneMC/endstone/commit/3206d8a53c49e63af80d7a6fb82bfca2bcbd2c56) connects ticks to an approximate one-second recurring action. These are useful offline teaching artifacts and evidence of consumer-facing explanation.

They also reveal limits. The C++ timer example omits Plugin&, as confirmed against the actual public header. Some tutorials still declare API 0.4 after [1525](https://github.com/EndstoneMC/endstone/commit/9947476be15466517e37c92999a68bdf37f06659) changes the accepted Python API list to only 0.5. Omitted API versions still warn and proceed, while explicit unsupported versions are rejected. Thus “version bump” is not an adequate disposition: it changes compatibility gates. Publishing guidance remains explicitly under construction.

[1520](https://github.com/EndstoneMC/endstone/commit/c2da10d10ebfd48acec82df0544a0c9979744ad2) labels Form and Scoreboard experimental and documents breaking names and ping representation. [1530](https://github.com/EndstoneMC/endstone/commit/94e617f8ab48407aab72ae13713f27800a27dba7) marks their roadmap delivery in 0.5.0. Those are compatible scope statements, not proof of final completeness. Later custom-board networking and Linux construction fixes occur after the milestone. [1558](https://github.com/EndstoneMC/endstone/commit/85767fae4ca37d391094627ab748be2be81554d5) explicitly chooses UTF-8 for TOML read/write, a bounded configuration-portability fix with no transactional persistence claim.

## Attribution and reusable boundaries {#attribution-and-reusable-boundaries}

Git records Vincent as author and committer throughout this sequence. That does not establish coauthor or reviewer involvement; linked issue and public-thread reports remain distinct. Native APIs, compiler/library behavior and package metadata retain their own source history rather than representing independent inventions by Vincent. No external review rationale or executed build result is included.

Use this chain for naming-policy migration, deciding where common plugin initialization belongs, reducing repeated build recipes, and distinguishing release communication from validation. Do not infer an unconditional preference for stricter compatibility or richer metadata: the sequence itself includes reversals and incomplete migration. Exact small changes remain individually listed rather than being padded into artificial lessons.
