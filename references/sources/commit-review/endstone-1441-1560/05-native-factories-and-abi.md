# Native construction: hook lookup, ownership and platform ABI {#native-construction-hook-lookup-ownership-and-platform-abi}

## The need for call-only targets {#the-need-for-call-only-targets}

Hook installation previously assumed every known target needed a detour. [1537](https://github.com/EndstoneMC/endstone/commit/dfc76a6036a9811b3696719dc5fe61a4d6047d6b) reverses the iteration: every detour must find a target, while other targets are available for direct original-function calls. It adds all target addresses to the original-name map after installing hooks; emplace preserves existing trampoline entries. This is a meaningful capability change, not a loop-style refactor. It enables the native constructor addresses introduced in [1541](https://github.com/EndstoneMC/endstone/commit/d93e4bc4d0a6e24539ca422edad91f3973a45db5) without requiring artificial detour implementations.

[1540](https://github.com/EndstoneMC/endstone/commit/cfe8e8d242e7ae6b68245421002d66f33a2358b0) models a shared gameplay-user-manager stack reference wrapped in not_null and calls its native getter through the RVO bridge. [1541](https://github.com/EndstoneMC/endstone/commit/d93e4bc4d0a6e24539ca422edad91f3973a45db5) uses it to construct ServerScoreboard with a registry and no storage. [1542](https://github.com/EndstoneMC/endstone/commit/5cfccc8a4e854d47f5f9e2e6450f70b90359455d) generalizes the factory to a macro that derives a constructor's decorated name from the wrapper's create function, and infers the call signature from the declared factory. This removes repeated mangled-name strings at call sites, while retaining dependence on compiler decoration and native ABI agreement.

The actual alternatives are explicit platform constructor strings, then derived names and a typed helper. There is no recorded discussion comparing a generated registry, imported symbol declarations or a safer allocation abstraction. Those could be future alternatives, but they must not be attributed as choices debated here.

## Two distinct Linux corrections {#two-distinct-linux-corrections}

The initial helper assumes a constructor returns Class*. [1559](https://github.com/EndstoneMC/endstone/commit/39acfab6801cb82ddb5c1e3682ad70ad14bb5b46) separates Windows's returning function type from Linux's void-returning constructor and retains the storage address independently. The message explicitly reports getNewScoreboard no longer crashing on Linux. This is strong evidence of a platform-specific boundary correction, but not a reviewer-run test result.

[1560](https://github.com/EndstoneMC/endstone/commit/b9a6ecf21236751e036a802f7fe436176f454ae2) then gives CommandSoftEnumRegistry a user-provided Linux copy constructor. It copies the same pointer value that a defaulted constructor would, yet changes the class's copy triviality and therefore may change the native by-value ABI. This makes the one-line-looking copy implementation substantive. The patch title only says the registry is fixed; a precise compiler-level diagnosis is inferred from the signature and platform conditional, not supplied by a trace or compiler experiment.

The wrapper returns unique_ptr ownership around raw char-array storage after the native constructor has initialized the object. Allocation/deallocation compatibility, exceptional construction and decorated-name matching are not validated by any new tests in these commits. The source uses a virtual native destructor model, but that alone is not a proof that this storage strategy is portable. The correct synthesis is that the implementation explicitly adapted to native construction rules and revised assumptions when one platform failed.

## Counterexamples against overgeneralization {#counterexamples-against-overgeneralization}

[1543](https://github.com/EndstoneMC/endstone/commit/cf27430a803a4eddbbb91189661a1d0ffc540548) makes original pointers static inside function templates. Template instantiation is selected by types; fp and optional name remain runtime arguments. Thus two different functions with the same signature can reuse the first cached original. The change's title describes the optimization, but no benchmark is present and no cache identity test is added. This is a concrete caution against turning “cache native lookup” into a general prescription without a function-identity key.

The not-null RVO adapter also creates a shared_ptr owning a sentinel invalid address, copies it into the result wrapper, then asks the native function to populate that result. The original temporary still exists and will release its sentinel ownership. This is visible in full endpoint source, not an assumption about unseen engine behavior. It is a significant historical hazard and a reason not to reuse this adapter as a safe construction recipe. No execution was attempted to demonstrate a crash.

The same period's NonOwnerPointer and GameSession corrections, discussed in the scoreboard dossier, show that layout size, pointer adjustment, ownership and call ABI are independent. A struct of the expected size can still use the wrong field ownership or copy semantics. A value-preserving source change can be ABI-significant. That is the strongest portable engineering lesson supported by this cluster.

## Evidence boundaries and future use {#evidence-boundaries-and-future-use}

All six changed symbol manifests were parsed as complete TOML mappings. They add the exact platform targets for score reset, form events, the gameplay manager getter, ServerScoreboard construction, player teleport and teleport command helpers; existing address entries are unchanged in these patches and timestamps advance. This corroborates full patch reading, not semantic validation of those addresses.

The runtime hook implementation and complete endpoint hook header were read, as was the RVO getter. No BDS process, compiler, detour library or upstream test was executed. These dossiers are suitable for researching native-ABI failure chains and designing targeted validation, not for claiming the historical declarations are currently valid or production-safe. Keep explicit source reports, source-visible mechanisms and reviewer inferences separate.
