## Decision and context {#decision-and-context}

Separate parsed descriptor data from mutable build ownership, while also restoring three concrete schema capabilities.

## Observed implementation, tests, and changes {#observed-implementation-tests-and-changes}

DescriptorPool owns the built-file cache, builds imports first with cycle guards, classifies transitive versioning and plans snapshot identities. Frozen FileSet loses its mutable resolved cache; ResolvedFile points back to the pool. In the same patch, MappingType plus dict parsing and std::map codecs are added, keyword-only trailing underscores are stripped, and ExpressionOp declares UNKNOWN=-1, operations0..108 and COUNT=auto(). Map encoding writes count then ordered key/value pairs; decoding clears, creates a scoped key temporary and inserts each value via operator[]. Includes and string-enum traversal learn maps.

## Rationale and alternatives {#rationale-and-alternatives}

Explicit protoc analogy separates FileDescriptorProto-like pure data from pool-owned resolved descriptors. Map support serves the impending biome packet and pass_ escape preserves a BDS field name.

The old FileSet both held source data and resolver memo. The new pool keeps memoization without making parsed data the cache owner. std::map creates deterministic key order; no unordered-map implementation is added.

## Constraints, revisions, and uncertainty {#constraints-revisions-and-uncertainty}

The refactor title and reported byte-identical existing output do not make the whole commit semantic-no-op: dict, field escaping and molang model are real additions. Frozen dataclass alone does not deeply freeze nested mappings. Cyclic type safety is not established by import recursion guards. Map duplicate keys overwrite and sizes remain unbounded in this code; no adversarial claim.
