Restore BDS class nesting and revise the enum-evidence model after a dumper defect.

## Observed implementation, tests, and changes {#observed-implementation-tests-and-changes}

InventorySourceFlags moves inside InventorySource; item transaction action/trigger/result/cooldown enums move into their owners, repeated identically across eras; SubChunkPosOffset is scoped under an otherwise unmodeled SubChunkPacket. Reflection tests assert qualified names and cross-snapshot type identity. Agent guidance attributes incorrect unsigned dump output to std::is_signed_v<Enum> and protocol-dumper11a6c46, says all branches regenerated, requires bare fixture bytes and initially permits only casing patches.

## Rationale and alternatives {#rationale-and-alternatives}

Message says a full BDS-header audit found three naming sites. Explicit docs correct earlier categorical claim that cereal enums always unsigned. A dump implementation can be defective, so source authority needs validation too.

## Constraints, revisions, and uncertainty {#constraints-revisions-and-uncertainty}

TriggerType uint32 to uint8 is byte-equal only for its small current members. Existing ItemUse fixtures select PLACE0, hiding the signedness delta. Do not repeat the broad no-wire-change claim.
