# Bedrock protocol foundations: decisions, reversals, and use boundaries {#bedrock-protocol-foundations-decisions-reversals-and-use-boundaries}

## 1. Bootstrap broad, reduce to a concrete closure, then grow under demand {#1-bootstrap-broad-reduce-to-a-concrete-closure-then-grow-under-demand}

The root targets endweave, a real downstream translation consumer. Its architecture is already static: griffe parses Python with inspection disabled; descriptors and a resolver form a transitive version graph; the C++ backend generates paired declarations and out-of-line serializers; CMake compiles them once into a static library. The stream's borrowing reader and expected-based error flow are implementation choices, not proof that malformed input is bounded.

The initial scaffold is much broader than its AttributeLayerSync consumer. It carries predicates, maps, bitsets, nested/versioned declarations, wire controls, and builtins, with restrictions and unresolved-type fallbacks that make the apparent surface larger than the dependable one. Commit 2 removes thousands of lines and replaces general walkers with small polymorphic field generators. The stated reason is an MVP tied to the required packet closure and protoc-shaped architecture, not an enduring objection to maps or nesting.

Concrete needs then bring capabilities back:

- Full adjacent declarations and recovery of griffe-shadowed class bodies for SubChunkRequest (19).
- Builtin escape hatches, NBT and UUID for StartGame (23–25).
- Maps, escaped field names and pool ownership during the ostensibly refactoring commit 32.
- Snapshot-aware enum membership and auto sentinels for sound data (36–38).
- Conditional fields and grouped branches for pre-cereal BossEvent and InventoryTransaction (40–48).
- Snapshot-aware aliases and storage/wire separation to express legacy item/source forms (45–46).
- Externally counted lists for ClientCacheBlobStatus (55–56).
- Endianness and raw integer selectors for handshake packets (62).
- Nested types and stable nested identities for BDS-compatible schemas (64–65).
- Explicit wire constants to replace an unsafe marker abstraction (76).

Useful transfer: when revisiting a removed feature, recover the actual consumer and tests that justified its return. The fact that a feature was deliberately removed is not enough to reject it in a new context. A target-driven MVP still needs clear diagnostics: early silent enum skipping and unresolved empty structs are concrete counterexamples, corrected incrementally by 18 and 24 rather than magically solved by the rewrite.

## 2. Copy a mature architecture at the mechanism level, document the divergence {#2-copy-a-mature-architecture-at-the-mechanism-level-document-the-divergence}

The protoc analogy evolves through actual ownership boundaries:

1. Commit 2 introduces MessageGenerator and a field-generator factory.
2. Commit 4 renames that domain to ClassGenerator to follow Python class terminology.
3. Commit 32 moves mutable resolution caches out of frozen parsed data into DescriptorPool.
4. Commit 33 separates SourceTree, Importer, and Parser. It explicitly differs from protoc: eager reference resolution requires global loading and classification before parsing.
5. Commit 34 restores MessageGenerator terminology and implements an actual FieldGeneratorMap, reusing one generator per field for write/read emission rather than merely renaming a factory.

The naming reversal matters. The evidence supports choosing correspondence when the architecture genuinely corresponds; it does not support a universal personal preference for “message” over “class.” Frozen dataclasses do not establish deep immutability of contained mappings. Import recursion guards do not establish every type cycle is safe. Existing-schema output identity, reported repeatedly, is a bounded acceptance criterion rather than proof all malformed inputs behave identically.

Include generation follows an analogous ownership progression. Commit 5 centralizes recursive type-tree include discovery; 6 distinguishes header requirements from serializer-body requirements; 7 moves dependency declarations to the emitting generators through Printer. The source emits only body requirements not already satisfied by its paired header. This removes a central list of feature-specific rules, while leaving an observable render-header-before-source coupling.

Commit 63 takes another mature-project mechanism, enum reflection API shapes familiar from magic_enum, but uses schema-time knowledge instead of compiler-signature introspection. Explicit tables avoid range scans and compiler-specific parsing. They preserve declaration order and use linear lookups; runtime index access is unchecked and no performance superiority was measured. Protoc and magic_enum are architectural references with their own authorship, not evidence that their code or design originated with the commit author.

## 3. Keep storage identity, wire grammar, and version identity separate {#3-keep-storage-identity-wire-grammar-and-version-identity-separate}

The central modeling lesson is more specific than “use types.”

- An enum's underlying C++ type supplies memory identity, but field annotations can select a different codec (15, 28).
- A primitive or semantic alias can retain its storage type while using a field-specific integer encoding (46).
- A full packet/type redeclaration expresses changed field type, name, or order, with adjacent ranges and the same packet identity (19, 21, 48, 54, 59).
- A field gate can insert or remove a field anywhere in a surviving order, including the middle of a packet (53, 59). Earlier “trailing only” guidance was too narrow.
- Transitive versioning splits unchanged outer wrappers when their dependencies change (45, 48, 50, 58). Copying the outer declaration merely because a nested item migrated would duplicate information.
- Snapshot enum filtering precedes auto numbering (37–38). Auto is previous visible value plus one, not member count for sparse enums.
- A `using` alias does not create a new C++ type; serializer deduplication must use concrete identity, rather than alias spelling (45).
- Nested names need lexical lookup, outer-root dependency planning, and stable cross-snapshot C++ identity (64). The implementation conservatively groups nested changes, not per-child minimal deduplication.

The public selector initially depends on a DSL ProtocolVersion enum; 62 removes that coupling in favor of integer template arguments. This does not mean arbitrary integers create arbitrary faithful wire snapshots. Supported boundaries and historical model coverage still matter.

Two wire-equal small values are a recurring trap. Enum uint8 and uvarint32 agree below 128. Signed and unsigned compressed codecs agree at zero but differ at positive nonzero values. Correct model names or green zero-valued tests cannot establish width, signedness, or serialization family. Commit 65 is the strongest local counterexample: its message claims spelling-only changes, but three ActionType declarations change uint32 to int and therefore change default nonzero encodings. The existing ItemUse action is zero, masking that delta.

## 4. Treat source authority as a question-specific, revisable model {#4-treat-source-authority-as-a-question-specific-revisable-model}

Agent-facing documentation initially separates header names/types, dump order/encoding, reference golden bytes, and version/changelog dating (17, 35). It asks whether consumers exercise a reference path, since multiple quiet implementations can agree while remaining untested.

The chain then tests that framework against actual contradictions:

- Diagnostics serializes nine floats rather than all twelve visible in memory (16).
- EduSharedUriResource writes button before URI despite header member order (25).
- Old StartGame is absent from a cereal dump; that absence does not mean the packet did not exist (27, 35).
- An adjacent generated `.cpp` can contain declarations rather than usable serializer bodies (39).
- PrimitiveShapes' cylinder has a two-Vec2 wire interpretation despite a header disagreement (52).
- New LevelSoundEvent uses a plain string even though its in-memory representation suggests a variant (54).
- The enum dumper used `std::is_signed_v<Enum>` and falsely classified signedness. Commit 65 records the defect and regenerated branches; a dump is software that can be wrong.
- ContainerID's Compression trait is initially read as demanding varint (68), then that inference is reversed (70). The enum semantic improvement remains while the encoding and fixture change are undone.
- BoolAttributeData's operation resolves in the other direction: retain the name-coded enum rather than the reference's optional int32 (71–72).

The ContainerID sequence is especially useful in audits. Commit 67 locates the question at InventorySource.container_id rather than a flattened reference member. Commit 68 preserves the mismatch as a marked patched fixture, acknowledging a production consumer. Commit 70 restores int8 and exactly restores the old test-file blob. Commit 71 explains why one-byte enum fields did not follow the earlier Compression inference. “The dump wins” and “the reference wins” are both unsupported universal conclusions.

The reference checks and binary investigations above were reported by the source authors. This review inspected the resulting code/documentation and their evolution; it did not independently reproduce those external checks. ## 5. A golden needs independent provenance, discriminating inputs, and declared exceptions {#5-a-golden-needs-independent-provenance-discriminating-inputs-and-declared-exceptions}

The fixture process is itself an implementation history:

- The root starts with hand-derived Cloudburst structure plus a BDS/IDA-attributed uppercase operation spelling (1, 3).
- Early guidance describes reading Marshal and encoding fields, despite cautioning against hand derivation (14).
- StartGame switches to a literal reported from an executed reference with a complete input description (30). The parent commit already had the corrected three-byte empty compound; do not invent a visible four-to-three-byte repair from an earlier development mistake mentioned only in the message.
- Consolidated guidance requires executing a reference rather than reasoning bytes into existence (35). A newly added biome fixture is still described as derived (39), so stated process and recorded practice differ.
- Commit 66 reports re-running 46 golden comparisons, 44 matches, two acknowledged name-code divergences, and 83 passing tests. Its broad reformatting preserves all 16,483 noncomment C++ tokens across all 18 packet test files, including strings, punctuation, and 1,580 hexadecimal literals. It updates provenance and the allowed handling of marked disagreements.
- Commit 72 removes a resolved TODO without changing the uppercase operation bytes. A resolved, patched fixture still does not become an independent oracle for that disputed field.

Tests improve in several concrete ways. Wrong-era frames are rejected after reshapes (19, 21, 41). Biome gradient testing moves into the full three-optional packet path (51). A nonempty ClientCacheBlobStatus case distinguishes two layouts of equal total size, while the empty packet remains identical (56). Armor fixtures expose old one-byte versus new eight-byte air items (50). Login tests exercise byte order and truncation (62). Literal-marker validation finally gains a malformed marker case (76).

Limitations remain visible:

- Old StartGame at 30 checks a three-byte size relation and round-trips its own output, rather than committing an independently produced old literal. Later reported re-execution does not alter that artifact fact.
- Four BossEvent old-shape fixtures are not all nine event IDs, despite a broad test name.
- Five shape cases do not exercise every PrimitiveShapes alternative.
- Inventory fixtures cover representative action/variant states, not the entire domain.
- Compiler changes often arrive without direct compiler-unit tests; packet integration exercises only reachable features.
- Reported green goldens are not malformed-input safety, bounded allocations, version-range correctness, or toolchain success. Commit 60 fixes mypy that was reportedly broken since 45 despite preserved generated C++.

## 6. Make wire-only obligations explicit rather than hiding them in consumer types {#6-make-wire-only-obligations-explicit-rather-than-hiding-them-in-consumer-types}

Commit 42 allows optional containers by staging a decoded inner value before assignment. It also introduces an unusual nested Optional adapter: one public optional, plus an unconditional true marker on the wire. Its reader checks only that a marker was read and ignores a false value. That creates a stream interpretation risk.

Commit 76 removes the adapter and introduces Literal wire nodes. A marker is spelled as a top-level Literal[True] followed by an ordinary optional. It produces no public C++ field, writes the canonical first permitted literal, and rejects a value outside the accepted set. Integer literals require an explicit integer codec; bool literals default to one byte. This preserves consumer structure while exposing the fixed wire grammar in the schema.

The alternatives are visible: keep the permissive adapter, expose boilerplate marker fields to consumers, or create a validated wire-only node. The selected mechanism fits this case. It does not establish arbitrary nested conditional/container Literal composition, integer-width range checks, or complete noncanonical-bool rejection. The added malformed fixture flips the first marker, rather than exhaustively testing all literal combinations.

Other abstraction boundaries are deliberately narrow. Item extra-data stays an opaque length-prefixed blob (43, 48). NBT uses handwritten builtin serializers rather than forcing the DSL to own all tree semantics (23). The latter also inherits resource questions: negative counts and recursion depth are not bounded by this reviewed patch. Externally counted lists (55) do not validate that caller-owned counts match vectors on writes.

## 7. Build, toolchain, documentation, and agent coordination are part of correctness {#7-build-toolchain-documentation-and-agent-coordination-are-part-of-correctness}

The generated/static-library boundary is established at root; commit 9 aligns `.h`/`.cpp` pairs and CMake output-list behavior. Commit 8 removes an unnecessary expected shim because the project requires C++23; transferring that cleanup to older toolchains would lose its constraint.

CI progresses from Python lint/type checks plus Clang/libc++ goldens (11), through GCC/Clang/MSVC (12), then corrects Clang back to libc++ for the documented expected/concepts compatibility problem (13). Configuration is observed; actual cross-platform success is not verified here. Commit 73 changes Ruff selection without explaining a motive. Commit 74 updates branch filters and names after the rewrite becomes main and the unrelated old root becomes prototype.

Agent-facing documentation records an evidence protocol, packet-id naming, snapshot boundaries, architecture comparisons, golden provenance, and unresolved-blocker conventions. Commit 31 moves settled reasoning to commit history while leaving unresolved field questions nearby. That policy makes complete messages essential; diff-only retrieval would lose decisions. Yet subsequent settled comments and derived fixtures show imperfect adherence, so policies are evidence of intended practice rather than guaranteed behavior.
