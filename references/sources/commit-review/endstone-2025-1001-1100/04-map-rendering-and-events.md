## Initial API and successive corrections {#initial-api-and-successive-corrections}

1062 reuses the exact completed PR215 patch and its full squash history: cursor types,128x128 canvases, map views, native map creation, ABGR encoding, map metadata and Python bindings. The initial native update hook only operates when the server produces a packet and a player is identified; replacing its full pixel buffer can disagree with native rectangle metadata. The PR is empty-bodied with no human review discussion, so the implementation revisions are stronger evidence than inferred motivation.

1069 promotes map lookup to Server.1070 removes metadata implementation diamonds;1087 exposes map IDs and1089 corrects inverted emptiness. The current MapMeta map ID sentinel is-1; loading uses truthiness for NBT IDs, so ID0 remains a source boundary rather than silently being assumed valid/invalid by this review.

## Packet placement matters {#packet-placement-matters}

1077 moves map patching to per-recipient NetworkSystem::send, looks up the first map ID, validates a rectangle and fills exactly that rectangle from the rendered buffer. It rebuilds visible cursors but skips if either original pixels or decorations is empty. The first implementation patches after serialization;1078 moves patching before native outgoing filters and serialization, so the public packet-send event sees the revised bytes. Bounds checks on rectangle geometry are not a proof that the pixel vector has sufficient length. The input packet is modified via const_cast, retaining shared-packet/reentrancy considerations.

1079 separates a canvas's persistent own buffer from its lower-layer base pointer. The aggregate is replaced with the whole canvas buffer; upper untouched pixels no longer automatically copy the lower layer. Callers must explicitly use base pixels. The pointer is uninitialized at construction, although ordinary render installs it before invoking callbacks. Base-pixel APIs are not bound to Python at1100. Renderer iteration is directly over mutable storage; no snapshot/reentrancy guard is added.

## Creation versus loading {#creation-versus-loading}

1073 hooks successful _loadMapData;1076 adds symbols/binding.1086 tries deserialization, initially before native processing.1091 moves original first and adds a retained on-create subscription at setLevel.1092 explicitly reverts the deserialization hook while preserving creation subscription. Final behavior is load-after-original plus create callback. The history does not state why the alternative was rejected, so no invented failed-test story is attached.

## Lifetime boundary at1100 {#lifetime-boundary-at1100}

MapItemSavedData::getMapView stores wrappers in a function-static ID-keyed map. Each wrapper borrows native saved data, retains renderers/canvases and per-player render caches. No eviction/teardown appears in that method or the reviewed map/server paths. Locks/unlimited tracking still leave dirty marking commented out. Smart-holder fixes trampoline retention but does not solve native-map lifetime, cache eviction or callback threading. Tests in this range update mocks rather than exercise rendering, events, equality or persistence. All claims are historical static observations.
