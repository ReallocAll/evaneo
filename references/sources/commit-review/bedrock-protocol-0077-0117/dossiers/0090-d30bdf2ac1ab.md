## Problem and constraints {#problem-and-constraints}

DimensionData2168 appends pack UUID per definition and dump map shape differs from codec list presentation.

## Implementation and producer semantics {#implementation-and-producer-semantics}

Empty DimensionDefinitionGroup scopes nested definition; map<string,definition> writes name key inline before value; only pack_id gated2168. Packet and shared GeneratorType need no duplicate declaration.

## Stated rationale and alternatives {#stated-rationale-and-alternatives}

A count plus repeated name/value pairs makes map presentation wire-equivalent to list structs with name first; host scoping is separated from emitted wire structure.

## Tests and outcomes {#tests-and-outcomes}

1001 and2168 attributed goldens, UUID fields, old-to-new short read and reverse leftover bytes.

These are tests and outcome claims examined in source. No upstream test, compiler, codec, regeneration, Windows or BDS execution was performed by this review. The cited source/byte checks are static observations, not independent runtime validation.

## Limits and counterexamples {#limits-and-counterexamples}

Single-entry golden cannot prove map ordering equivalence for arbitrary multi-entry sequences; std::map host ordering is a distinct concern. No external execution.
