## Engineering finding {#engineering-finding}

Non-trickle SDP exceeded1140-byte LAN message and got silently truncated. Session now strips a=candidate and end-of-candidates from offer/answer, sends candidates as individual signals; wrapper retains full SDP. Manager buffers up to64 candidates per unknown connId for UDP reorder, flushes after request. This bounds each list but not number of keys or lifetime, so it is not a global memory bound. Tests verify signal types/order and candidate-free SDP, not global resource safety.

### Commit message {#complete-guarded-message}

> fix(session): trickle ICE candidates to fit the LAN message cap
> 
> A non-trickle offer/answer (candidates embedded) overflows the 1140-byte LAN Message
> payload (SPEC.md s7.3), so the truncated SDP failed to parse remotely. Sessions now strip
> candidates from the offer/answer (strip_candidates) and send them separately as
> CANDIDATEADD (trickle, SPEC.md s9.3); the candidate-free SDP is ~800 bytes. SessionManager
> buffers candidates that arrive (UDP reordering) before the CONNECTREQUEST creates the
> listener session, then flushes them. The in-process PeerConnection path still uses the
> full SDP.
