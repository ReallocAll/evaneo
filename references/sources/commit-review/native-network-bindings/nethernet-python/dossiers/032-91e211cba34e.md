### Commit message {#complete-guarded-message}

> refactor: drop the C++ E prefix from enum class names
> 
> ESessionError -> SessionError, ESendType -> SendType, EConnectionFlags -> ConnectionFlags. The
> E prefix is the original NetherNet C++ convention, not a Python one, and PEP8 wants plain
> CamelCase class names.
> 
> SPEC.md keeps the E-prefixed names throughout, since it documents the C++ protocol rather than
> this API — errors.py records that mapping in its module docstring, next to the existing
> per-member spec-name comments, and docs/api-design.md s7 notes it alongside the other
> deliberate departures from BDS naming.
> 
> Numeric values are untouched, so nothing wire-observable changes. 147 tests green, ruff clean.
