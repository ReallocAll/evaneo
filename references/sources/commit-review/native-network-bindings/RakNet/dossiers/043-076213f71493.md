## Engineering finding {#engineering-finding}

Adds a GitHub Actions workflow restricted to main pushes with docs/** paths, plus manual dispatch. Permissions are contents:read, pages:write and id-token:write. Build uses Ubuntu, Node 22, npm ci and next build under docs with GITHUB_PAGES=true, touches out/.nojekyll and uploads the generated site. Deploy uses the GitHub Pages environment and deploy-pages. Shared pages concurrency leaves cancel-in-progress false. Workflow-only edits outside docs are not a listed path trigger. These are source configuration observations; no workflow run/result was inspected. Next configuration sets output:export, conditionally uses /RakNet for GITHUB_PAGES=true, disables image optimization and removes rewrites. React strict mode and the Takumi external package setting remain. This adapts the serving model to a static project subpath and removes a server-rewrite assumption. The search route becomes statically generated through revalidate=false and exposes createFromSource staticGET as GET. A client Provider injects a custom SearchDialog. The dialog uses useDocsSearch with type:static, an English Orama instance, a query state, loading indicator, list results and normal dialog/header/overlay composition. The direct @orama/orama dependency is added at^3.1.5. The lockfile already contained Orama 3.1.18 transitively; only the root package entry changes and the total remains691. That is dependency promotion to a direct import requirement, not a newly downloaded691-package dependency set. No package code or install hook was run. This is the clearest engineering mechanism in the documentation sequence: move from server-driven search/runtime routing assumptions toward build-time content and browser-side search for a static host, while preserving a root development path and project deployment prefix. Removing rewrites does not update the page actions that request `${page.url}.mdx`; the handler is still /llms.mdx/[[...slug]]. The static route/source-link inconsistencies from 014 persist. Base-path interactions with raw MDX hrefs, images and fetches require a build/browser check and are not proven here. The workflow builds but does not explicitly run lint, the types:check script, example compilation, link checking or documentation/API consistency tests.
