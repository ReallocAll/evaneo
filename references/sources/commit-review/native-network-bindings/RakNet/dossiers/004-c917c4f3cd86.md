## Engineering finding {#engineering-finding}

Root CMake moves to3.14/C++11, target-local include/link/compile settings, a single sample helper, optional dependency discovery and install/export files. Separate static/shared targets initially remain. Legacy global compiler/linker string surgery and old dependency fallback guesses are removed. Optional MySQL/PostgreSQL/Boost/graphics dependencies now skip unavailable targets with messages. The new helper still uses CONFIGURE_DEPENDS globs and suppresses warnings; RakNet retains /GS- and /GR- initially. Old FindBoost is retired with explicit Kitware/contributor copyright, not attributed to Vincent. The full new build and meaningful residuals were read; the unchanged historical FindBoost algorithm deletion is a provenance-verified bulk disposition. Claude Opus4.6 is explicitly co-authored.

### Attributed commit-message summary {#complete-guarded-message}

Source: [commit c917c4f3cd86](https://github.com/wu-vincent/RakNet/commit/c917c4f3cd86c978aa099145a6a7952d704d48ab). The following is a factual paraphrase of the message; supplemental static observations are identified separately.

The author presents this change as a migration away from the CMake 2.6-era build design. A root-level CMake 3.14 requirement replaces version declarations spread across more than 70 files. Include paths become target-scoped; compiler options and definitions replace direct edits to CMAKE_CXX_FLAGS. Seven custom build macros are reduced to raknet_add_sample(), while 14 custom dependency-finding macros give way to find_package(). Sample linkage uses a private RakNetLibStatic dependency instead of the global RAKNET_COMMON_LIBS collection.

The described packaging interface uses GNUInstallDirs and RakNetTargets for installation/export, introduces the RakNet::RakNet, RakNet::Static and RakNet::Shared aliases, and supplies cmake/RakNetConfig.cmake.in so consumers can request find_package(RakNet). Static and shared definitions move into Lib/CMakeLists.txt, although they remain separate targets at this revision. The bundled FindBoost.cmake is emptied in favor of CMake's own module.

The engineering finding above records the reviewed implementation and its remaining constraints, including optional dependencies, warning suppression and compiler switches. The removed FindBoost implementation is inherited Kitware/contributor work; neither its removal nor the repository owner's identity establishes authorship of that implementation. This summary reports the message's design intent, without adding a build or test result.
