# Skin values, localized messages and early login control {#skin-values-localized-messages-and-early-login-control}


## Fresh native values versus stale login snapshots {#fresh-native-values-versus-stale-login-snapshots}

870 models SerializedSkin and native Blob/Image/persona types.878 changes public Player::getSkin from a nullable pointer to a value and reads current native skin rather than the stored login snapshot.879 copies skin/cape bytes using their independent dimensions; invalid primary image still goes through unchecked Result.value, while invalid cape is omitted.880 temporarily replaces shared ThreadOwner with a direct implementation pointer and marks uncertainty;882 restores ThreadOwner but removes its modeled24-byte base state. These are ABI-model revisions, not measured memory/layout evidence. ThreadOwner::get does not enforce its named Assert policy.

The old token/base64 decoding still executes inside initFromConnectionRequest at900, including its cape/skin dimension mismatch. Replacing the getter therefore does not remove that initialization exposure. Native-to-public conversion now has a different contract. Its skin ID truncates by cape ID length without confirming a suffix match. No assertion of complete skin decoding safety follows from the new value API.

880's PlayerSkinChangeEvent owns a new-skin value but only allows message mutation and cancellation, not replacing the skin. Matching client UUID is required before callback. Cancellation sends the previous native skin and suppresses native processing; allowed changes announce before native application. Native duplicate announcements are suppressed. No client/server synchronization test was run.

## Preserve localization and native text policy {#preserve-localization-and-native-text-policy}

874–875 explicitly break join/quit message APIs from string to optional<Message>, allowing Translatable and None. Instead of pre-rendering defaults and then guessing whether a plugin changed a string, the structured message survives until delivery. Empty string/None suppresses output. Routing through server.broadcastMessage also imports its existing permission/event semantics, unlike the old direct per-player loop.876–877 recover native ServerTextSettings and gate final announcements after event callbacks; events still occur when text is disabled. Native connection announcements remain suppressed to prevent duplication. Borrowed settings pointers and extended ServerInstance layout are not runtime-validated.

## Rejection is not a cancellable kick {#rejection-is-not-a-cancellable-kick}

883 adds a one-shot InternalDisconnect marker so cancelling login cannot be reversed by a PlayerKickEvent handler. It also removes both late primary and subclient ban checks.886 reintroduces checks in a Login packet decorator after the native original, with an explicit comment prioritizing native rejection of invalid attempts. IP bans precede certificate identity/name/UUID/trusted-XUID checks; a nonempty ban reason is included. The supplied title says this occurs before resource-pack stacks, but no packet trace proves that timing here. The decorator installs only for primary Login and hardcodes PrimaryClient; SubClientLogin declarations do not replace the removed subclient check. PreLogin remains TODO.

900 adds eager EnderChest wrapper construction over a borrowed native container and a Python reference-returning property. Owning the wrapper does not prolong the player/native container; a null native container is dereferenced at construction without a local guard. Existing inventory sync behavior is reused, not separately tested.
