# Native block ownership, piston cancellation and fire scaffolding {#native-block-ownership-piston-cancellation-and-fire-scaffolding}


## Piston evolution {#piston-evolution}

837–841 build native BlockActor/circuit/state support.839's piston hook only logs placeholders;842 introduces real events but lets the unique block wrapper die before dispatch.843 moves BlockEvent and block-place wrapper members to unique ownership;844 updates piston call sites. The event owns wrappers, not the native world behind them.845 then replaces early return on cancellation with states4/5 that vanilla is expected not to recognize, while always calling the original tick. Its comment explicitly calls this a hack. Preserving native tick housekeeping is an inferred benefit; unknown-state semantics, save/reload handling and binary layout are unvalidated. Power polarity clears the sentinel to permit a later transition.861 corrects the horizontal facing mapping before applying opposite direction for retraction.

## Fire and block state dependency chain {#fire-and-block-state-dependency-chain}

847–860 stage a native fire reimplementation through shared state/type constants, random interfaces, material/biome/weather declarations, six-neighbor flammability checks, bee eviction, campfire lighting and bit/altered-state setters.854 explicitly corrects inverted rain logic and isolates TNT so a disabled explosion gamerule does not remove it. Campfire lighting changes the extinguished state, emits sound, updates the block and posts a game event.853 initially treats the state-list head address with the wrong indirection;862 fixes it and initializes the singleton at setLevel;864 completes Linux symbols. State getters default missing values and setters can return null, while setState enforces nonnull.

These source implementations are not equivalent to an activated public burn API. At900, FireBlock::checkBurn is included in the runtime build but has neither an ENDSTONE_HOOK declaration nor a symbol entry in the inspected table. BlockBurnEvent and TNTPrimeEvent remain TODO comments. Native random classes are interfaces/layout declarations, not a newly implemented random-number generator. Several support declarations have no implementation or no build entry. The state registry caches borrowed pointers and a head once; no rebuild/clear path was introduced.

## Collaborator contribution: cooking {#collaborator-contribution-cooking}

PR212's squash is authored by killcerr with explicit alternate-email and Vincent coauthors. It introduces an owning BlockCookEvent wrapper/source/result and Python result replacement by clone. The actual dispatch is campfire completion, inside canDoBlockDrops. Cancellation returns before consuming the slot or resetting the cooking time, permitting a later retry. Allowed completion converts the result, spawns an item, posts a game event, clears the slot/time and marks changed. Furnace recipe matching scans ID/tag/aux and handles wildcard aux. Generic event wording does not establish a furnace hook. Null source/result conversion and the inherited clone/conversion limits are relevant boundaries.

## Build and evidence discipline {#build-and-evidence-discipline}

893 adds block_state.cpp to the build while removing duplicated inline definitions;899 does the same for block_source.cpp and corrects its stale inverse-air implementation. These paired changes preserve one implementation owner. Compile-fix titles and static_asserts are authored intentions and compile-time checks that were not executed here. No native address/layout or event behavior is certified.
