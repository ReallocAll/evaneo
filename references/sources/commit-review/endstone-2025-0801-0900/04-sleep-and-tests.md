# Sleep events: narrowing a promise and revising test scope {#sleep-events-narrowing-a-promise-and-revising-test-scope}


PR196 is authored by GX/dreamguxiang and explicitly coauthored by Vincent. Its full imported patch is unusually broad: sleep entry/exit, position transforms, block states, wakeup search, ECS layouts, JSON/text objects, spawn and movement scaffolding. The squash message preserves the revision sequence. No public discussion body or human review was returned; implementation motives beyond the code/message are not invented.

The proposed BedEnterResult/useBed force-or-deny surface remains commented out. Actual bed entry performs a reconstructed eligibility check and calls the event only on OK, then calls native startSleepInBed for its own processing. Thus a discrepancy in reconstruction can suppress a plugin callback even if native behavior later differs. Cancellation returns OTHER_PROBLEM. Bed references are borrowed from wrappers kept alive across synchronous dispatch. Wakeup search rotates candidate offsets and prefers safe positions, falling back to dangerous-but-valid ones. The code tests whether the head-piece state exists rather than its boolean value, and obtains the below block's collision shape using the candidate position; these are static boundaries, not demonstrated game failures.

Commit865 explicitly says bed leave is not cancellable. It removes the native stopSleep hook and exposes a notification on incoming StopSleeping while the player is sleeping. This narrows coverage: natural or forced native wakeups are not shown to produce that packet event. The revised API, Python inheritance and stub agree. This is a deliberate contract reduction to what the integration can support, not merely a missing cancellation flag.

The initial32 BlockPos transform cases cover all four mirrors and four rotations at two pivots.866 reverses90/270 orientation and rewrites them as18 focused examples. Expected behavior changes and test coverage breadth both change: the new suite checks chosen mirrors, rotations and nonzero pivots but no longer every combination. No explicit speed rationale is provided, so reduced coverage is a tradeoff, not automatically a defect.867 fixes active isEmptyBlock to compare equal to air and initializes its collision buffer.899 later activates the out-of-line implementation and carries that fix into it.

The imported JSON helper work has distinct static inconsistencies: mutable subscript resizes to index, not index+1, and a vector of raw Value pointers acquires null entries; const access loses its bounds guard. TextObjectRoot copies its children JSON value instead of modifying the root reference. Much sleep/spawn/text scaffolding is commented out or absent from CMake, so these observations are not all claims about active sleep behavior. This dossier keeps implementation availability separate from class declarations.

884 adds ten UUID tests and886 registers them. The supposedly valid compact literal in CanParseCompactValid has30 characters while canParse requires32, so that single expectation contradicts source. Other tests exercise formatting, ordering, invalid lengths/chars and both valid parsing forms. This is a static test-content finding; tests were not run. No bed/native/client tests are claimed.
