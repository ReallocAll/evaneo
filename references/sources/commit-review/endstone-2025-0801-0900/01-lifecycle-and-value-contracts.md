# Lifecycle, item data and scoreboard contracts {#lifecycle-item-data-and-scoreboard-contracts}


<a id="what-changed-and-why-it-matters"></a>
## What changed and why it matters {#what-changed-and-why-it-matters}

The 0.9.1 boundary becomes a platform for richer 0.10 APIs, while several earlier contracts are repaired. Commit 802's warning-policy change also changes the exported C server getter from a Server reference to void pointer. That is an ABI declaration revision hidden by a routine title; no binary compatibility test was run. Commit 804 moves plugin shutdown into server-script reset before the service locator is cleared, so callbacks can still resolve the server. The earlier destructor-level GIL guard disappears, but Python loader destruction still acquires it and plugin virtual callbacks pass through Python bindings. The source review does not establish complete interpreter/thread shutdown correctness. Scheduler cancellation and handler unregistration occur after each loader disables its plugin; service cleanup is not added.

PR200 (GX/dreamguxiang, explicitly coauthored by Vincent) supplies pickup/chunk event surfaces. The chunk native hooks in that contribution are disabled. Commits 806–809 instead repair ChunkPos's overlapping coordinates and connect native chunk publishers, storing two subscription handles. Loading callbacks use a state threshold, unloading callbacks create a temporary wrapper, and both run through a multithreaded publisher without explicit marshalling here. At the endpoint, Subscription merely contains a weak pointer and no disconnect destructor; its native body has a strong self-reference. Thus retaining a handle is not evidence of unsubscribe-on-destruction. The wrapper/event borrows world lifetime. Native callback ownership and reload teardown require separate validation.

Commits 811–812 distinguish internal compensating actions from user-visible actions using one-shot component flags. Spawn cancellation should not produce a remove notification, and correcting cancelled movement should not recursively produce teleport callbacks. Flags are consumed in the relevant hooks. If native processing aborts before consuming a flag, lifetime of that marker is a conditional boundary, not an observed failure.

Item data in 813 completes more than a field addition: base string setType now calls the virtual typed setter, fixing the earlier native-wrapper mismatch. Native aux data is masked to 15 bits, while the plain value class accepts an int. Python assigns by string and does not expose the Result. At 900, conversion of a plain ItemStack back to native still constructs from type/count without copying the new data field; the native-wrapper branch copies the native object. The previously noted wrapper clone aliasing remains unchanged. These representation asymmetries matter for event replacement and conversion, not just API shape.

Scoreboard work is a causal chain, not an isolated fix. Commit 814 corrects the inverted Success guard and propagates checkState errors, but depends on the helper/type changes in 815. Objective display/sort setters preserve the first display order while clearing existing slots. The new setSortOrder still returns an error after setting a found slot at 900. Python returns None for an undisplayed sort order while its stub remains nonoptional. There are no new scoreboard behavior tests in this slice; native outcome enums and borrowed objective lifetime remain static assumptions.

## Applicability and limits {#applicability-and-limits}

Use this history when separating internal recovery from public events, migrating value/borrowed representations, or reviewing cleanup order. Track dependencies between consecutive commits and inspect bindings, conversion functions and shutdown owners together. Do not infer native validity from declarations, source assertions or release notes.
