# Plugin unload order, shadow loading and unresolved quiescence {#plugin-unload-order-shadow-loading-and-unresolved-quiescence}

<a id="reported-failure-and-implemented-response"></a>
## Reported failure and implemented response {#reported-failure-and-implemented-response}
GyanPrakash2483's [issue228](https://github.com/EndstoneMC/endstone/issues/228) describes replacing a compiled .so while the server is running and crashing on /reload. The captured Linux stack/report is source evidence from the reporter, not a reproduced test. Vincent later points to968 and says0.10.4 will include the fix; the reporter thanks him without supplying a detailed retest result.

965 captures each dynamic-library module in the plugin unique_ptr deleter, destroys the plugin before closing the module, and changes reload to clear commands before clearing plugins. The causal requirement is concrete: plugin destructors and command implementations can reside in the library being unmapped. Keeping a module alive until its last plugin object is destroyed is stronger than storing a raw module elsewhere with unrelated destruction order.

968 adds plugins/.local shadow copies. It resolves the original absolute path, derives a filename from its stem/path hash and extension, copies with overwrite, and loads the copy. This allows replacing the source plugin without directly overwriting the loaded file. Loader construction removes matching old regular plugin files;969 removes noisy per-file warnings. It is an operational technique with costs: filesystem work, cleanup failures, possible hash collisions, deterministic per-path copy reuse, and library-load failures leaving files until later cleanup. The API-version mismatch branch still returns after module/plugin creation without registering them in the owning deleter, a static cleanup concern visible in endpoint context.

## Python dependency preservation is a separate fix {#python-dependency-preservation-is-a-separate-fix}
967 stops deleting the entire plugins/.local tree. It adds the site directory and selectively deletes endstone_ or tilde-prefixed directories only within the local non-environment prefix. Native dependency files are retained, reducing the risk of removing installed dependencies still mapped into the interpreter. Existing dependency versions can persist; this is a retention/cleanup tradeoff rather than a fully clean isolated environment. addsitedir precedes deletion, and deletion exceptions are no longer suppressed. No package code, .pth file or plugin was executed during review.

<a id="what-the-sequence-does-not-establish"></a>
## What the sequence does not establish {#what-the-sequence-does-not-establish}
Endpoint plugin-manager source disables plugins, cancels scheduled tasks, unregisters event handlers, clears plugin lookup/handlers/loaders and permissions. Server.reload still has a TODO to wait up to2.5 seconds for asynchronous tasks, placed after clearPlugins. Cancellation is not proof that an already-running task has stopped executing library code. Service cleanup is not present in the reviewed disable/clear path. Hence the source comment “safe reloading” is an intention, not a global guarantee of unload quiescence.

[Issue239](https://github.com/EndstoneMC/endstone/issues/239) describes intermittent incomplete shutdown and crashpad Text file busy. Vincent explicitly cannot pinpoint the root cause and suggests restart delay/container isolation. That is an operational hypothesis, not proof that965/968 fixes shutdown, or that crashpad is definitely the cause. Keeping these reports separate prevents broad success claims from swallowing unresolved lifecycle cases.

## Applying the evidence {#applying-the-evidence}
For a reload change, map the lifetime of commands, callbacks, services, tasks, native modules, Python modules and installed dependencies. Preserve the source file/update workflow without pretending it solves all consumers. A targeted lifecycle test around the reported replacement scenario could be high value; requiring exhaustive tests for every cleanup path is not justified by this source alone.
