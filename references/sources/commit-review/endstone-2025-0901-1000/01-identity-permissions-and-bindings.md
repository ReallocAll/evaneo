# Identity, permission construction and Python hierarchy reversal {#identity-permission-construction-and-python-hierarchy-reversal}

<a id="question-and-causal-result"></a>
## Question and causal result {#question-and-causal-result}
How should a native actor wrapper expose several API roles without duplicating forwarding, while remaining usable through Python and permission callbacks? This slice contains an attempted simplification, its supporting cast changes, and a later reversal with a corrected diagnosis. It is evidence for tracing real ownership/cast contracts, not a rule that one inheritance style always wins.

Commits903–907 move console/player/mob/actor diamonds to virtual bases. They remove repeated forwarding and add Python multiple-inheritance annotations. The transition is staged:905 repairs a qualified call to an implementation removed904,906 replaces invalid virtual-base static downcasts with dynamic casts,908 moves mob conversion to Actor rather than all command senders. These changes affect public layout, vtable shape, native casts and Python teardown together. Reducing source duplication is a real benefit, but successful C++ compilation would not alone establish binding lifetime correctness.

The captured [issue237](https://github.com/EndstoneMC/endstone/issues/237) is unusually useful because the explanation changes. Reporter pgrd1 supplies a Linux crash stack inside pybind11 base traversal while deallocating Player. Vincent first suspects stored player wrappers becoming invalid, says isValid may not protect an already-invalid wrapper, and suggests retaining UUIDs and looking players up. He later explicitly identifies pybind11 virtual-inheritance teardown issue3514 and removes virtual inheritance in953 as the available workaround. The linked external issue itself was not fetched; the local evidence is Vincent's revised diagnosis and953's complete patch. Preserve both stages rather than promoting the initial speculation into a permanent recommendation.953 restores explicit forwarding macros and adjusts Python declarations/casts. No reproduction was run here.

## Ownership and initialization are independent axes {#ownership-and-initialization-are-independent-axes}
927 stops relying on enable_shared_from_this and obtains the existing shared_ptr from the ECS actor component or server console owner. This avoids an auxiliary shared-from-this control-block precondition. It does not strengthen the weak native entity retained inside the wrapper.930 removes permission recalculation from PermissibleBase construction and calls it after the owner is fully built. Console creation moves into server init. This is a two-phase construction response to virtual callbacks observing incomplete owners, not an argument to split every constructor indiscriminately. The shared generic-actor permission singleton and reload lifetime remain separate concerns.

928/931 introduce BlockCommandSender. The adapter can own itself while borrowing CommandOrigin and CommandOutput supplied by a synchronous command. An owning shared_ptr around that adapter is not ownership of its borrowed internals. Minecart sender support remains TODO.931 continues native command dispatch for non-player/non-console origins while applying public command events to those recognized roles.929 similarly keeps CommandSenderWrapper's identity instead of forwarding asCommandSender into its wrapped permission object.

<a id="api-usability-and-reported-rationale"></a>
## API usability and reported rationale {#api-usability-and-reported-rationale}
cenk's [issue221](https://github.com/EndstoneMC/endstone/issues/221) reports that importing Button from endstone.form fails. Vincent explains that Button was historically nested because ActionForm alone supported buttons, then915 moves it to a direct module class;921 separately guards an unset callback. A historical reason can be valid when introduced and no longer match the evolved API. Neither release notes nor the changed type stubs are an import/UI test.

## Practical application and limits {#practical-application-and-limits}
When simplifying wrappers, inspect all cast directions, Python deallocation, owner initialization, and borrowed references together. Prefer a targeted regression around the observed failure over blanket test proliferation. No test file changes in this sequence; that observation does not establish an author preference against tests. The remaining unchecked casts and singleton lifetime are bounded static concerns, not demonstrated crashes.
