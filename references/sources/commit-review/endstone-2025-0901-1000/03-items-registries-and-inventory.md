# Item actors, value/borrowed stacks and string identifiers {#item-actors-value-borrowed-stacks-and-string-identifiers}

## Dropped entity versus inventory value {#dropped-entity-versus-inventory-value}
909–913 add Item actor identity, native wrapper selection and Python properties, then change pickup events from an ItemStack to a mutable Item entity reference. The design is revised during implementation: owner UUID is removed, thrower becomes optional native64-bit ID, and unlimited lifetime maps to INT_MAX rather than6000 ticks. Clearing the stored OWNER value writes0, whereas reading an existing field returns optional0; absence and sentinel0 are not automatically equivalent. Setter access assumes the synced field exists. These are concrete native semantics rather than generic object-model preferences.

959 makes Position/Location coordinate-first and dimension optional.960 exposes Dimension.dropItem, deliberately using the receiver dimension and given coordinates. The native spawn pointer is dereferenced without a null check, and the Python binding has no explicit reference-return policy. An owning returned Python wrapper and a borrowed native Item require separate reasoning. This review does not assert that an actual spawn failed.

## Two branches, two contracts at the cutoff {#two-branches-two-contracts-at-the-cutoff}
The target chronological order interleaves branches. Main ends at996 c1355ac53bc20bb117aff346553acbcc1145ab17; stable v0.10 ends at1000 c8392d2a45fb2e087c583760bf1470c0805e76ed. The stable endpoint still returns ItemType references and retains an optional owned native stack plus borrowed pointer. The main endpoint has972–977's string-based public values, borrowed native reference adapter and no validated factory. Do not describe ordinal1000 as containing all lower-numbered API changes.

972 initially validates create/setType, stores a string, and removes an eagerly borrowed ItemType dependency. Its Result<void> setter lacks a success return in this intermediate version.973–976 propagate strings through factories, metadata, inventories and Python stubs.977 removes the validated factory entirely and accepts arbitrary type/amount/data until native conversion. This simplifies construction independent of registry availability, while shifting invalid-ID policy downstream. Metadata conversion can still consult the server.975 changes the native adapter to a borrowed reference and routes setType to reinit so it would mutate the original slot rather than allocate a detached stack. Endpoint context reveals all three native reinit overloads are empty bodies. Therefore the route's intended benefit is not a completed native implementation at either tip.

The clone copy constructor on both branches aliases the original native handle. It is not an independent item snapshot even though the wrapper is newly allocated. On main, setAmount calls the native setter after8-bit masking; the native setter still clears valid stacks because its final guard is !isNull().1000 corrects that guard to !operator bool(), but only on the stable branch within this scope. The public pure-value setAmount and borrowed-native setAmount therefore have materially different behavior here.

## Client refresh and serialization {#client-refresh-and-serialization}
[Issue242](https://github.com/EndstoneMC/endstone/issues/242) records PrimeStrat's metadata update that only became visible after dropping an item. The author initially asks the reporter to call set_item; the supplied code already does.979 adds a slot packet immediately after inventory mutation. The reporter proposed batching through update_inventory for efficiency, but the implementation chooses immediate per-slot notification. That is an observed alternative and implementation choice, not a measured performance result.980 implements an outbound serializer, descriptor resolution and net-ID variants; the read path throws and existing setItem still constructs its packet through the native factory. No wire capture or client test was performed.

991 preserves auxiliary data on stable conversion from a public stack.992's conflict resolution keeps main's string implementation, losing that imported change in this file;993 applies the corresponding string-API fix. The two patches share a purpose but differ in types and ancestry, so neither should silently vanish as a duplicate.

## Identifier simplification and costs {#identifier-simplification-and-costs}
989 removes NamespacedKey, its character validation, plugin/minecraft default namespace behavior and Python wrapper. Registries use raw strings; enchantment.key becomes id; ItemType.key disappears. Native lookup receives the strings directly. The top-level package import remains stale until995 and generated stubs catch up in996. This reduces wrapper/normalization machinery but also changes accepted-input semantics and caller migration burden. The registry cache still owns unique_ptr wrappers and borrows underlying native registry values. Removing an identifier class is not proof that native-value lifetime or cache invalidation is solved.

## Applicability and validation {#applicability-and-validation}
For inventory APIs, distinguish pure values, borrowed views, native copies, and visible client state. A method name such as clone or setType is insufficient evidence. Useful targeted validation would cover detached copy behavior, count/type/data round trips and visible slot updates; this review makes no execution claim and does not infer that every edge case warrants an expensive test suite.
