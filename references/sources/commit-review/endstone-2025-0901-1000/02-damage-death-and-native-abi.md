# Damage propagation, translated death and native-version adaptation {#damage-propagation-translated-death-and-native-version-adaptation}

<a id="damage-boundary-evolution"></a>
## Damage boundary evolution {#damage-boundary-evolution}
916 attempts to reconstruct invulnerability behavior in Mob::_hurt. Its visible branch dispatches the public event for nonpositive damage difference or an immunity result; this conflicts with the title's goal.918 replaces this intermediate implementation, so treating it as the final algorithm would be misleading. The new shared health-delegate boundary observes positive old-minus-new health changes, including damage potions that bypassed the earlier entry point. Cancellation returns the old health and modified damage adjusts new health before invoking native behavior. Linux symbols follow919 and platform-specific size assertions follow922.

That centralization solves coverage of health changes but not all caller effects.946 preserves original damage in last_hurt so reducing damage through a plugin does not weaken the subsequent immunity-window comparison.948 bypasses non-damage changes and accumulates last_hurt during the immunity window. It also restores a higher-level Mob::_hurt hook because suppressing health loss alone does not suppress knockback.949's rename title hides a substantive argument repair: the original old value must remain old, with modified damage applied to new value.950 changes stale cancellation state into a per-call presence flag, cleans it after the native call, and preserves the native result. This is a causal chain of lower-boundary interception plus upstream side-effect signaling; a single boolean/component still has nested-call and exceptional-exit questions.

[Issue175](https://github.com/EndstoneMC/endstone/issues/175) supplies an earlier custom invulnerable mob and creative block-break report. Vincent's earlier comment reports fixes in other commits; that is context, not fresh credit for those commits or execution evidence here. Referenced198/202 were absent from the canonical captured thread inventory and remain unavailable context; target patches are complete.

## Death message is a value across two outputs {#death-message-is-a-value-across-two-outputs}
923 changes death text to optional Message, allowing plain or translatable text and suppression. Broadcast honors gamerule and plugin edits, while the death-screen packet initially still uses the original native death cause.945 replaces an unnecessary heap event with a stack event for synchronous dispatch.961 fixes both TypeWrapper(const T&), which had an empty body after the port, and DeathInfo construction from the edited event value. Thus the screen and broadcast now derive from the same semantic result. A stack event reduces allocation without licensing listeners to retain it beyond synchronous dispatch.

## Transferable reasoning {#transferable-reasoning}
Test behavior at the semantic boundary where the reported effect originates, then trace upstream consequences. A successful size assertion cannot prove member offsets, vtable slots or calling convention. Keep “author tested,” “source model agrees,” and “independently reproduced” distinct. For this history only the first two forms of evidence are available, with the author's report scoped to PR224.
