# Reliable transport: identity, accounting and progress {#reliable-transport-identity-accounting-and-progress}

## Distinct identifiers must stay distinct {#distinct-identifiers-must-stay-distinct}

A UDP datagram may carry multiple logical messages, and a logical reliable message can appear in successive retransmissions. [C02](../commits/002-2597418d9be3.md)'s initial history treated those domains too simply. [C04](../commits/004-81ae65ca9786.md) introduces a datagram-history node with a timestamp and a list of reliable-message identifiers; [C05](../commits/005-49384b07697d.md) wires outgoing datagrams into it; [C08](../commits/008-f3aa1a48e07f.md) initializes the lists and separates reliable-message numbering from datagram numbering. An ACK can then retire each reliable message carried by that datagram rather than accidentally treating the datagram number as a message number. NAK processing advances deadlines for messages recorded in the history. These are RakNet-derived transport mechanisms; the reviewed contribution is the port and its corrections.

[C20](../commits/020-c32957a1c1be.md) repairs several independent resend errors together. Indexed source-buffer copying avoids consuming payload on first encoding. `datagramSizes` tracks the current datagram, while `totalSize` tracks the update's bandwidth budget. A flush resets the former and clears the send list. Requeued resend entries are collected separately and reinserted after iterator traversal. None of those repairs by itself proves correct loss recovery: cursor stability, collection traversal, packing and accounting each impose their own invariant.

[C29](../commits/029-ec4a7ac721fc.md) uses a bounded 512-slot resend array indexed by message number masked with 511. A slot index is not an identity. ACK removal now verifies that the stored packet's full reliable number equals the acknowledged number before clearing the slot, decrementing unacked bytes and releasing its payload. For example, a late ACK associated with message 1 must not release message 513 merely because both map to slot 1. This is a manual static illustration, not an executed test. The patch also centralizes the next-slot-full predicate and checks it before and after insertions. It protects the bounded resend table but does not bound the higher-level pending queue.

The final NAK path checks nonnull and nonzero action time but lacks the corresponding full-number equality check (outbound context, 108–124 versus 180–209). The lesson is to audit all completion/control paths for identity, not to label the entire reliability layer correct after an ACK fix. Sequence wrap, 24-bit signed reads, history eviction and old retransmissions remain validation concerns.

## A concrete no-progress loop {#a-concrete-no-progress-loop}

[C27](../commits/027-e270537f83a0.md) repairs a reliable-receive hole loop. Previously the loop continued while a hole remained; if the current base was absent, it changed neither the base nor the remaining size. It could repeatedly test the same false condition on an event-loop thread. The new code exits when the base is absent; otherwise it removes the present number, advances the base and reduces the hole size. Every iteration now makes progress or exits. This follows directly from the changed control flow and supports the commit's reported “pipeline stuck” explanation, without claiming an independent reproduction.

Do not widen that proof to all receive ordering. Final inbound context, 139–189 uses absolute message numbers in some `hasReceived` branches and relative `holeIndex` values in another. Its sequence comparison also uses ordinary integer ordering. The liveness repair remains useful even while delivery order, duplicates and wraparound require dedicated tests. Sequenced-in-order handling updates sequence state then returns without the ordinary forwarding call, another reason no complete feature claim is supported.

## Timers, control output and congestion {#timers-control-output-and-congestion}

[C05](../commits/005-49384b07697d.md) reverses incorrect deadline differences; [C08](../commits/008-f3aa1a48e07f.md) standardizes timeout/ping calculations around nanoseconds; [C17](../commits/017-97a60d613446.md) fixes millisecond wire timestamp comparisons; [C30](../commits/030-26bfb46b9284.md) converts configurable unreliable timeout to nanoseconds. Unit normalization is essential because “a duration” and “an absolute timestamp” can otherwise look equally like long integers. The final update loop runs every 10 milliseconds, caps elapsed accounting and also accepts immediate-priority triggers. Repeating scheduling in `finally` preserves updates after some exceptions, while close suppresses/resets work. That is not a guarantee that every exception is recoverable or every timer terminates.

[C11](../commits/011-6dd9a8ae525d.md) changes ACK/NAK output to `writeAndFlush` so control responses do not wait for an unrelated data datagram. [C23](../commits/023-acc137a6e879.md)/[C33](../commits/033-7d52b850ceb9.md) route internal output from a saved handler context, bypassing later user encoders and preserving the control layer. A title in [C22](../commits/022-a0ae0658193d.md) describes that goal, but the actual routing arrives in [C23](../commits/023-acc137a6e879.md); [C22](../commits/022-a0ae0658193d.md) alone would be an inflated claim. Final source distinguishes send-queue emptiness, ACK queue emptiness and resend state. These predicates are not interchangeable, particularly for graceful close.

## Costs, counterexamples and applicability {#costs-counterexamples-and-applicability}

Immediate ACKs may reduce avoidable resend but can increase small-packet/flush work; no measurement here chooses an optimal policy. Fragmentation promotes reliability and retains more memory. Per-message tracking adds state and demands cleanup on terminal paths. Larger buffers and more workers are not automatically improvements. The initial congestion-window model contains explicit RakNet source references; it was ported, not independently validated against a networking specification or simulation.

Use this case for retries, queues, network transports and async correlation: separate envelope identity from operation identity; ensure every loop progresses or exits; preserve payload across retries; distinguish per-item and aggregate budgets; audit all terminal paths. Suggested tests are delayed ACK/NAK after slot reuse, duplicate datagrams, multi-message datagrams, retransmit across MTU boundaries, long loss bursts, no-input timer progress, 24-bit wrap, all reliability modes, empty/unreliable culling, and shutdown with pending queues. No such runtime tests were run or added in this review.
