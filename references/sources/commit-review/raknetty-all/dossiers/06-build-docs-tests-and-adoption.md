# Build, documentation, tests and adoption boundaries {#build-documentation-tests-and-adoption-boundaries}

## Packaging is part of the public contract {#packaging-is-part-of-the-public-contract}

[C02](../commits/002-2597418d9be3.md) starts with core/example Maven modules and conflicting stage-specific compiler settings. [C17](../commits/017-97a60d613446.md) raises the root to Java 16; [C32](../commits/032-4b5668b9374c.md) deliberately converts switch expressions and pattern matching to Java 8-compatible constructs and sets source/target8, centralizes dependency/plugin versions, configures release/snapshot deployment and excludes selected modules from deployment. This sequence cannot support a timeless personal preference for one language level.

The initial aggregate/shade approach changes repeatedly. [C32](../commits/032-4b5668b9374c.md) shades core dependencies while filtering the aggregate; [C34](../commits/034-dc62d520d41e.md) removes core shading and narrows the aggregate allowlist to the project's own modules. It also replaces concrete Bedrock logging dependencies with SLF4J API. The explicit reason is compiled-JAR size, but no before/after size or successful build is recorded in this review. [C39](../commits/039-ce529bc7d4f8.md) imports shared parent/BOM management. [C40](../commits/040-b1629bfe80ba.md) removes Bedrock, [C42](../commits/042-e0ef690d3167.md) removes the all artifact, and [C43](../commits/043-24a3e0a1e1fe.md) flattens to `org.nukkit:raknetty`. These coordinate/configuration changes are real API/deployment changes even where the source bodies mostly move.

[C44](../commits/044-35795928db7f.md) replaces compiler exclusions with JAR exclusions for examples and `log4j2.xml`, initially using the wrong example package. [C45](../commits/045-8b850e0cb248.md) corrects it to `org/nukkit/raknetty/example/**`. Same title, different effect: verify the delta before deduplicating. The intention is to keep example/runtime logging configuration out of the distributable, not to ban examples or logging. No JAR was built or opened; inherited plugin/BOM semantics and artifact availability remain unvalidated.

[C46](../commits/046-db568984314f.md) selects released parent/BOM 1.0 and SCM/repository metadata. [C52](../commits/052-50b33ad4f2ee.md) changes them to 1.1. [C53](../commits/053-4d45b4572389.md)/[C54](../commits/054-344932b55073.md) are release-plugin POM changes: release version/tag then next snapshot/HEAD. [C55](../commits/055-4e43ce6a6067.md) updates README dependency coordinates on a parallel branch, [C56](../commits/056-07a79ae4009c.md) merges. A release-preparation commit proves changed metadata, not successful publication, installation or reproducibility.

## Configuration and documentation can disagree {#configuration-and-documentation-can-disagree}

[C46](../commits/046-db568984314f.md) makes RakNet protocol version configurable through shared channel options; server-child getters derive shared values from their parent, and setters reject direct child mutation. It also renames MTU candidates and moves server clamping. The setter control flow initially falls through to the UDP config even after handling a shared option; [C47](../commits/047-dac6800b72e9.md) changes it to an exclusive chain. The final default client protocol is 6 and server protocol 5, while README says 6 for both. The declared MTU maximum/candidate 1492 meets a strict `<1492` channel validation. Those are concrete consistency checks to add before adoption, not executed connection results.

[C43](../commits/043-24a3e0a1e1fe.md) creates an offline-response builder initialized on channelActive. [C50](../commits/050-f8ef7371c370.md) removes it, stores an object directly, and retrieves it from config for each ping. That changes both construction and hot-update semantics. Legacy method/option-string names survive. [C51](../commits/051-bae5b946a21f.md) updates the README. Within a week the public API changes from provider to builder to object; do not infer a stable anti-builder preference or promise source compatibility. Reusable ByteBuf ownership and sharing across channels still require a caller contract.

[C48](../commits/048-0cdf9f9f00ff.md)'s README states goals of 90% feature coverage and within 10% native performance, plus “only trivially tested.” [C51](../commits/051-bae5b946a21f.md) removes the numeric aspiration and asserts broad feature support while retaining that testing caveat. The port's threading/performance explanations are author claims, not measurements in these commits. [C51](../commits/051-bae5b946a21f.md) also corrects mixed-up client MTU/attempt table entries and adds the protocol option. [C57](../commits/057-f4d33fdb9d02.md) is whitespace only; it supplies no new validation. Issue #1 remains bounded project intent.

## Actual test coverage {#actual-test-coverage}

[C02](../commits/002-2597418d9be3.md) adds one `AcknowledgementTest` class with two tests. One encodes fixed sparse indices and checks empty queue, range count and decoded index count. The bounded-output test verifies remaining count and how many indices decode. They do not compare every decoded value, vary ordering/duplicates, assert wire bytes, simulate loss, exercise channel lifecycle or interoperate with an independent implementation. [C43](../commits/043-24a3e0a1e1fe.md) deletes the class; the final tree has no automated-test source tree. The Maven JUnit dependency or former Surefire settings are not evidence of tests passing.

TCP, forwarder, Bedrock, JWT and Zlib example mains are diagnostic code. Some consume local capture paths unavailable in the repository. Delays, logs and `.sync()` calls are not assertions or captured successful runs. Examples that were moved into main sources later get JAR exclusions, not validation status. No source/build/test/example execution was attempted in this review.

## Conditional adoption checklist {#conditional-adoption-checklist}

1. Choose the actual public version and scope before reading a class as a capability: transport-only final artifact versus deleted Bedrock experiment.
2. Verify configured defaults against documentation and independent protocol fixtures; include upper boundaries, empty MTU candidates and attempts smaller than the candidate count.
3. Verify effective dependency management and the built artifact's contents; release metadata is insufficient.
4. Restore meaningful tests: full ACK values/golden bytes, packet-mode coverage, retries/loss/reorder, reference lifetimes and promise/event terminal paths.
5. Measure using representative traffic before changing batching, threading or compression. Historical performance aspirations cannot substitute for the later [2026 network-thread methodology](../../bedrock-bench-blogs/series-analysis.md#network-paths), which itself reports rather than independently reruns experiments here.

These are context-dependent engineering questions. The evidence is several years old and supports neither present-day dependency recommendations nor an impersonated personal style. Frozen evaluations, original inventories and delivered v1 were not changed; this expanded source review is not covered by their prior runtime/evaluation results.
