# Execution domains, promises and closure {#execution-domains-promises-and-closure}

## Problem and constraints {#problem-and-constraints}

One UDP server socket serves several logical peers. Each peer has reliability/order state, timers and user handlers, while the server owns address lookup and the shared socket. Closing a peer must not close siblings; asynchronous completion must not be confused with merely scheduling a write. The target's implementation adapts Netty's channel/event-loop model; those abstractions belong to Netty, not the port's author.

## Implementation and revisions {#implementation-and-revisions}

[C02](../commits/002-2597418d9be3.md) supplies the wrapper/per-peer architecture but is incomplete. [C07](../commits/007-66ae15a457fa.md) routes `send` through the owning event loop before creating/enqueueing internal packets. [C08](../commits/008-f3aa1a48e07f.md) introduces peer open/active state and server-child removal, then [C18](../commits/018-6d09923f158d.md)/[C19](../commits/019-76a59ec0d9ce.md) repair mistakes such as borrowing the parent unsafe and closing shared UDP. At final head, `NioRakChannel.doClose` closes UDP only for a client; server children ask their parent to remove the address. `removeChildChannel` dispatches mutation to the server loop. Server `doClose` closes its UDP socket and requests child closes. These are separate ownership responsibilities.

[C35](../commits/035-398af46ee855.md) finally sends an inbound datagram from the server dispatcher to `channel.eventLoop().submit(...)` before invoking the child's pipeline. Merely allocating per-peer handlers earlier did not prove they executed on peer workers. Final source confirms the call path in NioRakServerChannel, lines 179–198, and caller-side sends in NioRakChannel, lines 211–250. This establishes the intended execution domains, not a complete cross-thread race proof. Off-loop `getChildChannel` returns null rather than scheduling lookup, and public `numberOfConnections` iterates the map without its own affinity assertion; caller contracts matter.

[C18](../commits/018-6d09923f158d.md) adds attempts/interval/MTU candidates and a connect promise, but the client reply handler is still empty. [C19](../commits/019-76a59ec0d9ce.md) adds the offline reply handshake. Its completion listener originally confuses noncancel failure with success; [C23](../commits/023-acc137a6e879.md) distinguishes success from failure/cancellation and closes failed connects. [C47](../commits/047-dac6800b72e9.md) maps explicit remote rejection identifiers to failure of a still-pending promise instead of waiting for timeout. Final connect rejects an overlapping pending connect, sets an optional timeout, cancels timeout/retry tasks on completion, and clears the pending field. Each stage should be evaluated at its own SHA: a scaffold is not completed behavior.

[C21](../commits/021-dbc4e1a5da71.md) centralizes active/inactive transitions, removes scattered event firing and sends a reliable ordered disconnect notification. [C28](../commits/028-67e17db2955b.md) cancels the update task on close and removes `.sync()` from forwarder close listeners. Blocking inside an event-loop callback can prevent the completion that callback waits for; requesting closure and chaining futures avoids that dependency. This was an explicit reported forwarder shutdown problem, not an independently reproduced deadlock. [C35](../commits/035-398af46ee855.md)/[C38](../commits/038-8e4215e4234d.md) revise the close state model again, leaving draining modes active and choosing a no-ACK-close mode for a received disconnect.

## A final-state counterexample to an attractive summary {#a-final-state-counterexample-to-an-attractive-summary}

Do not summarize this history as “graceful close waits for the disconnect ACK.” Final `disconnect` comments say that, but `DISCONNECT_ASAP` closes when `isOutboundDataWaiting()` is false. That predicate checks only `sendBuffer`, not `resendList` or unacknowledged bytes (outbound handler, 176–178; channel, 165–177 and 500–511). The code supports queue-drain intent, not proven acknowledgement drain. Also, when disconnected or ineligible, `disconnect(promise)` returns the supplied promise without completing it. Those are static test candidates, not observed deployment failures.

Final close cancels recurring updates; its source does not release every held resend, order or split-buffer collection. Full reference cleanup and late task rejection are unvalidated. Server dispatch of a datagram with no matching child also has no explicit release in that branch. A fixed primary path does not establish all shutdown/unknown-peer paths.

## Conditional decision aid {#conditional-decision-aid}

For an async transport or agent task pipeline, write three separate contracts: where state may mutate, which operation a completion belongs to, and which event guarantees forward progress or terminal completion. Record socket owner versus logical-child owner. Audit cancellation and errors as first-class terminal paths. Use nonblocking completion composition inside event-loop callbacks, but do not assume every synchronous API everywhere is inappropriate.

Suggested tests, not run: exactly one active/inactive transition; rejected-connect immediate failure; timeout/cancel/close races; close one peer while a sibling keeps receiving; parent close with pending child tasks; repeated/no-op disconnect; lost disconnect ACK; executor rejection during handoff; and final refcounts of queued buffers. Inspect both queue-empty and ACK-empty predicates.

## Later evidence boundary {#later-evidence-boundary}

The already-reviewed 2026 [network-thread investigation](../../bedrock-bench-blogs/series-analysis.md#network-paths) supplies a useful counterexample to “more per-peer workers means faster.” It reports handoff/latency costs and shared worker co-tenants with single-thread assumptions, and requires per-thread saturation measurement. That later analysis supports conditional execution-domain and capacity reasoning; it does not prove a continuous personal preference or retroactively benchmark this Java port. Its experiments remain reported, not rerun here.
