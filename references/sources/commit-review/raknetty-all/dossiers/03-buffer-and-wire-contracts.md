# Buffer ownership and wire-contract migration {#buffer-ownership-and-wire-contract-migration}

## The invariant is larger than the method signature {#the-invariant-is-larger-than-the-method-signature}

A reliable sender may encode the same payload repeatedly. A receiver may parse several messages from one datagram, retain a fragment, forward a user buffer, or drop a control message. The relevant contract includes byte layout, reader/writer indices, reference lifetime and who consumes the message identifier. Java types alone do not express those obligations.

## Evolution of the transport payload {#evolution-of-the-transport-payload}

[C05](../commits/005-49384b07697d.md) serializes reliability flags, 24-bit counters, ordering/sequencing and split metadata; receipt-only API modes are reduced to on-wire reliability variants. Its first encoding consumes the source payload index and decoding does not advance the containing buffer correctly. [C08](../commits/008-f3aa1a48e07f.md) changes decode to `readBytes(bodyLength)`, so the enclosing datagram loop can advance. [C20](../commits/020-c32957a1c1be.md) replaces consuming payload writes with indexed writes so retry encoding can reuse the payload. This repair is narrower than “arbitrary ByteBuf views are supported”: final InternalPacket, lines 53–77 computes the bit length from readable bytes but passes `writerIndex()` as the indexed copy length. A nonzero reader index is an important unresolved test case. No new runtime failure is asserted.

[C06](../commits/006-cbafe9891b58.md) fragments large payloads into MTU-sized owned buffers, copies ordering/sequencing properties and releases the original. Fragmentation upgrades unreliable modes to reliable variants. That changes semantics and resource lifetime, not merely packet size. [C24](../commits/024-86e953d885a0.md) caps transport buffers by MTU, but also caps typed-message serialization before fragmentation, preventing larger messages from reaching the splitter. [C30](../commits/030-26bfb46b9284.md) restores an expandable initial serialization buffer. This is a concrete counterexample to applying one maximum at every layer: cap the datagram, not necessarily the logical message. Aggregate split counts/bytes, expiry and per-peer budgets still require separate policy and tests.

[C25](../commits/025-286a9e612e18.md) introduces inbound/outbound reliability envelopes, including ByteBuf variants. [C30](../commits/030-26bfb46b9284.md) removes them and exposes raw ByteBuf sending/receiving. [C31](../commits/031-334efa71fd4d.md) updates the forwarder by assuming HIGH priority, RELIABLE_ORDERED and channel 0 rather than preserving arbitrary received metadata. It is therefore an example policy, not proof of transparent forwarding. The `InternalPacket` holder's copy/duplicate/replace methods return plain `DefaultByteBufHolder` at final head, so metadata preservation cannot be inferred from implementing ByteBufHolder.

## Read and release ownership {#read-and-release-ownership}

The final inbound datagram handler releases the parent datagram in `finally`; independent payload buffers can then outlive it. The internal message handler releases handled control messages and restores the reader index before forwarding user data, transferring that buffer to the next handler. Its early identifier read occurs before the try/finally, so malformed-empty input deserves separate validation. [C30](../commits/030-26bfb46b9284.md) moved unverified-peer rejection into the release-protected body, repairing an earlier hole. [C35](../commits/035-398af46ee855.md) releases typed-message buffers after serialization errors. Those concrete changes justify an ownership audit, not a claim of globally leak-free operation.

Final outbound reliable ACK removal releases the exact retained packet. Unreliable queues, ordered heaps, split assembly and shutdown have distinct paths; automatic Netty lifetime management does not prove every application-held reference is released. The Bedrock batch refactor [C36](../commits/036-490abddec457.md) uses retained slices before releasing the enclosing batch, an explicit transfer boundary. Its unknown-ID and exception returns in network dispatch lack uniformly protected releases. That module is removed by [C40](../commits/040-b1629bfe80ba.md); keep its concerns attached to the transient source version.

## Wire layout corrections and identifier ownership {#wire-layout-corrections-and-identifier-ownership}

[C10](../commits/010-362e683cd026.md) moves IPv4 port writing outside the four-address-octet loop. The message attributes a security-bit interpretation failure to the old byte misalignment. [C14](../commits/014-e82c81634792.md) reads ports unsigned. [C19](../commits/019-76a59ec0d9ce.md)/[C35](../commits/035-398af46ee855.md) replace string-character lengths with actual UTF8 byte counts; [C35](../commits/035-398af46ee855.md) also corrects the IPv6 family endianness. Multibyte strings and adjacent fields are necessary tests: ASCII round trips would miss the first defect, and reading only one field would miss the second.

[C37](../commits/037-d49e13f37326.md) makes callers write/read the RakNet ID once instead of every packet class doing so. Offline nonmessages and user data must reset their cursor before forwarding; request1 MTU accounting must include the consumed ID byte. During the same refactor a Bedrock helper delegates UTF8 output and then writes the bytes again; [C38](../commits/038-8e4215e4234d.md) removes that second write. A wrapper refactor can preserve signatures and still duplicate wire output.

[C39](../commits/039-ce529bc7d4f8.md) changes Bedrock helper representation more radically. Player-list UUID writes change from little-endian halves to the wrapper's big-endian convenience methods. Login decode uses nonconsuming `toString` without skipping the token bytes before reading the next length. Animated-image and checksum encoders write raw bytes where decoders expect a length. These are source-level asymmetries to validate, not proof of exploitability or real client failure. [C39](../commits/039-ce529bc7d4f8.md) does correct [C38](../commits/038-8e4215e4234d.md)'s experiment-count mismatch by using intLE on both sides. No interop tests accompany these revisions.

## Conditional test plan {#conditional-test-plan}

Before reusing these designs, test encode twice without index mutation; arbitrary reader offsets and retained views; non-ASCII strings; ID exactly once; encode/decode equality plus an independent golden vector; truncated headers, invalid enums and length bounds; split loss/duplicates/reorder and aggregate limits; and refcounts for success, error, cancellation and rejection. Symmetric local codecs can share the same wrong byte order, so a round trip alone cannot establish protocol compatibility. The original two ACK tests assert counts rather than complete data equality and disappear in [C43](../commits/043-24a3e0a1e1fe.md). No test in this plan was executed.
