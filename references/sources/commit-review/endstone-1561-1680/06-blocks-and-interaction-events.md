# Live block access, native face semantics, and cancellable interactions {#live-block-access-native-face-semantics-and-cancellable-interactions}

Scope: assigned Endstone ordinals 1561–1680, August 2024; historical static analysis, not a current-version verdict.

## The abstraction becomes deliberately narrower {#the-abstraction-becomes-deliberately-narrower}

1594 removes unfinished BlockData/snapshot promises and leaves a smaller live Block wrapper. Later commits add current type, coordinates, dimension, relative lookup, and Python access. Each wrapper addresses a native source/position and reads current data; it is neither a persistent block-state snapshot nor a unique canonical object per position. The public comment about one instance per block is not enforced by the factory, which allocates a wrapper for each request.

Chunk validation is staged: height/unloaded/ticking checks first use a placeholder tick, then actual LevelChunk last_tick, then a missing-field repair moves that field from 288 to 320. Current or immediately previous tick is accepted. That freshness check is not a lock or lifetime pin. Relative lookup can return null, and the Location overload uses the receiver Dimension even if the Location names another one. These are essential semantics for callers, not obscure implementation trivia.

## Faces and event ordering {#faces-and-event-ordering}

The initial BlockFace API includes self and diagonals, then contracts to the six native values so direct FacingID casts line up. Python stubs lag until 1669. Block placement first interprets the hook position incorrectly and is repaired in 1670: pos is the replaced block; the against block lies in the opposite face direction. No fixture verifies all faces, replaceable blocks, or unloaded neighbors. This makes the initial interpretation and repair valuable negative examples for native-hook reconstruction.

Break, actor interaction, use-item-on, and placement events dispatch before the corresponding native operation and return the native cancellation result without invoking it. Placement is player-only. Windows useItemOn uses explicit return-value-out handling, Linux direct return. These are distinct native signatures and event scopes, not interchangeable generic callbacks. A referenced PMMP spam heuristic is attributed in the source, never becomes active in this sequence, and is removed; it is not evidence of an enduring anti-spam design or of excluded historical Nukkit style.

## Lifetime revisions and remaining boundaries {#lifetime-revisions-and-remaining-boundaries}

Early block events borrow wrappers local to the hook. PlayerInteractEvent later owns its wrapper objects through unique_ptr, but its item wrapper can still borrow the native inventory ItemStack. Owning an adapter is not owning the adapted object. Python reference return policies do not keep the event alive indefinitely; nullable pointer returns also need optional typing that the endpoint does not consistently provide.

BlockPlaceEvent's opposite-relative lookup can return null and is dereferenced without a guard. Hit coordinates are documented as 0–1 without enforcement. Snapshot fields and richer placed-item/state information remain unfinished. These limits are recorded to prevent overselling cancellation or retention guarantees, not as a claim that a runtime failure was reproduced.

## Evidence and reuse {#evidence-and-reuse}

Full endpoint block, item-placement, and GameMode hook bodies were read, plus all native interface, binding, stub, and incremental diffs. Exact include-only body equivalence is verified for 1660. No placement/cancellation/coordinate test or native execution is supplied. Use the chain for live-versus-snapshot API decisions, guard sequencing, ABI-aware hook returns, event lifetime, and preserving revisions when translating native concepts into public abstractions.
