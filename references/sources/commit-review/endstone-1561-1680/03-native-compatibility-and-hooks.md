# Native ABI migration, hook reversals, and ownership repair {#native-abi-migration-hook-reversals-and-ownership-repair}

Scope: assigned Endstone ordinals 1561–1680, August 2024; historical static analysis, not a current-version verdict.

## Causal sequence rather than a flat version bump {#causal-sequence-rather-than-a-flat-version-bump}

The 1.21.20 work starts with Windows addresses and signature/layout changes while Linux is still incomplete. It then revises vtable entries, packet layouts, ECS access, event variants, JSON ownership, and Linux mangling. Several placeholders are corrected more than once. Full before/after symbols.toml parsing corroborates every numeric/name change, but does not validate any address in a running proprietary binary. Static assertions constrain the local declaration only when built; this review ran no upstream build.

Three reversals are especially instructive. First,1592 explicitly removes the signature-specialization static original-function caches introduced in 1543 after a regression: looking up by each actual target matters when multiple functions share a C++ signature. Second,1601's Admin-threshold operator interpretation is reversed in 1619 to any level above Any; an inverted setOp ternary remains in the endpoint, so the source's consistency/regression claims are partial. Third,1621 temporarily dispatches spawn events through a coordinator before the native operation, while1625 returns to the postReload hook after it. The reason for abandoning the coordinator is not supplied and must stay unknown.

## Representation and ownership {#representation-and-ownership}

ValueOrRef changes alternative ordering, then abandons std::variant for an explicit union and 8-bit discriminator. That exposes a genuine native-layout constraint, but gives the project responsibility for C++ object lifetime and copying. Event visitors reduce wrapper copies through const references while asValue still returns values. Nontrivial/const event data, noexcept copying, and native-owned lifetimes were not tested. The custom representation is evidence of an ABI adaptation, not a universally preferable C++ sum type.

The local Json::Value implementation adds string ownership, copy/swap, and container deletion. 1627 fixes a specific array-destructor fallthrough introduced in 1609. Full endpoint context establishes that ArrayValues contains pointers, so array copying is container-only; object copies recursively copy their values. Do not describe the repair as a complete deep-copy solution or import conclusions about the external JsonCpp project, whose upstream implementation was not audited here.

The player event placeholder sequence is368→352→352/344→352/352. Actor fields, ItemStack sizes, Level event variants, weak context wrappers, and optional filtered-message fields are all version-sensitive. Placeholder names remain unknown semantics. This is an example of explicit uncertain modeling and subsequent correction, not proof that the entire native map is correct.

## Hook discovery and dependency reduction {#hook-discovery-and-dependency-reduction}

1631 changes detour discovery from the intersection with known targets to the actual exported-function catalog. Full install context shows missing targets become explicit errors instead of absent detours being silently excluded. Export discipline becomes part of correctness. This differs from 1592: one fixes enumeration completeness, the other prevents template-static target aliasing. Constructor overload repairs in the item family likewise restore typed call signatures without restoring those removed caches.

1622 removes a global AttributeCollection dependency in favor of searching an actor's attributes by name, trading a cached global relationship for local linear lookup and an explicit missing-name exception. The source supports dependency removal, not a measured speedup. 1603 removes only the now-redundant receive workaround; outbound adaptation remains. 1632 removes a command enum-autocomplete flag without explaining why. Each removal is bounded to its observed target.

## Evidence limits and use {#evidence-limits-and-use}

Use this family for ABI migration checklists, regression chains, layout uncertainty, hook catalog completeness, and costs of manual ownership. Every actual target diff was read, including numerical maps. No compiler, symbol loader, game server, client, sanitizer, or external native implementation was run. Inferred edge cases are clearly separated from explicit commit claims; they are explanatory counterexamples, not an unbounded bug audit or current-version verdict.

### 1592 — fix: regression in hooks due to incorrect use of static variables {#commit-1592}

Source: [16b13fe8d5ba5ed5b685b9a7143d13cf5f4c4b50](https://github.com/EndstoneMC/endstone/commit/16b13fe8d5ba5ed5b685b9a7143d13cf5f4c4b50); committed 2024-08-08T13:27:02Z; Git author Vincent. Disposition: `substantive_reversal`.

Function pointers/names are looked up for each actual invocation again, avoiding the earlier risk that equal-signature functions share the first cached target in one template specialization.
