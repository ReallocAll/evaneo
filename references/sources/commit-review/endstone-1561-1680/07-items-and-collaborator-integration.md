# Collaborator furnace fixes, item ownership, and constructor ABI {#collaborator-furnace-fixes-item-ownership-and-constructor-abi}

Scope: assigned Endstone ordinals 1561–1680, August 2024; historical static analysis, not a current-version verdict.

## From the overload TODO to typed native construction {#from-the-overload-todo-to-typed-native-construction}

The collaborator's factory macro explicitly leaves overloaded constructors unresolved. 1672 attempts to support them by changing deduction, and 1680 restores typed factory-function signature deduction with an explicit OVERLOAD form. 1674 also satisfies the string-construction need through registry lookup and the existing Item constructor, without adding a new native address. These are observed alternatives in the code chain.

The typed signature matters because forwarding named lvalues can otherwise infer references where native arguments are values. That explanation is static reasoning, not an explicit author postmortem. Linux's constructor return is void, Windows' is a class pointer; raw char storage and native destruction assumptions remain inherited. 1680 does not reintroduce1592's static original-target caches, so the two reversals must not be conflated.

## Three different item objects {#three-different-item-objects}

The public ItemStack is a simple value-like DTO with unvalidated type/amount and an unfinished component-reset contract. The native ItemStack is constructed through an engine function. EndstoneItemStack is an adapter that starts by borrowing a native handle but can redirect itself to a newly owned stack when type changes. That redirection is not a write-back to the original inventory slot. Amount mutation masks to eight bits and invokes a deliberately unimplemented throwing native set wrapper for nonzero values. The endpoint therefore does not support a claim of completed inventory mutation.

The registry-manager adapter explicitly disclaims being the actual BDS implementation and obtains the registry through the current Endstone level with thread/lifecycle checks. The subsequent registry reference locks a weak pointer without checking expiry and uses map.at for lookup. Returning a map reference assumes external registry ownership survives the temporary lock. These concrete preconditions are not eliminated by the earlier acquisition guard.

## Cross-language and refactor limits {#cross-language-and-refactor-limits}

Python's plain ItemStack defaults air to amount one, while C++ default construction uses zero. Interaction event pointers can be null yet have non-optional stub types. Event-owned wrappers may outlive neither their event nor their native borrowed handle merely because a reference policy is specified. Ten inline method moves in 1676 are proven body-equivalent, but the same commit adds a throwing set stub, so calling the entire patch mechanical would hide behavior relevant to 1677.

No native item construction, registry error path, inventory mutation, amount boundary, or Python lifetime test is added or executed in this unit. Use the evidence for collaborator attribution, exact merge reuse, typed ABI boundaries, adapter-versus-resource ownership, and incomplete staged APIs. Unknown external motives and native engine internals remain unknown.
