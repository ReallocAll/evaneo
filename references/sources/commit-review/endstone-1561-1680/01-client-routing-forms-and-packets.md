# Client routing, form repair, and an outbound packet boundary {#client-routing-form-repair-and-an-outbound-packet-boundary}

Scope: assigned Endstone ordinals 1561–1680, August 2024; historical static analysis, not a current-version verdict.

## What this chain establishes {#what-this-chain-establishes}

This sequence carries custom scoreboards from server-side objects into filtered network audiences, repairs the ActionForm callback ownership mistake, and builds the first public particle-packet path. The common problem is where a public object meets native client state. The solutions differ: scoreboards wrap the native sender; forms move button dispatch out of a self-capturing callback; custom packets borrow a public DTO through a native adapter; toasts continue using the native factory. These are observed architectural choices, not a single universal preference for one packet mechanism.

The causal chains are unusually important. Ordinals1561–1564 add identifier comparison, a sender interface, filtering, then installation and an IPv6 repair. 1570 fixes the callback mechanism introduced in 1515; 1571 completes its convenience API; 1593 separately fixes empty-array serialization. 1575–1578 create interfaces and adapters while sending/encoding is still incomplete; 1579 adds the codec with two errors; 1581 repairs both and binds construction; 1582 synchronizes typing. Publishing a name, a Python class, or documentation at one intermediate SHA is not proof of working end-to-end behavior.

## Ownership and ordering, with limits {#ownership-and-ordering-with-limits}

The scoreboard sender owns no native transport and matches both network identity and split-screen subclient. Full endpoint player/server/sender context shows a possible transition-order gap: native new-board join work occurs before the active-board map changes. That is a bounded static concern to remember when reusing this design, not a client bug reproduced in this review. The owning wrapper also installs a pointer into a borrowed primary scoreboard without a restoration path in the examined declaration.

Form response now deliberately calls the form callback before the button callback. That improves composition and removes stale self-capture. It also means the first callback can throw, mutate forms, or call closeForm before the code accesses buttons and erases the old iterator. Callback order is therefore an observable contract and reentrancy remains a review boundary. No claim is made that1570 resolves every form-lifetime problem.

The custom adapter exists on the send call's stack and holds a reference to the DTO. Its safety depends on synchronous native consumption, which the source assumes rather than demonstrates. Type dispatch static-casts based on a reported ID; validity is unconditional; size checking is not structural payload validation. These limits prevent treating the first custom-packet API as a general untrusted protocol framework.

## Evidence and practical use {#evidence-and-practical-use}

Use this family for client-audience routing, callback ownership, API/binding sequencing, and concrete protocol-repair examples. Preserve the earlier defect and the later repair together. There are no golden wire vectors, client captures, form callback tests, or scoreboard transition tests in these commits. Native behavior is inferred only as far as calls and layouts show; engine/client implementation is not independently audited. The per-commit source links and dispositions below are the navigable evidence. The original endpoint-context and patch-overlap audits are not distributed; their coverage and hash claims were not independently rechecked for this release.
