# Spyglass: recent engineering mechanisms and their limits {#spyglass-recent-engineering-mechanisms-and-their-limits}

This is a source-level synthesis of114 GitHub-attributed wu-vincent commits from August–October2026. The seven detailed dossiers retain the SHAs, causal parents, public source links, attribution, reversals and narrower dispositions. The conclusions below are conditional lessons from observed development, not universal preferences. The client was not tested, and the review does not exhaust all relevant public work.

## 1. Preserve the real boundary before simplifying the surface {#1-preserve-the-real-boundary-before-simplifying-the-surface}

The legacy implementation briefly replaced a member read detour with a free function taking Packet*. That looks like removal of indirection, but the rewrite's root guidance explicitly describes a hidden MSVC return-buffer/this ordering mismatch that was quiet on Itanium. The later hook is a genuine nonvirtual member so its address is a callable implementation, not a virtual-call thunk. There are two independent hazards: the calling convention of a member returning a nontrivial result, and recursion when a pointer-to-virtual-member dispatches back through a patched slot. Preserving a superficial C++ signature is insufficient without matching the platform ABI.

The same pattern appears in platform ownership. A Linux-hosted launcher is running an Android x86_64/bionic client. Its ImGui context, allocator and rendering backend belong to the launcher; Spyglass resolves host symbols and checks the exact ImGui revision instead of constructing or destroying a competing context. Windows owns its own context/backend and has different resource duties. Toolchain selection in CMake must likewise avoid overriding the NDK's compiler with a Windows cache variable.

Use this evidence when simplifying FFI, hook adapters, plugin ownership or cross-compilation. Ask who owns the object and allocator, how a return value crosses the boundary, what a member pointer actually represents, and which host selects the compiler. Do not substitute local sizeof or type-hash assertions for complete external layout validation.

Sources: [root guidance and platform/build changes](dossiers/01-foundation-and-platform-ownership.md#commit-001), [legacy simplification counterexample](dossiers/03-lineage-and-ui-expansion.md#commit-040), [correct per-packet member boundary](dossiers/02-capture-and-observability.md#commit-025), [virtual-slot replacement](dossiers/06-replay-policy-and-hook-boundaries.md#commit-099).

## 2. Find the execution path, not the plausible API name {#2-find-the-execution-path-not-the-plausible-api-name}

Three successive corrections define capture accuracy. The first inbound peer hook observes batches, so it moves to Packet::readNoHeader where a concrete packet and Bedrock::Result exist. Later NetworkSystem::send exposes a live outgoing object, but suppressing the byte-only fallback loses broadcasts through sendToMultiple. Finally the new preview compiler inlines readNoHeader; stable-looking string patterns cannot find a function body that no longer exists. Factory-created packet classes expose virtual slots that remain on the live read/write path.

The source preserves concrete reverse-engineering recipes: surviving diagnostic strings, their cross-references, Windows exception indexes or Android unwind indexes, jump-table dispatch shape, sibling virtual methods, relocation addends and RTTI where available. The final factory signature still changes when a near conditional branch becomes a short one. A smaller signature surface is easier to maintain, not permanent immunity to compiler changes.

The write-slot solution has a bounded scan of IDs1–511, per-vtable deduplication and getId validation. Its message reports inspecting real vtables and direct-call absence, Windows in-game verification and Android CI only. Those reports constrain applicability; this review did not possess or execute those client binaries. Hook-isolation errors and class counts improve diagnosis, but a mismatched factory ID still aborts enumeration and a failed write swap skips that class's read swap.

Sources: [capture correction](dossiers/02-capture-and-observability.md#commit-023), [binary recipes](dossiers/02-capture-and-observability.md#commit-029), [outgoing path and missing broadcasts](dossiers/06-replay-policy-and-hook-boundaries.md#commit-083), [inlining and slots](dossiers/06-replay-policy-and-hook-boundaries.md#commit-099), [latest pattern maintenance](dossiers/07-allocator-diagnosis-and-release-evolution.md#commit-114).

## 3. The client's decoder is an authority with preconditions {#3-the-client-s-decoder-is-an-authority-with-preconditions}

Reading the client's reflection avoids a second wire-protocol implementation, but it does not make arbitrary replay safe. Early fields are decoded lazily. Eager inbound capture later preserves the partially populated object from the actual failed read and avoids replay under a forced CerealOnly/primary-subclient context. Work then shifts back toward lazy decoding to avoid JSON construction for packets never inspected.

The difficult exception is a thread-local item registry. The history first asks reflected types which packets contain item descriptors. A crash shows that getter-reached data was missing; a conservative list replaces the walk. Silent empty items then motivate a union of list and traversal. Dynamic setter argument types and per-ID caching fix further gaps and startup cost. A later optimization removes the list after checking apparent type coverage, but ItemRegistryPacket immediately crashes through a constraint that touches the registry without declaring the relevant item type.

The final explanation is a changed model: dependencies live in bound serializer and constraint functions, not just data types. The author reports auditing61 constraint bodies and combining that with header ownership paths to derive twelve numeric packet IDs for eager capture. That audit is explicitly tied to1.26.40 and needs rechecking for newer clients. A false positive costs CPU; a false negative may crash or silently falsify observed items. This is stronger evidence than a generic principle to prefer lists or schemas.

An unknown startup state must not be cached as a negative fact. Packet names, decode mode and schema-members detection originally permanently cached empty results before the reflection/factory became available. Later changes retry unanswered queries. Concurrent access, object lifetime and readiness are separate obligations from once-only initialization.

Sources: [reflection reconstruction](dossiers/04-reflection-and-nbt.md#commit-048), [fidelity reversal](dossiers/05-storage-and-abi-versioning.md#commit-073), [complete classifier evolution](dossiers/06-replay-policy-and-hook-boundaries.md#commit-079), [disproved schema optimization](dossiers/06-replay-policy-and-hook-boundaries.md#commit-092), [behavior-based audit](dossiers/06-replay-policy-and-hook-boundaries.md#commit-093), [unknown name cache](dossiers/06-replay-policy-and-hook-boundaries.md#commit-097).

## 4. Heap corruption is detected later than its cause {#4-heap-corruption-is-detected-later-than-its-cause}

Two NBT changes widen the field walk: accepting const references and adding client-generated list/compound summaries. A join fails with STATUS_HEAP_CORRUPTION while allocating a label. The rollback message correctly distinguishes the detection site from the corrupting operation and declines to guess which widened path caused it. It accepts temporary missing fields while investigating.

The later diagnosis is cross-allocator ownership. The client allocates a returned std::string through MallocRedirect.dll/mimalloc; the payload destroys it through UCRT. Restoring old rendering was insufficient because scalar tags had called the same virtual for much longer. The solution reads scalar members and container sizes from verified mirrors, formats locally, and restores const-reference handling. The patch changes no tag layout, contradicting earlier layout-drift speculation. The author supplies specific inspected offsets and variant shape, but no binary remeasurement occurred in this review.

For native boundary diagnosis, preserve the sequence: observed detection, competing hypotheses, bounded rollback, ownership accounting and field-level evidence. The resulting prohibition on client functions returning owning containers is motivated by this incident. It is not a proof that all remaining client calls, reflection getters or copied standard-library values are safe.

Sources: [const-reference change](dossiers/07-allocator-diagnosis-and-release-evolution.md#commit-101), [uncertain rollback](dossiers/07-allocator-diagnosis-and-release-evolution.md#commit-103), [allocator diagnosis](dossiers/07-allocator-diagnosis-and-release-evolution.md#commit-104).

## 5. Resource limits must name what they bound {#5-resource-limits-must-name-what-they-bound}

Capture moves from4096 retained records to a record cap plus64MiB of bodies, and then to temporary disk-backed bodies and a paged index. The body budget does not include metadata, error trees or every auxiliary structure. A disk store can retain a long session while still dropping packets when its producer queue is full. A bounded queue also does not bound a single JSON construction before enqueueing. The later typed-field change raises queue bytes from4MiB to16MiB; that is a capacity change, not a total-memory guarantee.

The storage design separates accepted packets, written records and dropped work, with a lightweight32-byte index entry, field sidecar, small hot-field cache and liveness lock for stale-file cleanup. A concrete Windows bug shows why counters need read-back or write-status evidence: a mandatory lock on byte0 blocked the process's other writer handle while the index and counters still looked healthy. Moving the lock and adding an error report fix that observed cause. Source inspection still finds counters published after failed writes; error visibility is not transactional persistence.

Queue notification moves outside the mutex and only occurs on empty-to-nonempty transitions. The wait predicate and periodic timeout are part of why notifications are not treated as queued work. Direct3D12 similarly needs a fence covering the overlay's own submitted work, not the game's earlier fence. ResizeBuffers1 is a separate live entrypoint from ResizeBuffers, so releasing resources under only the older hook does not cover actual resizes.

Current-head static risks remain documented in KNOWN_LIMITS.md: detached writer lifetime, restart versus an already-swapped writer batch, old-block eviction immediately after paging, counters after failed I/O and unbounded auxiliary metadata. They were not exercised and should not be promoted into reproduced bug claims.

Sources: [retention budget](dossiers/02-capture-and-observability.md#commit-032), [disk store](dossiers/05-storage-and-abi-versioning.md#commit-070), [GPU fence and Windows lock](dossiers/05-storage-and-abi-versioning.md#commit-071), [actual resize path](dossiers/05-storage-and-abi-versioning.md#commit-074), [queue notification](dossiers/06-replay-policy-and-hook-boundaries.md#commit-094).

## 6. Keep retained values, display previews and exports distinct {#6-keep-retained-values-display-previews-and-exports-distinct}

The first field model stores labels and children. Typed ordered JSON later retains booleans, numeric widths, arrays, objects and full text/binary content rather than a picture of a tree. NBT scalars only become native values in the allocator fix. Duplicate field names receive deterministic suffixes. Byte strings use a documented atob(BASE64) marker, not a native JSON binary type; text validation and replacement still limit claims of universal losslessness.

Display shortening initially leaks into text export because both call the same renderer. A required full/preview argument makes each caller choose deliberately, text stops truncating, and byte preview size determines its Base64 decode window arithmetically. Storage fidelity alone did not ensure output fidelity.

Optimizations are specific: reserving Base64 length removes geometric growth; direct byte-vector access avoids per-byte meta dispatch; an optional key index activates at256 entries and backfills earlier keys. The author reports a16k-sibling example improving from330ms to10ms with small objects unchanged. That is a reported measurement, not a benchmark reproduced here or a portable optimal threshold.

Exports are incrementally advanced from View::draw, with a cooperative12ms check every32 records. One expensive record can exceed the budget. Calling this a background export thread, as one message does, conflicts with the actual call path. The UI replay guard for failed records is absent from export's separate decode path; detailed source locations are preserved in KNOWN_LIMITS.md.

Sources: [export architecture](dossiers/05-storage-and-abi-versioning.md#commit-075), [typed storage](dossiers/05-storage-and-abi-versioning.md#commit-078), [key-index threshold](dossiers/06-replay-policy-and-hook-boundaries.md#commit-091), [full text export](dossiers/06-replay-policy-and-hook-boundaries.md#commit-096), [failed-read replay](dossiers/06-replay-policy-and-hook-boundaries.md#commit-100).

## 7. Compatibility and release history belong to the implementation {#7-compatibility-and-release-history-belong-to-the-implementation}

One payload per client line becomes necessary when EnTT/cereal layouts change. Dependency selection, struct gates, pattern sets, names, injector selection and documentation must agree. Release versions reset their fourth component below earlier previews, so stable build-byte saturation prevents accidentally selecting pre-update layouts. Three-component release versus four-component preview input encodes the distinction. The current EnTT selector uses a three-component1.26.50 boundary, independently checked against this change.

Compatibility guards are narrower than README promises. Windows verify_client rejects channel mismatch and a lower patch-line floor, but does not reject higher incompatible lines or compare preview build numbers. Android's verify_client is empty. The overlay is installed before network verification. Therefore “wrong payload installs nothing” is not a proven global invariant. A unique pattern match is also not sufficient proof of all associated layouts.

Release CI validates version/tag/changelog/main-branch conditions, stamps version files, atomically pushes commit plus tag, then builds each platform from the tag. The release is created before both build/upload jobs succeed. A source workflow is evidence of intended checks, not observed successful runs. The six actual bot commits show date/link/version stamps only and receive no commit-author credit. Earlier orphan rewrite history requires an ancestry test before linking a previous-tag comparison; the later history-only merge restores ancestry without replacing the rewrite tree.

## 8. Documentation and attribution require evidence too {#8-documentation-and-attribution-require-evidence-too}

README revisions repeatedly replace implementation exposition with visible capabilities, installation steps and concrete caveats. That does not erase the need for detailed source comments where binary reconstruction would otherwise be unrecoverable. The repository's initial no-unneeded-helper guidance coexists with later substantial helpers and explicit ABI commentary; apply the actual constraint rather than turning one sentence into a personality rule.

The replacement shows Preview26.60.21 and a client-to-server violation warning, not a server-originated warning. The StartGame image proves a visible nested example, not every field. README partial-fields-on-failure wording also lags behind the UI leaf guard. These disagreements are useful checks against repeating author narratives as observed facts.
