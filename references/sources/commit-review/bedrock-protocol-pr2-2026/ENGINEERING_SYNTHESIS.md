# Bedrock protocol PR #2: architecture reversals and evidence boundaries {#case}

## Scope: read the merged tree, not the opening PR prose {#scope}

[PR #2](https://github.com/EndstoneMC/bedrock-protocol/pull/2) was merged after 24 commits and changed 73 files. Its original description advertised an optional `BatchCodec` wire layer, immutable Python values, a compiler package named `bedrock-protocol` and native runtime named `bedrock-protocol-native`. These were **intermediate design statements**, not the final implementation. The merged [Python documentation](https://github.com/EndstoneMC/bedrock-protocol/blob/1fdcec8f2dc4a4b01bf556243a5f46dc3b7a218a/docs/python.md) instead describes a mutable generic-reflection runtime named `bedrock-protocol`, a separate `bedrock-protocol-compiler`, and no transport-level wire codec. The CMake Python build option remains optional; `BEDROCK_PROTOCOL_PYTHON_VERSIONS` defaults to `2193`, not all 19 schema versions at once. PR head `626333d6af6c` had a successful reported GitHub Actions CI run; no independent execution was done for this dossier.

The first two decisions are indexed separately as [MT14](../../../cases/maintainable-testing/bedrock-wire-scope.md) and [MT15](../../../cases/maintainable-testing/bedrock-reflection-binding.md). This document preserves the causal surrounding evidence and integration boundaries, not another duplicate set of universal rules.

## A. Transport-oriented scope was explicitly retracted {#wire-scope}

The initial PR implementation mixed schema-driven packet codecs with batching, compression, encryption and connection-local `BatchCodec` state. [b7b436a12cfa](https://github.com/EndstoneMC/bedrock-protocol/commit/b7b436a12cfa53df1c0784163a8dd26132408dc0) removes the optional wire library and transitively unneeded `prepare_packet` / `EncodedPacket` abstractions. The commit's concrete arguments are differentiated consumer behavior (client/proxy/server), existing downstream implementation, and OpenSSL/zlib/Snappy wheel dependencies. A packet codec still exists. This is a selective boundary change, not advice to omit required encryption or framing in an actual transport.

## B. A per-field binding generator became one reflection binder {#reflection-binding}

[9853b97c448c](https://github.com/EndstoneMC/bedrock-protocol/commit/9853b97c448cd80f7b663b7402ba22a1d2dadc41) adds reusable generated type/enum/primitive metadata and a shared packet header serializer; [3737018ed434](https://github.com/EndstoneMC/bedrock-protocol/commit/3737018ed4349e9e1116c7dfa6cce725dcc93cc0) deletes the separate nanobind code-generation backend. The author reports around 6 MB of generated binding C++ per build in the previous approach, plus per-version Python files. The new binder walks generated reflection and handles unsupported leaf shapes with casters; this allows a release's generated C++ to serve native builds without the DSL authoring toolchain. The reported quantity and maintenance concern were not benchmarked independently.

## C. Distribution and build contracts were tested by removing conveniences {#distribution}

[82b8baadd098](https://github.com/EndstoneMC/bedrock-protocol/commit/82b8baadd098aa75093e7716f00b580efc7decf9) separates the compiler distribution from the native runtime, including import namespaces and runtime install dependencies. [7b9dbb8614de](https://github.com/EndstoneMC/bedrock-protocol/commit/7b9dbb8614dec6956c52d52bcb6e974bec1e0250) builds the native extension from a source-package artifact with the compiler/schema/uv removed, installs wheels into a separate consumer environment, and asserts `cp312-abi3` tagging. It also removes a downstream consumer workflow referencing deleted `Codec` / `BatchCodec` interfaces. This is a targeted check of the published artifact, not full live-server testing.

[f893f4e7e728](https://github.com/EndstoneMC/bedrock-protocol/commit/f893f4e7e728e3b1fca0b1301def2639bdc834a3) fixes a reproducible Windows build-boundary failure: one generation command with 43 schema paths exceeded `cmd.exe`'s 8191-character limit after extraction under a long path. Returning to one CMake custom command per schema shortened command lines. Using an arbitrarily discovered Python interpreter had also made the consumer supply `click` and `griffe`, so uv became the default and a configured interpreter remained an explicit alternative. [6819e60f7508](https://github.com/EndstoneMC/bedrock-protocol/commit/6819e60f7508cc72f1f69c1042749a2efbf3b30c) selects MSVC for Windows wheel builds because another compiler path hit a 1024-ID fold/expression nesting limit. These are platform- and generator-specific failures, not a generic argument against code generation.

## D. A discriminating byte fixture can overturn a third-party oracle {#protocol-evidence}

[f6c312b83eb0](https://github.com/EndstoneMC/bedrock-protocol/commit/f6c312b83eb05d59ceb00f3d90bef061e9697fde) corrects the packet-header mapping against the author's reverse-engineered BDS and Windows client 1.26.51 evidence: packet id bits 0–9; **recipient** subclient bits 10–11; **sender** bits 12–13. A third-party implementation had reversed the two subclient fields. Zero-valued test IDs cannot detect the swap, so the correction tests sender 2 and recipient 3. The reverse-engineering claim is source-reported, not independently re-derived in this review.

[77d107ea505b](https://github.com/EndstoneMC/bedrock-protocol/commit/77d107ea505be5be47b846ffeff7dc2b18d9dd91) reexamines packet 124's event-data NBT. The first single capture suggested a narrow version gate and `field(nbt_root=)` workaround. More writer/binding evidence and a capture instead supported **rootless `CompoundTagData`**, with entries and closing `TAG_End`, across the supported versions. The change models it as a separate serializable type and removes the artificial version gate and field-generator special case. The old third-party golden was not a discriminating oracle because that implementation retained the field as raw bytes. Distinguish live capture, source-based inference, third-party goldens and internal round-trip tests.

These new details complement the earlier [Bedrock protocol synthesis](../bedrock-protocol-all/ENGINEERING_SYNTHESIS.md) on protocol identity, independent golden evidence and build/release boundaries; they do not rewrite that earlier, separate commit sample.
