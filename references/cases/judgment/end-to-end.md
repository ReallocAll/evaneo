# Prefer an early working end-to-end path {#overview}

## Rationale {#rationale}
Once the direction is clear, complete the smallest safe real workflow before expanding preparations. Passing a build or installation step alone is not proof that the intended feature works. Respect explicit stop boundaries: never start or modify production as a byproduct of testing.

## Case and counterexample {#example}
An installed reviewer component that could not be enabled failed the user goal despite the installer succeeding. A single representative real integration is a stronger first check than broad dry-run paperwork.

## Applicability {#applicability}
Use when evaluating installation, integrations, experiments, or delivery completeness.

## Evidence boundaries {#limits}
This account summarizes historical decisions and their limits. It is not an authorization to perform new work and does not override a current repository contract.
