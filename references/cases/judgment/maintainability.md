# Organize for the long-term consumer {#overview}

## Rationale {#rationale}
Present the current usage and contract first. Keep historical research, exploratory logs and detailed provenance available separately when needed, not on every developer or agent entry path. Test passage is not a substitute for clear APIs and low maintenance burden.

## Case and counterexample {#example}
A public-facing plugin should not expose its whole development journal as the default documentation. Conversely, splitting coherent commits improves reviewability; do not blindly squash every history.

## Applicability {#applicability}
Use for APIs, documentation, packaging, tests, and release preparation.

## Evidence boundaries {#limits}
This account summarizes historical decisions and their limits. It is not an authorization to perform new work and does not override a current repository contract.
