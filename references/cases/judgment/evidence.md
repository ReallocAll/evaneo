# Report the actual delivery state {#overview}

## Rationale {#rationale}
Separate verified behavior from agent claims, synthetic experiments, outstanding defects, deferred work and untested assumptions. A successful push, lack of user feedback, or a passing static test is not proof of adoption or runtime correctness.

## Case and counterexample {#example}
An installation report must not claim success until the installed capability can be used. A documented limitation should not be erased simply because it no longer blocks a narrow task.

## Applicability {#applicability}
Use for review conclusions, deployment reports and acceptance criteria.

## Evidence boundaries {#limits}
This account summarizes historical decisions and their limits. It is not an authorization to perform new work and does not override a current repository contract.
